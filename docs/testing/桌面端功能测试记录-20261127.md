### 6.3 P-26 并发 refresh 阻塞分析（2026-11-27 07:20-07:50）

- 现象：登录成功后约 1-3 秒内出现 2-3 次并发 `POST /_matrix/client/v3/refresh`，服务端判定 refresh token 重放并吊销该用户全部 access/refresh token，随后所有请求 401，客户端触发统一登出回到登录页。testuser1 在本轮 07:33、07:35、07:39 三次登录中 100% 复现；testuser2 登录尝试同样在数秒内 401 退回登录页。

  - 07:33:14 / 07:35:35 / 07:39:29 三次 `POST /login 200`；
  - 每次登录后 2-3 秒内固定出现 `POST /v3/refresh 200` ×1 与 `POST /v3/refresh 401` ×2；
  - 07:39:29 之后 07:39:33 起 sync/friends/presence/crypto 请求全部 401。
- 服务端证据（`synapse-app`）：每轮登录后出现 2 次 `event="refresh_token_reuse_detected" user_id="@testuser1:matrix.test" revoked_access_tokens=205`，伴随 `Revoked refresh token replayed; revoked all user refresh tokens and access tokens`（`synapse-services/src/auth/session.rs`）。吊销后 `refresh_tokens` 表中 testuser1/testuser2 记录全部为 `is_revoked=true`。
- 客户端证据：07:39:37-07:39:38 `[MatrixCryptoService] 获取设备列表失败: M_UNKNOWN_TOKEN: [401] Token has been revoked`；`[MatrixConnection] 同步错误: ERROR`；07:40:07 与 07:41:22 两次 `[RuntimeFetch] access token 已失效（401 M_UNKNOWN_TOKEN），触发统一登出回到登录页`。
- 定位结论：客户端存在多个会调用 refresh 的路径（`MatrixTokenManager.refreshAccessToken`、`MatrixClientAuth.loginWithToken`）与会话恢复入口，多窗口/多路径在启动阶段并发使用同一 refresh token；首个请求轮换成功后，其余请求重放旧 token，命中服务端复用检测并触发全量吊销。单次 refresh 失败本身被 `MatrixClientAuth.loginWithToken` 的 `try/catch` 吞掉，不会踢出会话；真正导致会话不可用的是服务端的全量吊销。
- 影响：当前环境下所有账号登录后均无法保持会话，主界面功能（含 M-10/M-11/M-12、P-25 复测）全部阻塞；登录-登出切换轮次与既有通过结论不受影响（06:41-06:45 已在修复前取得）。
