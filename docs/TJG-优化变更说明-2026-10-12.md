### 2.8 §5 P3-3 滑动同步死列表清理（commit `85b91dba`）

spec §5 P3-3 指出：`MatrixSyncManager` 的滑动同步 `friends` 列表过滤常量 `im.hula.friend_list` 与后端不匹配，导致该列表**恒为空**。本次经实证取证后按「删除死配置」处置（与用户裁定一致）：

| 取证维度 | 结论 | 依据 |
| :--- | :--- | :--- |
| 过滤常量与后端是否匹配 | **不匹配**。后端好友**列表**房间以 `room_type: "m.friends"` 创建（非 `im.hula.friend_list`），故该 list 恒空 | `synapse-services/src/friend_room_service/mod.rs:156-163`（`room_type: Some("m.friends")`、`name: "Friends"`） |
| 前端是否有消费点 | **无**。`grep` 全 `src/` 无消费 `friends` 滑动列表的代码 | — |
| SDK 是否有消费点 | **无**。SDK `FriendListManager` 全部经 REST `VendorPrefix` `/friends` 系列端点获取，从不读取滑动同步列表 | `node_modules/matrix-js-sdk/src/friend/sub-managers/friend-list-manager.ts`（`getFriends()` → `friendPath("/friends")`） |
| 删除是否损失功能 | **不损失**。好友**列表房间**仍由无过滤的 `default` 列表覆盖；`friends` list 删除后无任何功能变化 | `default` 列表无 `room_types` 过滤 |

**处置**：从 `extensionListFilters` 移除 `friends` 键，最终保留 **3 个 list**（`default` / `spaces` / `dms`）；同步把单测由「正向锁定 `im.hula.friend_list`」改为**负向回归守卫**（断言 `getListParams('friends')` 为 `null`，锁定不再注册该列表），`timeline_limit` 循环由 `['friends','spaces','dms']` 收敛为 `['spaces','dms']`。

**证据更正说明**：早期评估曾以「后端 friend room 创建时 `room_type: None`」作为「无正确常量可用」的论据，该论据实际取自**好友 DM 路由**（`synapse-web/src/routes/friend_room.rs::create_friend_dm`，`is_direct: true`、`room_type: None`），**并非好友列表房间**。经复核，后端好友**列表**房间确实以 `m.friends` 创建，即**存在正确常量**；但因该 list 在前后端与 SDK 均无消费点、且删除功能中性，故仍维持「删除」处置（优于「改常量为 `m.friends`」——后者是无收益的保留）。

**验证**：`pnpm vitest run src/services/matrix/__tests__/MatrixSyncManager.test.ts` → **39/39 passed**；`pnpm check:release` 整链 **EXIT 0**。
