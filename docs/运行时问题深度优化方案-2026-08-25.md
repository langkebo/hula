## 一、已彻底修复（客户端代码层）

### P0 消息只显示空气泡（核心，用户最初问题）✅

**根因**：`src/services/matrix/MatrixEventService.ts` 的 `convertEventToMessage()`（历史与实时消息的**共同主路径**，被 `getPagedRoomMessages`、`RealtimeService`、`room/sync.ts` 三方调用）对 TEXT 等类型直接 `: content` 透传 Matrix 原始 content（`{msgtype:'m.text', body:'hello'}`），而渲染组件 `Text.vue` 读取 `body.content`（`TextBody.content` 字段）——两者结构不匹配，`content` 恒为 `undefined` → 空气泡。

引入点：`dc77357a` 提交只给 LOCATION/BEACON 补了 `convertMatrixContent` 转换，其余类型一直透传，并有测试 `keeps raw content passthrough` 固化了这个错误行为。

**修复**：
- `MatrixEventService.ts`：`convertEventToMessage` 改为**所有类型统一走 `matrixMessageAdapter.convertMatrixContent`**（TEXT→`{content}`、IMAGE/VIDEO/VOICE/FILE→媒体结构、LOCATION/BEACON→位置/信标），仅 LINK_PREVIEW 保留透传（适配器未覆盖其 msc2788 结构）。
- `MatrixEventService.test.ts`：更新两处固化错误行为的断言（TEXT 映射为 `{content:'hello'}`；m.beacon 位置更新归一化为 `{content:''}`）。

**验证**：`MatrixEventService.test.ts` 19 项全过。

---

### P2 `@test3` 幽灵联系人（P3 仅治表 → 彻底过滤）✅

**根因**：`@test3` 由服务端 `synapseFriendExtensionService.getFriends()` 返回（测试残留账号）。客户端已有 DM 房间存在性校验，但判断写的是 `presence.status_msg?.includes('M_NOT_FOUND')`——而 `MatrixPresenceService.getPresence()` 在 M_NOT_FOUND 时**已降级返回 `status_msg: null`**（吞掉了错误标记），导致判断永远失效。且好友列表（`friends.map`）路径完全没有存在性校验。

**修复**：
- `MatrixPresenceService.ts`：`PresenceInfo` 新增 `notFound?: boolean` 字段；M_NOT_FOUND 降级分支返回 `notFound: true`。
- `contacts/list.ts`：① 修复失效判断 `presence.notFound`；② 好友列表加载后新增**批量存在性校验**（`getBatchPresence`，优先批量接口、失败降级逐个），过滤 `notFound` 的幽灵账号。

**验证**：`MatrixPresenceService.test.ts`（10）+ `contacts.test.ts`（11）全过。

### P3 enterChat 空 targetId ✅

**根因**：`SpaceChildrenPane.vue` 的 `handleEnterRoom(roomId)` 缺空值守卫（同类的 `SpaceList.vue:handleSelectRoom` 已有），空 `room_id`（`m.space.child` 状态事件缺 state_key）直接传入 `useEnterChat` 触发告警。

**修复**：`SpaceChildrenPane.vue` 加 `if (!roomId)` 拦截（复用 `space.load_failed` 提示），避免空 targetId 下传。

**验证**：`SpaceChildrenPane.test.ts` 19 项全过。

### P1 启动收尾超 15s ✅（超时根因定位 + 降级保护）

**根因**：日志显示 08:46:08 → 08:46:23 无任何输出，之后才进入 `ensureCrypto`。定位到 `MatrixClientLifecycle.doStartClient()` 里 `client.isSlidingSyncSupported()` 探测在服务器端点不响应时**挂起约 15s**，拖死整个启动流程，触发 `settlePostLoginStartup` 的 15s 超时兜底（该兜底本身是合理的非阻塞设计）。

**修复**：新增 `probeSlidingSyncSupport()` 私有方法，给探测加 **5s 超时**——超时即降级到传统 `/sync`（复用已有降级逻辑），避免启动流程被探测拖死。

**验证**：`MatrixClientLifecycle.test.ts` + `MatrixClientService.spec.ts` + `MatrixCryptoStateTracker.test.ts` 共 57 项全过。

## 二、已在工作树未提交改动中修复（无需重复修改）

### P4 Space 加入 403/400 双层失败

`MatrixSpaceService.ts` 的 `joinSpace()` 已有未提交的完善实现：自动提取 `viaServers`、最多 2 次重试、403 invite-only 直接抛「该空间仅限邀请加入」、400 make_join 抛「无法连接到远程服务器」。客户端侧已就绪。

**服务端边界**：`400 Remote server rejected make_join: Connection error ... federation/v1/make_join`（`matrix.test:8448`）是 **synapse-rust 的 federation `make_join` 实现缺陷/配置缺失**，客户端无法修复。建议在 synapse-rust 侧排查 federation make_join 端点。

## 三、环境/开发期项（不改代码，给出建议）

### P5 Keychain dev-mode ACL bug

macOS 开发模式 keychain `set_password` 返回 Ok 但 `get_password` 返回 NoEntry（ACL 问题）。客户端 `secure_store.rs` 的 file fallback 已实现写后读回校验 + 0600 权限，**功能正确**。属 macOS 开发环境缺陷，生产签名应用不受影响。

### P6 HMR 整页重载（12 次客户端初始化主因）

编辑 `MatrixEventService.ts` 触发 `page reload` → 每次全客户端重建。根因是该模块被全局单例/初始化链强依赖，Vite HMR 无法热替换只能整页重载。**生产环境不触发**。若要优化，可在 `main.ts` 对 Matrix 服务模块配置 `import.meta.hot.accept` 边界，但收益低、风险高，暂不实施。
