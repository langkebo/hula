## 6. 典型场景压测

### 场景 A：冷启动进入主工作区

- 步骤：
  1. 启动应用
  2. 进入登录态恢复
  3. 进入主工作区
- 建议记录项：
  - 启动到首屏挂载时间
  - 登录恢复完成时间
  - 首屏可交互时间
  - 首屏长任务数量
- 结果：
  - `pnpm dev --host 127.0.0.1 --port 4173` 启动完成时间约 `1318ms`
  - 本地开发服务根路径 `TTFB / time_total` 三次样本：
    - sample1: `0.000000s / 0.000581s`
    - sample2: `0.000000s / 0.000434s`
    - sample3: `0.000000s / 0.000185s`
  - 说明：以上为本地 Web 开发服务器响应基线，不等同于真实用户侧 `FCP/LCP/INP`

## 7. 当前已知瓶颈

基于当前代码与实施方案，首轮基线前已知的高概率性能风险如下：

1. 首屏和高频路径仍可能过早加载重型依赖，如 `mermaid`、`three`、`@vue-office/*`
2. 房间列表与消息列表在大数据量场景下仍需重点验证虚拟滚动和渲染边界
3. 主线程上仍有富文本、预览、媒体处理等潜在重计算路径
4. 桌面容器启动链、前端挂载与登录恢复的总耗时尚未被统一量化

首轮实测完成后，请将本节改为“已验证瓶颈”，避免长期停留在推断状态。

## 9. 回归判断

以下任一条件满足，视为性能回归：

- 首屏可交互时间恶化超过 `15%`
- 房间列表或消息列表渲染 P95 恶化超过 `15%`
- 大房间滚动 FPS 下降超过 `10%`
- longtask 数量明显增加且无合理解释
