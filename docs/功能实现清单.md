## 审查方法

对每个契约文档中定义的后端端点，逐条比对以下三层实现状态：

1. **SDK 封装**: matrix-js-sdk 是否提供对应 Manager/方法
2. **前端服务层**: HuLa `src/services/matrix/` 是否封装调用
3. **UI 集成**: 前端组件是否实际使用（仅标注明显缺失）

状态标记：

- ✅ 已实现 — SDK 封装 + 前端服务层均已集成
- ⚠️ 部分实现 — SDK 已封装但前端服务层未完整集成，或功能有限
- ❌ 未实现 — 后端/SDK 已提供但前端服务层未集成
- ➖ 不适用 — 管理端/内部接口，前端不需要集成

本轮复核状态（2026-05-27）：

- `已上线` — 前后端主链路、入口与现有测试资产基本闭环
- `已完成但未测试` — 代码与入口已具备，但缺少针对性自动化验证或真实回归记录
- `开发中` — 存在实现遗漏、上下文错误、接口兼容缺口或关键入口未闭环
- `未开始` — 仅有规划，无前后端有效实现

### 综合回归清单（建议执行顺序）

#### 1. 管理模块-访客管理

- **前置准备**：准备 1 个管理员账号、2 个 guest 账号，其中至少 1 个 guest 已加入房间，另 1 个 guest 处于停用或未加入房间状态。
- **访客概览**：进入 `AdminGuests.vue` 页面，确认 guest 总数、活跃 guest 数、最新 guest 用户 ID 与创建时间能正确展示，且不再调用当前登录用户 guest 自检语义。
- **访客列表**：点击“加载访客账户”，确认列表仅展示 `isGuest=true` 用户，不混入普通用户；创建时间、最后活跃时间、停用状态展示正确。
- **访客房间访问**：点击“加载访客房间访问”，确认按 guest 用户逐个拉取 admin 房间接口，已入房 guest 展示正确房间 ID 与 membership，未入房 guest 不报错。
- **访客升级**：对 guest 账号执行升级，确认返回 `user_id` 与升级前主体一致、`is_guest` 变为 `false`、新密码可登录、升级后原 token/新 token 身份语义一致。
- **验收标准**：页面数据与数据库实际状态一致；管理员视角下不再出现“仅 guest 自身可调用”的接口报错；升级前后身份与登录态不冲突。

#### 2. 设备验证兼容接口

- **前置准备**：准备 2 台设备登录同一账号，其中 1 台走现有 SAS/QR 入口，另 1 台覆盖 `keys/verification/*` 兼容链路。
- **SAS 发起与接受**：从设备 A 发起 SAS 验证，在设备 B 接受，确认 `verify_start`、`verify_accept`、`verify_key_agreement`、`verify_mac`、`verify_done` 整链路成功。
- **取消与异常**：在比对阶段主动取消一次，确认 `verify_cancel` 能终止流程，前端 UI 状态恢复，不残留错误中的验证会话。
- **二维码验证**：执行一次二维码展示与扫码流程，确认 QR 展示、扫码确认、完成态与现有设备验证 UI 保持一致。
- **兼容入口混跑**：分别从旧入口与兼容入口各执行一次验证，确认前端不会出现分叉状态、重复会话或按钮状态错乱。
- **验收标准**：两套入口都能完成发起、确认、取消；事件状态一致；前端页面不会因为兼容端点接入产生重复流程或异常提示。

#### 3. MSC4133 扩展资料

- **前置准备**：准备 1 个支持 `uk.tcpip.msc4133` 的服务端环境、1 个不支持该能力的环境；同时准备移动端入口与桌面端 `AccountSettings`。
- **支持环境-写入与回填**：在移动端 `EditBio`、`EditBirthday`、`EditProfile` 保存 `resume`、`birthday`、显示开关、`sex`、`region`，确认返回资料页后能重新回填；桌面端修改 `about`、`sex`、`region`、`birthday` 后重新进入页面仍能看到最新值。
- **跨端一致性**：在移动端修改资料后切到桌面端确认回填；再在桌面端修改后回到移动端确认回填，确保两个入口读到的扩展资料一致。
- **不支持环境回退**：在不支持环境进入移动端与桌面端资料页，确认读取不报错；移动端保存时给出 warning，桌面端输入项保持禁用并显示 unsupported 提示。
- **旧客户端兼容**：使用未消费 `MSC4133` 的旧入口或仅依赖基础 profile 的页面，确认昵称、头像等基础资料链路不受影响。
- **验收标准**：支持环境下读写成功、跨端回填一致；不支持环境下 graceful fallback 正常；基础 profile 能力不因扩展资料接入而回归。
