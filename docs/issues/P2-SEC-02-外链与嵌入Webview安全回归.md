# [P2][安全] 外链与嵌入 Webview 安全回归

## 背景

`hula` 允许在聊天中发送 Markdown 链接，并支持打开外部浏览器或在桌面端嵌入 Webview 预览。这涉及 URL Schema 劫持、钓鱼攻击以及容器逃逸风险。需要建立一套专项回归用例，确保这些“出口”点的安全性。

## 现状

- 当前行为：基础的 `openUrl()` 调用，缺乏系统性的异常链接测试。
- 已知风险：恶意的 `javascript:` 或 `data:` 协议链接可能导致脚本执行或敏感信息泄露。
- 影响范围：链接点击交互、预览窗口。

## 目标

- 目标 1：建立覆盖白名单、异常协议、伪造域名的测试用例集。
- 目标 2：验证在不同 OS（Windows/macOS/Linux）下的链接跳转安全性。
- 目标 3：确保所有嵌入式 Webview 均开启了沙箱隔离。

## 范围

### 包含

- Markdown 消息中的超链接。
- “发现”页面中的外部链接。
- 登录流程中的 OIDC 回调链接。

### 不包含

- 消息同步过程中的协议安全（由 Matrix SDK 处理）。

## 交付物

- 文档：外链安全回归测试清单（Checklist）。
- 代码：针对高危协议（如 `file://`）的拦截逻辑单元测试。

## 执行步骤

1. 收集常见的 XSS 链接 payload。
2. 在 `hula` 中逐一点击，观察容器行为。
3. 编写自动化 E2E 脚本，模拟点击恶意链接。
4. 审计 Tauri `shell` 插件的白名单配置。

## 验收标准

- [ ] 所有非 `http/https` 协议的链接均有明确的拦截或用户二次确认提示。
- [ ] 恶意 URL 无法通过伪装绕过域名白名单检测。
- [ ] 嵌入式 Webview 无法访问宿主机的敏感 `capabilities`。

## 风险与依赖

- 风险：不同操作系统的 Shell 处理逻辑存在差异。
- 依赖：`P1-SEC-01` 建立 v-html 渲染点台账。

## 灰度与回滚

- 灰度方式：先在内测版发布更严格的链接拦截规则。
- 回滚方式：调整 URL 白名单配置。
