# [P2][构建] 建立 bundle 变更审查模板

## 背景

为了防止 JS 资产体积在迭代中失控，除了建立自动化的体积门禁外，还需要在人工评审阶段引入“体积意识”。通过标准化的 PR 体积变更说明，让评审人能快速判断体积增长是否合理。

## 现状

- 当前行为：PR 评审主要关注业务逻辑，忽略体积变化。
- 已知风险：重型依赖在不知情的情况下被合入，导致首屏加载变慢。
- 影响范围：代码评审流程。

## 目标

- 目标 1：在 `pr-templates.md` 中增加体积变更必填项。
- 目标 2：规定当体积增长超过 `50KB` 时，必须提供分析截图或合理解释。
- 目标 3：建立 bundle 变更的决策记录（ADR）关联。

## 范围

### 包含

- PR 模板更新。
- 评审规范文档更新。
- `bundle-baseline.md` 中的“变更记录表”规范。

### 不包含

- 自动化的体积对比工具（由 `P1-BUNDLE-02` 处理）。

## 交付物

- 文档：更新后的 `pr-templates.md`。
- 文档：`bundle-baseline.md` 中的体积评审指南。

## 执行步骤

1. 修改项目根目录的 `.github/pull_request_template.md`（或对应平台的模板）。
2. 在 `docs/` 下创建一个简易的“体积分析操作指南”。
3. 在团队内部分享新的评审规范。

## 验收标准

- [ ] 之后所有涉及依赖变更的 PR 都包含了体积变化说明。
- [ ] 评审人能基于 PR 信息直接判断是否需要进行 tree-shaking 优化。
- [ ] 大体积变更均有对应的技术方案说明。

## 风险与依赖

- 风险：增加开发者的填写负担。
- 依赖：`P0-BUNDLE-01` 建立首轮 bundle 基线。

## 灰度与回滚

- 灰度方式：先从核心模块（如 `matrix-js-sdk` 封装层）开始试点。
- 回滚方式：回退 PR 模板。
