# Tjg macOS 分发版签名 / 公证配置指南（2026-11-19）

## 一、结论（先看这里）

已完成配置落地，涉及 3 处：

| # | 文件 | 改动 | 作用 |
|---|---|---|---|
| 1 | `src-tauri/tauri.macos.conf.json` | `bundle.macOS.signingIdentity` 设为 `"-"` | 本机无凭据时走 ad-hoc 签名，仍能打出可运行的 dmg；有凭据时会被环境变量覆盖 |
| 2 | `.env.macos-signing.example` | 新建，凭据值全部留空 | 公证 / 签名环境变量模板，复制为 `.env.local` 后填写 |
| 3 | 本文档 | 新建 | 操作步骤与依据 |

**核心机制**：Tauri 2 的 macOS 公证凭据与真实签名身份**只从环境变量读取，不写进 config**。
config 里的 `signingIdentity` 只作为"环境变量缺失时的兜底"，因此把它设为 ad-hoc 占位 `"-"`
既能保证本地构建不被破坏，又不妨碍分发时用环境变量注入真实 Developer ID 证书。

自检结果（可直接复核）：
- 本机工具链齐备：Xcode（Apple clang 17）、Rust 1.98.1（已装 `aarch64-apple-darwin`）、Node 22.22.2、pnpm 12.4.1（与 `packageManager` 钉版一致）。
- 签名 / 公证凭据：**未在 config 中写入任何密钥、密码、Team ID**；仅在空值模板中出现变量名。

## 三、两种构建路径

### 路径 1：本机自用 dmg（无需签名证书 / 公证）

直接走项目自带的交互脚本，什么都不用配：

```bash
pnpm tauri:build        # 或 pnpm tb
# 依次选：MacOS → 📦 dmg 磁盘映像 → 🚀 正式版本
```

因为 config 里 `signingIdentity: "-"` 且未设置 `APPLE_SIGNING_IDENTITY`，Tauri 会对 app 做
ad-hoc 签名（Apple Silicon 上从 Internet 下载的 app 需要签名才能运行，ad-hoc 可满足基础要求），
公证因缺少凭据只会打印 `skipping app notarization` 警告，**不会失败**。
首次打开若被 Gatekeeper 拦，右键 → 打开，或 `xattr -cr /Applications/Tjg.app`。

### 路径 2：对外分发版（Developer ID 签名 + 公证）

1. 准备凭据（二选一）：
   - **方式 A（Apple ID）**：`APPLE_ID` + `APPLE_PASSWORD`（App 专用密码）+ `APPLE_TEAM_ID`
   - **方式 B（API Key，CI 推荐）**：`APPLE_API_ISSUER` + `APPLE_API_KEY` + `APPLE_API_KEY_PATH`
2. 复制模板并填值：`cp .env.macos-signing.example .env.local`，至少设置：
   - `APPLE_SIGNING_IDENTITY`：证书全名，形如 `Developer ID Application: <名称> (<TEAMID>)`
     （用 `security find-identity -v -p codesigning` 查）
   - 上述公证凭据中的一组
3. 确认证书已在 login 钥匙串（本机签名无需 `APPLE_CERTIFICATE`；CI 才需要 base64 .p12 导入）。
4. 构建：

```bash
# 交互式（会加载 .env / .env.local，推荐）
pnpm tauri:build
# 选 MacOS → dmg → 正式版本

# 或非交互式（需手动 export 环境变量，脚本不会自动加载 .env.local）
export APPLE_SIGNING_IDENTITY="Developer ID Application: <名称> (<TEAMID>)"
export APPLE_ID="..." APPLE_PASSWORD="..." APPLE_TEAM_ID="..."
pnpm exec tauri build --bundles dmg
# 首次公证很慢，可加 --skip-stapling 跳过 staple，后续再去掉
```

5. 验收：`spctl -a -vvv -t install /Applications/Tjg.app` 显示
   `source=Notarized Developer ID`；或 `xcrun stapler validate Tjg_3.0.10_aarch64.dmg`。

> ⚠️ `.env.local` 已被 `.gitignore` 忽略；只提交模板文件，绝不提交真实凭据。

## 四、依据（可追溯到源码 / 官方文档）

1. **字段合法**：本机 `node_modules/@tauri-apps/cli/config.schema.json`（CLI 2.11.4）中
   `MacConfig` 允许字段为 `signingIdentity / hardenedRuntime / providerShortName / entitlements /
   infoPlist / frameworks / files / ...`。**Tauri 2 已无 v1 的 `gatekeeperAssess`**，故未写入。
2. **公证凭据不在 config**：Tauri 官方 macOS 签名文档（v2.tauri.app/distribute/sign/macos/）
   明确公证走环境变量（Apple ID 三件套或 App Store Connect API 三件套）；
   Tauri 源码 `crates/tauri-bundler/src/bundle/macos/sign.rs` 的 `notarize_auth()` 读取
   `APPLE_ID / APPLE_PASSWORD / APPLE_TEAM_ID` 或 `APPLE_API_KEY / APPLE_API_ISSUER / APPLE_API_KEY_PATH`。
3. **环境变量优先于 config**（方案成立的关键）：Tauri 源码 `crates/tauri-cli/src/interface/rust.rs`
   中 `tauri_config_to_bundle_settings` 原文：
   ```rust
   let signing_identity = match std::env::var_os("APPLE_SIGNING_IDENTITY") {
     Some(signing_identity) => Some(signing_identity.to_str()...to_string()),
     None => config.macos.signing_identity,
   };
   ```
   即环境变量存在则覆盖 config 的 `signingIdentity`；不存在才回退到 config 值（此处为 `"-"`）。
4. **`"-"` 是官方 ad-hoc 写法**：官方文档 "Ad-Hoc Signing" 一节示例即
   `"signingIdentity": "-"`。
5. **无凭据不阻断构建**：源码 `bundle/macos/app.rs` 中签名后调用 `notarize_auth()`，
   凭据缺失走 `log::warn!("skipping app notarization, {e}")`，仅警告不返回错误。
