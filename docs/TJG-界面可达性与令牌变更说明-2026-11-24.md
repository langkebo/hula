## 0. 一句话

这批改动**不动业务逻辑**，集中在三件事：**把填充色当文字色的问题、把装饰色当控件边界的问题、
把不可聚焦元素当可交互元素的问题**。另外修了两个会导致**数据丢失 / 静默失效**的窗口与保存竞态。

**上线前最需要盯的**：`n-input` 边框、侧栏配色、设置窗口关窗——这三处是全局视觉/行为变化，
其余都是逐点修复。

## 2. 需要开发注意的行为变化

### 2.1 `n-input` 边框与焦点态（全局，`df5af5d2f`）

`NaiveProvider.vue` 的 `Input` 覆盖改了四处：

| 属性 | 改前 | 改后 |
|---|---|---|
| `border` | 未设置（naive 自带灰 `#e3e3e3`，白底 1.28:1） | `1px solid var(--tjg-border-control)` → 3.11:1 |
| `borderHover` | `'0'`（悬停时边框**消失** + 1px 跳动） | 同上，稳定不变 |
| `borderFocus` | `'0'` | `1px solid var(--tjg-color-primary-600)` + 2px 品牌色环 |
| `borderDisabled` | `'0'` | **未动** |

**注意**：这是表单全局默认值。如果某个页面觉得边框太重，**不要**在局部覆盖成 `border: none`，
而是提一个更浅的语义令牌；否则会把 WCAG 1.4.11 的 3:1 又降回去。

### 2.2 侧栏配色（全局，`f89f2be65`）

| 令牌 | 改前 | 改后 |
|---|---|---|
| `--left-bg-color` | `primary-500 #13987f` | `primary-600 #0f7a66` |
| `--left-active-bg-color` | `rgba(255,255,255,.18)` | `#ffffff`（白 pill） |
| `--left-icon-color` | `.78` | `.88` |
| `--left-active-icon-color` | `#ffffff` | `primary-600` |
| `--left-win-icon-color` | `.60` | `.72` |

**两个必须一起改的地方**：
1. `design-tokens.css`（`:root` 与 `html[data-theme='dark']`）
2. `src/styles/scss/theme/simple.scss` 的 `.simple` 块 —— **特异性更高，只改 CSS 那处不生效**

### 2.3 `--tjg-status-online` 变深（全局）

`#52c41a` → `var(--tjg-color-success-600)`（`#389e0d`，3.46:1）。

改动前已确认全仓 15 处引用**全部是 `background-color` / 圆点填充 / 光晕，无一处当文字**。
**若你新增"在线"文字，请用 `--tjg-color-success-700`（5.59:1），不要再引用 `status-online`。**

### 2.4 设置窗口关窗行为（`8f0df52b5` + `cefddaec4`）

- 点窗口红灯 / `Cmd+W` 现在会**先 flush 在飞写请求**，再决定是否弹"未保存"确认。
- **`window.beforeunload` 在 Tauri v2 拦不住原生关窗**，必须用 `onCloseRequested` + 同步
  `event.preventDefault()`；关闭时用 `destroy()` 而非 `close()`（后者会重入守卫）。
- 新增 `src/composables/settings/settingsPendingWrites.ts`：模块级在飞写注册表。
  **新写自动保存表单的同学请用 `trackSettingsWrite(promise)` 登记**，否则同样的丢失会再出现。

## 3. 新增的公共设施

| 设施 | 位置 | 用途 |
|---|---|---|
| `v-clickable` **可用于 `<svg>`** | `src/directives/v-clickable.ts` | 补 `role/tabindex` + Enter·Space → click。**修了一个真 bug**：`click()` 只在 `HTMLElement` 上，`SVGElement` 没有，原来直接调会抛 `TypeError` 且表现为"按 Enter 没反应" |
| `settingsPendingWrites` | `src/composables/settings/` | 关窗 / 切 tab 前 flush 在飞写请求，8s 超时 |
| `useSettingsNativeCloseGuard` | `src/composables/settings/` | 独立窗口的原生关窗守卫（可注入窗口替身，便于单测） |

### 3.1 `v-clickable` 的正确用法

```html
<!-- 交互式 svg：给它一个可访问名 -->
<svg @click="doSomething" v-clickable="t('common.back')">…</svg>

<!-- 装饰性 svg：保持 aria-hidden，不要挂 @click -->
<svg aria-hidden="true">…</svg>
```

**别做**：给 `aria-hidden` 的 svg 补 `v-clickable`（两者语义互斥）；给已有 `aria-label` 的
`<n-button>` 内部图标再套一层 `v-clickable`（父按钮已可聚焦，会变成按钮套按钮）。

## 4. 会被拦住的写法（新规则）

`pnpm check` 里的 `scripts/check-svg-aria.mjs` 从"只查身份声明"扩成 4 条交互规则：

| # | 规则 | 说明 |
|---|---|---|
| 1 | 每个 `<svg>` 必须有身份声明 | `aria-hidden` / `aria-label` / `role` / `<title>` / **`v-clickable`** |
| 2 | `aria-hidden` 与 `@click` 互斥 | 唯一例外：脚本内 `DECORATIVE_CLICK_HANDLERS` 白名单（父元素已可交互）。**加白名单必须写明理由** |
| 3 | `role="button"` 必须同时有 `tabindex` 或 `v-clickable` | 否则"有名字、没焦点" |
| 4 | 可聚焦的 svg 不得写 `outline-none` | 否则"能聚焦但看不见" |
| 5 | `#close` 图标挂 `@click` 时不得 `aria-hidden` | 例外：handler 带 `delete-account`（X 图标被复用作删除） |

### 本地跑门禁

```bash
# 注意：不要用 `node x.mjs | tail` 看退出码 —— $? 是 tail 的
for s in check-svg-aria check-icon-button-aria check-token-usage \
         check-dead-handlers check-i18n check-i18n-refs check-capabilities-sync; do
  node scripts/$s.mjs > /tmp/$s.log 2>&1
  printf "%-24s exit=%s\n" "$s" "$?"
done
npx vue-tsc --noEmit --incremental --tsBuildInfoFile node_modules/.cache/tjg-tsbuildinfo
```

## 6. 已知限制 / 未完成

1. **8 处弹窗关闭键是 `v-if="isWindows()"`**，macOS 上不渲染 ⇒ 这批改动在本机**看不到效果**，
   只有单测和静态守卫在验证。要真机确认需 Windows。
2. **9 处 svg 仍挂 `aria-hidden` + `@click`**（`ActionList` 7 个导航图标 + `MsgInputToolbar` 2 个箭头）。
   它们不是缺陷：父元素已完整可交互，子 svg 的 `@click` 只是"顺手关掉别处的提示条"。
   正是这 9 处让规则 2 只能靠白名单。**把这些冗余 `@click` 删掉后，规则 2 可收紧成"一律不许"。**
3. **设置窗口写失败 + 同时关窗**时，回滚 toast 会被关窗吞掉。
   `flushSettingsWrites` 已经返回 `{ failed }`，只是守卫没接；接上后 `failed > 0` 走确认分支即可。
4. **没有做 `<IconButton>` 组件**。这一路用 `v-clickable` + 复用现有文案已够；
   只有当交互需要"按钮 + 内部复杂结构"时才值得抽。
5. **`SingleDetails` hero 区 6 项视觉对齐未做**（头像 148→72 等），见评审报告 §3。

## 7. 一个必须记住的教训

这批里我自己犯了两次同类错误，写下来避免重复：

1. **只跑 `vitest` 不跑 `pnpm check`** —— 改完 28 处后 `check-svg-aria` 与 `check-token-usage`
   两条 CI 路径都红了，而测试全绿。
2. **先造令牌再找消费方** —— 一次性加了 10 个令牌，全部零引用，被门禁判红。
   **正确顺序：先接消费方，再加令牌**（`df5af5d2f` 就是这个顺序做的）。
3. 附带一条：**注释里的字面量会误触扫描型守卫**（`borderHover: '0'` 写在注释里也会被判违规），
   处置是匹配前剥注释，不是删注释。

> **绿灯 ≠ 类型安全 ≠ 门禁通过。** 三道都要跑。
