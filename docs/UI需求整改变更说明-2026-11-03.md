## 2. 变更清单

### 2.1 P0：锁屏自锁死（清单 §1.1，需求 5.12 / 5.12.2）

| 项 | 内容 |
| :--- | :--- |
| 根因 | `lockScreen.enable` 持久化，但 `lockScreen.password` 被 `omit` 排除持久化，重启后锁定态为真而密码恒为空，形成永久锁死 |
| 改动 | 新增 [lockScreenCredential.ts](../src/stores/domains/settings/lockScreenCredential.ts)：用 PBKDF2 verifier（复用 secretChat 的 `createSecretChatVerifier` / `verifySecretChatVerifier`，明文口令用完即 `zeroize`）派生并校验凭据；持久化字段由 `password` 改为 `passwordHash` |
| 联动 | [setting.ts](../src/stores/domains/settings/setting.ts) 持久化 `passwordHash`；[model.tsx](../src/layout/left/model.tsx) 设置密码时写入 verifier；[LockScreen.vue](../src/views/LockScreen.vue) 解锁按 verifier 校验；[App.vue](../src/App.vue) 增加 `passwordHash` 非空兜底 |
| 兼容 | 历史数据（`enable=true` 且无凭据）不再锁屏，避免升级后自锁死 |

### 2.2 P0：锁屏跨窗口同步（清单 §1.2，需求 5.12.2）

| 项 | 内容 |
| :--- | :--- |
| 根因 | 全仓只有 `emit(EventEnum.LOCK_SCREEN)`，没有任何 `listen`，需求中「各窗口同时锁定／任一窗口解锁其余同步」不成立 |
| 改动 | 新增 [useLockScreen.ts](../src/composables/settings/useLockScreen.ts)：监听 `LOCK_SCREEN` / `UNLOCK_SCREEN` 并写回设置；同时把 `isLock` 派生（含 `LockExclusion` 白名单）从 `App.vue` 收口到该组合式函数 |
| 配套 | [app.ts](../src/enums/app.ts) 新增 `UNLOCK_SCREEN = 'unlockScreen'`；[LockScreen.vue](../src/views/LockScreen.vue) 解锁成功后广播解锁事件 |
| 结构收益 | [App.vue](../src/App.vue) 由 504 行降至 496 行，不再承载锁屏域逻辑 |

### 3.3 待人工回归清单

以下涉及真实交互与视觉，自动化无法替代，需在桌面端（Tauri）人工验收：

1. 设置本机密码 → 点击锁屏 → 错误密码提示"密码不正确"且保持焦点 → 正确密码解锁。
2. 锁定后重启应用仍为锁定态，输入原密码可解锁。
3. 主窗口锁定后，独立聊天窗口 / 文件管理窗口同步锁定；任一窗口解锁后其余窗口同步解除。
4. 把 `lockScreen.enable` 置 true 且清空 `passwordHash` 后启动，界面不应被锁死。
5. 访问 `/home` 应落在 `/message`。
6. 窗口宽度在 768 / 992 / 1200 三档切换，左侧栏 64/68px、中栏 280/240/64px 与需求 8.1/8.2 一致。
7. 语音消息录制、发送、播放正常，UI 中不存在转换／优化／转写入口。
8. 管理后台举报列表可正常打开，无评分入口。
9. 能力受限账号下 `PermissionGuard` 的隐藏/只读降级正常，无 openclaw 相关项。
