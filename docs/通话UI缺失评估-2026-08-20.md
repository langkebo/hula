## 结论摘要

通话**窗口本体与媒体层已基本完整**（`callWindow` + `useVoIPCallFlow` 已接 Matrix VoIP，Issue 4 已收口），去电/来电主链路也已接线。**真正缺失的是「入口」**：好友列表右键菜单、会话/房间列表右键菜单都没有语音/视频通话入口——含通话项的菜单函数是「孤儿」，真实 UI 用的是另一套无通话项的菜单，甚至会话列表行右键是空实现。

## 二、缺失项（按严重度）

### P1-1　好友列表右键菜单无通话入口

- **现象**：好友列表右键没有「语音通话 / 视频通话」。
- **根因**：好友列表 `FriendListView.vue` 实际用的是 `src/components/friend/composables/useFriendContextMenu.ts`，其 `contextMenuItems`（send_message / encrypted_chat / secret_chat / set_note / set_display_name / 分组 / remove）**不含 voice-call / video-call**。
- **对照**：`src/composables/common/useContextMenu.ts` 的 `buildFriendMenu` **确实包含** voice-call / video-call，但全项目**没有任何 `.vue` 组件引用它**（仅 `useContextMenu.test.ts` 引用），是「孤儿」函数。
- **建议**：给 `useFriendContextMenu` 菜单项补 `voice-call`/`video-call`，并复用 `useDetailsActions.handleVoiceCall/handleVideoCall`（或直接 `startRtcCall`）处理选中项。

### P1-2　会话/房间列表右键菜单是空实现

- **现象**：会话列表（房间列表）行右键无任何菜单（更无通话入口）。
- **根因**：`src/components/workbench/TjgRoomListItem.vue` 的 `handleContextMenu`（L237-239）只 `event.preventDefault()`，**不弹菜单**。`buildRoomMenu`/`buildSpaceMenu`（含 `video-call`）同样是无组件引用的孤儿函数。
- **建议**：为会话列表行接入右键菜单，单聊行提供语音/视频通话，群聊行按能力决定是否展示视频通话（见 P2-1）。

### P2-1　群聊通话能力被禁用，但按钮仍展示

- **现象**：群详情页/聊天头仍显示「视频通话」，点击仅弹警告「群聊暂不支持」。
- **根因**：`src/composables/common/windowRtc.ts` 的 `startRtcCall`（L43-46）对 `RoomTypeEnum.GROUP` 直接 `showFeedback('group_call_not_supported')` 并 return。
- **建议**：二选一——(a) 群聊场景隐藏通话按钮（UI 与能力对齐）；(b) 实现群聊通话后再开放入口。

### P2-2　屏幕共享无独立发起入口

- **现象**：无独立「屏幕共享」入口。
- **根因**：`ChatHeaderRoot.vue` 的 `handleScreenShare`（L371-374）注释明示「屏幕共享在现有架构下只能在通话内进行」，实际复用视频通话窗口（`startRtcCall(VIDEO)`）。
- **建议**：短期在通话内控制栏开放共享；独立发起入口需新增媒体流授权与推流接线，另立项。

---

## 三、修复优先级建议

1. **P1-1 + P1-2**：补齐好友列表 / 会话列表右键菜单的通话入口（复用现成的 `startRtcCall` 链路，改动小、收益直接）。
2. **P2-1**：群聊通话按钮与能力对齐（隐藏 or 实现）。
3. **P2-2**：屏幕共享独立入口（依赖媒体层扩展，另立项）。
