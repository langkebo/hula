## 问题 1：DM 房间 403 风暴（发消息彻底失败）🔴

### 现象
点击好友 `@admin` 发起私聊后，`unread_count`、`typing`、`send m.room.message` 全部返回 403：

```
unread_count -> 403 "You must be a member of this room to view events"
typing       -> 403
send         -> 403 "Insufficient permission"（重试 3 次后放弃）
```

### 根因
`useFriendContextMenu.performSendMessage` 无条件信任后端 `GET /friends/{uid}/dm` 返回的 `room_id`，直接打开一个**当前用户不是 joined 成员**的房间。后端残留了 stale 房间（`!0_BlkFtiKB...`），@test1 并非其成员，但客户端仍切换过去并允许输入，导致后续所有请求被服务端 403 拒绝。

### 修复
`src/components/friend/composables/useFriendContextMenu.ts` 增加成员校验：

```ts
function isJoinedRoom(roomId: string): boolean {
  const room = matrixClientService.getRoom(roomId)
  return !!room && room.getMyMembership?.() === 'join'
}
```

`performSendMessage` 仅在「后端返回房间 **且** 当前用户确为 joined 成员」时才直接打开，否则回落到本地 `contactStore.startDirectRoom` 重建。校验方式与项目既有 `useFooterOverlays` / `MatrixClientRoom` 的 `getMyMembership() === 'join'` 模式一致。

### 测试
- `useFriendContextMenu.test.ts`：新增 2 个回归用例（非 join 成员回落、未同步房间回落），mock `MatrixClientService`。
- `FriendListView.test.ts`：同步 mock 适配。

## 问题 2：i18n「仅 @提及」Invalid linked format 崩溃 🔴

### 现象
打开房间设置 → 通知 tab 时渲染崩溃：

```
Message compilation error: Invalid linked format
1  |  仅 @提及
   |     ^
```

### 根因
vue-i18n 的 message 编译器遇到 `@` 会进入 linked message 解析，`@` 后跟非 `.` / `:` 即抛 `INVALID_LINKED_FORMAT`。翻译值里的字面 `@`（`仅 @提及`）被误判为 linked 引用符。

### 修复
5 处裸 `@` 转义为项目既有约定的 `{'@'}` 字面量语法：

| 文件 | key | 修复前 → 修复后 |
|---|---|---|
| `zh-CN/room.json` | `notification_mentions` | `仅 @提及` → `仅 {'@'}提及` |
| `zh-CN/mobile_notifications.json` | `mention_only` | `仅@提及` → `仅{'@'}提及` |
| `zh-CN/message.json` | `mention_tag` | `[有人@我]` → `[有人{'@'}我]` |
| `zh-CN/setting.json` | `password_need_special` | `!@#$%^&*` → `!{'@'}#$%^&*` |
| `en/setting.json` | `password_need_special` | 同上（英文） |

改后执行 `pnpm gen:i18n` 同步 `src/typings/i18n.d.ts`。

### 验证
用 `createI18n` 实际解析 4 处修复值，全部正确输出字面 `@`，无 linked 错误。

## 问题 3：Space 创建 m.room.member in initial_state 400 🔴

### 现象
```
createRoom -> 400 "m.room.member cannot be supplied in initial_state"
```

### 根因
`MatrixSpaceService.createSpace` 在 `createRoom` 的 `initial_state` 里显式声明了创建者的 `m.room.member` join 事件。Matrix 规范禁止通过 `initial_state` 提供成员事件，synapse-rust 直接返回 400。创建者本就由服务端自动设为 joined 成员，无需显式声明。

### 修复
删除 `initial_state` 中的 `m.room.member` 块，仅保留头像事件。测试新增契约断言，防止该铁律再次被破坏。
