## 0. 结论摘要

| 严重度 | 数量 | 主要分布 |
| --- | --- | --- |
| 阻塞 | 4 | Tauri 权限面与 CSP（安全） |
| 严重 | 12 | 通知规则失效、同步订阅、索引库自愈、房间切换竞态、测试假绿、分层依赖环 |
| 一般 | 20 | 资源泄漏、并发收尾、事务与锁、测试盲区、重复实现 |
| 优化建议 | 8 | 配置一致性、依赖瘦身、可维护性 |

**最该先动的三件事**：

1. 收窄 Tauri 的「本地文件 + 外部协议 + TLS 校验 + 任意 https iframe」四条通道（B1–B4）。凭据加密本身合格，但渲染层一旦被注入，这四条可组合成完整的本地数据外泄链路。
2. 修「仅 @ 提及」推送规则（S1）——当前实现下该选项等于静音，是**用户可感知且 100% 复现**的功能缺陷。
3. 修索引库与同步补订阅的自愈能力（S2、S3）——一次瞬时故障会变成**永久降级**，且无日志之外的恢复路径。

安全基本盘（已核验为「合格」，不列入问题）：凭据 AES-GCM + 钥匙串主密钥落库、`.env.local` 已忽略、CSP 无 `unsafe-eval`（`script-src` 为 `wasm-unsafe-eval`）、SQL 全参数化、上传路径有 `path_guard`、updater 配置 minisign 公钥、SDK tarball pin 三方一致。

## 1. 阻塞（发布前必须修复）

### B1 · `allow_asset_path` 可把任意本地文件加入 asset 协议作用域
- 位置：[asset_command.rs](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/src/command/asset_command.rs#L7-L27)，注册于 [lib.rs](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/src/lib.rs#L654)
- 证据：参数 `path` 只做 `canonicalize()` 与 `is_file()`，随后 `app.fs_scope().allow_file(&canonical_path)`。
- 影响：`assetProtocol` 静态 scope 虽只有 `$APPDATA/$RESOURCE/$CACHE/$TEMP`（[tauri.conf.json](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/tauri.conf.json#L59-L66)），但该命令可**动态扩容**到 `~/.ssh`、钥匙串导出、任意用户目录。渲染层被注入（XSS/恶意 widget）即可读取并外传。
- 修复方向：仅接受前端的 dialog 选择结果（服务端校验 file token 与选择记录一致）；或限定 canonical 路径必须落在 `$APPDATA` 子目录；返回值不回传绝对路径。

### B2 · http 插件开启 `dangerous-settings` + `unsafe-headers`
- 位置：[Cargo.toml](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/Cargo.toml#L57-L61)
- 证据：`tauri-plugin-http = { version = "2.5.4", features = ["dangerous-settings", "unsafe-headers", "rustls-tls"] }`
- 影响：`dangerous-settings` 允许渲染层在请求里关闭证书校验（`acceptInvalidCerts`），`unsafe-headers` 允许伪造 `Cookie`/`Origin`。与 B1 组合，token 与文件内容可在中间人下被截获。
- 修复方向：移除两个 feature；确有自签证书需求时改成 Rust 侧自定义命令 + 固定证书指纹白名单。

### B3 · CSP `frame-src` 放通任意 https 页面
- 位置：[tauri.conf.json](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/tauri.conf.json#L50)
- 证据：`frame-src 'self' https:;`
- 影响：远程页面可嵌入主窗口 DOM 树，继承同 label 的窗口权限（asset / fs / shell）。若业务需要嵌入外部内容，等于把攻击面交给第三方页面。
- 修复方向：移除 `frame-src https:`，外部内容改用独立 `WebviewWindow` 并单独收窄 capability；确需 iframe 时改为显式域名白名单。

### B4 · 本地文件与外部程序面过宽（3 处叠加）
- 位置：
  - [default.json](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/capabilities/default.json#L79-L86)：`shell:allow-open`、`opener:allow-open-path` 对全部窗口开放
  - [directory_scanner.rs](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/src/desktops/directory_scanner.rs#L61-L70)、[:209-213](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/src/desktops/directory_scanner.rs#L209-L213)：`directory_path` 直接进 `AsyncWalkDir`，只判 `is_dir()`
  - [network.json](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/capabilities/network.json#L64-L74)：`http://127.0.0.1:**`、`http://localhost:**`
- 影响：可递归枚举用户文档目录（绕过 fs scope）；可打开任意 `file://`/自定义协议触发系统处理器（钓鱼升级为本地执行）；可探测/攻击本机任意 HTTP 服务（本地 SSRF）。
- 修复方向：目录扫描只接受 dialog 返回值或白名单根目录；`opener` 改自定义命令 + 协议白名单；network scope 只放通 OAuth 回调端口。

## 2. 严重

### S1 · 「仅 @ 提及」推送规则永不命中
- 位置：[RoomOperations.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/services/matrix/room/RoomOperations.ts#L574-L586)
- 证据：条件为 `{ kind: EventMatch, key: 'content.body', pattern: localPart }`。
- 影响：`EventMatch` 对字段值做**整串相等**匹配，消息 body 不可能恰好等于用户名。用户选择「仅 @ 提及」后连真正的 @ 也收不到通知，等价于静音房间，且难以自查。
- 修复方向：改用 `m.mentions` 条件（`contains_user_name` / `org.matrix.msc3952.mentions`）或 `ConditionKind.ContainsUserName`；补一条单测直接断言生成的 rule 条件类型。

### S2 · 补订阅标记先于结果写入，失败后永不重试
- 位置：[MatrixSlidingSyncService.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/services/matrix/sync/MatrixSlidingSyncService.ts#L184-L190)
- 证据：`autoSubscribedRooms.add(roomId)` 在 `subscribeRoomForSync(roomId)` **之前**，且 `has()` 判断位于 `getRoom()` 之前。
- 影响：订阅请求失败（断网/服务端 5xx）后该 roomId 永久占位（只在 stop 时 clear），被邀请/被拉入的新会话持续收不到消息，且不会再重试。只能靠重启客户端恢复。
- 修复方向：成功回调或「本地出现该 room」后再标记；给标记加 TTL 与最大重试次数；`has()` 判断后仍检查 `getRoom()`。

### S3 · IndexedDB open 失败被永久缓存
- 位置：[searchIndexDb.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/workers/searchIndexDb.ts#L33-L63)
- 证据：`if (dbPromise) return dbPromise`；`request.onerror` 只 reject，不重置 `dbPromise`；无 `onblocked` / `onversionchange`。
- 影响：一次打开失败（多标签页版本升级 blocked、隐私模式、配额耗尽）后，所有搜索读写都拿到 rejected promise，搜索**永久不可用**，且没有自愈路径。
- 修复方向：reject 时 `dbPromise = null`；补 `onblocked` 与 `db.onversionchange`（close + 重建）；查询侧对失败做一次重置重试。

### S4 · 房间切换的异步收尾覆盖「当前房间」状态
- 位置：[messageLoading.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/stores/domains/chat/chat/messageLoading.ts#L220-L238)、[:110-116](file:///Users/ljf/Desktop/hu_ts/Tjg/src/stores/domains/chat/chat/messageLoading.ts#L110-L116)
- 证据：`catch` 直接写 `currentMessageOptions.value = { cursor: '' ... }`；末尾无条件 `markSessionRead(globalStore.currentSessionRoomId)`。`currentMessageOptions` 指向「当前房间」而非入参 `roomId`。
- 影响：await 期间用户 A→B 切换时，A 的失败/收尾会清掉 B 的分页游标，并把 B 标为已读（未读角标被错误清除）。另外加载失败即抹掉 cursor，用户向上翻页会退回首屏，历史翻不回来。
- 修复方向：收尾前比对 `roomId === globalStore.currentSessionRoomId`，否则 return；失败分支保留旧 cursor，只置 `isLoading=false`。

### S5 · e2e 存在 14 处永久跳过
- 位置：[room-settings-e2e.spec.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/e2e/room-settings-e2e.spec.ts#L162) 等 10 处 `test.skip(true, ...)`；[scenario-23-settings-persist.spec.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/e2e/scenario-23-settings-persist.spec.ts#L17)、[scenario-30-capability-fallback.spec.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/e2e/scenario-30-capability-fallback.spec.ts#L20) 为 `test.fixme`（`grep -c` 合计 14）。
- 影响：房间设置、设置持久化、能力降级三类场景**永不执行**，CI 全绿造成「已有覆盖」的错觉；这三类恰好是回归高发区。
- 修复方向：用 mock room 补真实断言后取消 skip；确实阻塞的用例改为 `test.fixme` 并在 issue 中登记，禁止 `skip(true, '文案')` 长期留存。

### S6 · 安全域与 worker 域缺直接单测
- 位置：`src/services/matrix/crypto/**` 27 个文件中 8 个无测试（`cryptoStoreCleanup.ts`、`cryptoLocalState.ts`、`messageTrustCache.ts`、`cryptoLifecycleDiagnostics.ts`、`cryptoErrorNormalize.ts` 等）；`src/workers/**` 14/16 无测试（含 `matrixSdk.worker.ts`、`workerMessageValidation.ts`、`workerState.ts`）。
- 影响：登出清钥、换账号信任残留、worker 消息校验、主线程↔SDK 桥接全部裸奔；这些模块出错的后果是「解密失败/串号/静默丢消息」，且难以通过 UI 复现。
- 修复方向：按状态迁移补契约测试（登出→密钥清空；换账号→信任缓存失效；worker 消息 schema 拒绝非法 payload）。

### S7 · store 与 service 双向依赖形成环
- 位置：service 引 store：[MatrixTypingService.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/services/matrix/messaging/MatrixTypingService.ts#L2)、[MatrixPresenceService.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/services/matrix/user/MatrixPresenceService.ts#L11)、[RealtimeService.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/services/matrix/room/RealtimeService.ts)；store 引 service：[sync.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/stores/domains/chat/room/sync.ts#L3-L8)、[matrix.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/stores/domains/chat/chat/matrix.ts#L4-L13)
- 影响：初始化顺序敏感（store 在 Pinia 未激活前被 service 调用会抛错）；worker 无法脱离 Pinia 复用 service；单测必须 mock 整个 store 层。
- 修复方向：service 侧改为回调/上下文注入（构造函数或 `setHooks`），由 store 在初始化时注册；先做一个域（typing/presence）试点。

### S8 · Worker 内裸 fetch 打 Matrix 端点
- 位置：[workerProbeHandlers.ts](file:///Users/ljf/Desktop/hu_ts/Tjg/src/workers/workerProbeHandlers.ts#L33)（另见 `:63`、`:100`、`:137`、`:159`），已被 [check-no-raw-fetch.mjs](file:///Users/ljf/Desktop/hu_ts/Tjg/scripts/check-no-raw-fetch.mjs#L56) 白名单放行。

- 修复方向：探测改为主线程代理（postMessage 请求），或复用 `runtimeFetch`；同步更新白名单，避免规则被长期豁免。

### S10 · 移动端设置项为静态数组，无能力过滤
