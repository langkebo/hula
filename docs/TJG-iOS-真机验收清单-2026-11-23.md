# TJG iOS 真机验收清单（2026-11-23）

本条清单对应 7 步计划的第 6 步，覆盖本轮 iOS 原生层全部改动：
APNs 回调注入、原生 Splash、键盘上方栏移除（A1）、角标（B8）、
本地网络权限中文文案（方案 B）、Draco 资源裁剪。

## 0. 前置准备

| 项 | 要求 |
| :--- | :--- |
| 设备 | 1 台 iPhone（iOS 16+）+ 1 台 iPad（iOS 16+，**A1/B1/B2 必须 iPad**） |
| 签名 | 具备 `com.tjg.ios` 描述文件的 Apple 开发者账号（否则 `tauri ios build` 卡在 archive） |
| 后端 | 真机可访问的 synapse-rust 实例（`VITE_HOMESERVER_URL` 指向公网/同网段地址） |
| 网络 | 真机与开发机在同一 Wi-Fi；若用 LAN IP 调试，本地网络权限需放行 |
| 构建 | `pnpm tauri ios build --target aarch64-apple-ios --release`，或 Xcode 打开 `src-tauri/gen/apple/tjg.xcodeproj` 直接 Run 到真机 |
| 日志 | Xcode → Window → Devices and Simulators → 选中设备 → Open Console，过滤 `process == "Tjg"` |

> 提示：`xcrun simctl` 只对模拟器有效，真机日志统一走 Console.app / Xcode 控制台。

环境结论（本轮新增，影响后续模拟器调试方式）：

| 项 | 结论 |
| :--- | :--- |
| 模拟器回环 | iOS 26 模拟器内 `127.0.0.1` 与宿主不共享：Simulator 内 Safari 访问 `http://127.0.0.1:5210` 报 `Connection refused`，必须使用宿主 LAN IP |
| 本地网络授权 | `xcrun simctl privacy` 不支持 `local-network`；直接向模拟器 `TCC.db` 写入 `kTCCServiceLocalNetwork` 授权行重启后仍无效 |
| dev server 并发 | dev 模式上千个 `?import` 请求经模拟器代理时成批失败（627 请求 / 210 失败），改用生产构建 `dist` 静态服务后失败数归零 |
| `tauri ios build --target aarch64-sim` | 前端产物可正常生成，但 Rust 阶段 `tauri` build script 的 Swift 桥接错误解析到 `MacOSX27.2.sdk`，`BUILD FAILED`，暂不可作为离线包方案 |
| 生产构建渲染观察 | 登录页与聊天页大量私有区字形/图标显示为 `[?]` 方块（中文候选栏里的「何鲁丽」「喝了」渲染正常，说明系统 CJK 字体存在）。因此根因不是「模拟器缺 PingFang」，更可能是 WKWebView 在 dev-over-HTTP 部署下的字体解析/图标字体加载问题，需在真机与正式打包产物上复核，不阻塞本次验收 |
| 触摸注入链路（本轮打通） | `simctl` 不支持触摸；改用 idb（`~/Library/Python/3.11/bin/idb ui tap <x> <y> --udid <UDID>`，pt 坐标）+ AppleScript 驱动 DeviceHub 菜单，可无人值守完成点击/输入/截图 |

## 弹窗报错

### 结论（2026-11-23 排查）

**系统层原因（模拟器 WebKit/JavaScriptCore 自身崩溃），非项目代码缺陷；本项目的大前端只放大了触发概率。**

证据（本机 `~/Library/Logs/DiagnosticReports`，2026-11-23 共 21 份 WebContent 崩溃，13 份 SIGBUS + 8 份 PAC）：

| 判据 | 事实 |
| :--- | :--- |
| 崩溃进程 | `com.apple.WebKit.WebContent`，`Path: /Volumes/VOLUME/*/...`、`Parent Process: launchd_sim`、`Coalition: SimDevice.6E7693A2…` —— 是模拟器内的 Web 内容进程，Tjg 主进程未崩 |
| 签名一（13 份） | `EXC_BAD_ACCESS (SIGBUS)` / `KERN_PROTECTION_FAILURE`，崩溃线程 `JIT Worklist Helper Thread`，栈为 `JSC::DFG::Graph::hasExitSite` → `FixupPhase::fixupNode` → `JITWorklistThread::work`，fault 地址 `0x4002…` 落在 JIT 保留区，即 JSC 自己的 JIT 代码页失效 |
| 签名二（8 份） | `EXC_BREAKPOINT` + `Termination: PAC_EXCEPTION`，栈为 `JSC::Integrity::Analyzer::analyzeCell` ← `JSC::Wasm::Table::set` ← `operationSetWasmTableElement`，即 WebAssembly 表操作时 JSC 内部指针认证校验失败 |
| 主线程在做什么 | Thread 0 当时在执行 `IDBTransaction::abortInternal` / `jsIDBTransactionPrototypeFunction_abort`；崩溃在 Thread 8，IDB 只是并行任务，不是崩溃点 |
| 环境 | 宿主 macOS 27.2.1 (26B131, Mac16,10 Apple Silicon) + 模拟器 iOS 26.3.1，WebKit/JavaScriptCore 8623；跨代组合下模拟器 JIT/WASM 最不稳定 |

为什么「总不停弹窗」：模拟器的 WebContent 以宿主 macOS 进程运行，每次崩溃都会触发宿主 ReportCrash 弹出「com.apple.WebKit.WebContent 意外退出」；真机上 WebContent 崩溃只会重载页面，不会出现该弹窗。

项目侧事实（触发负担，非缺陷）：`dist` 41 MB / 319 个 JS 分包 / 11 MB JS（最大单包 0.8 MB 为 `matrixSdk.worker`），首屏 14 个 `modulepreload`，未预加载 shiki 语法包与 Draco —— 分包策略本身正常，仅在启动/登录时同时编译较多 JS/WASM，抬高了 JSC 触发崩溃的概率。

处置建议：
1. 换用 iOS 27.2 运行时（与宿主同代）新建模拟器复验，或 `xcrun simctl erase` 重建当前 26.3 模拟器后重测。
2. 模拟器里只用生产 `dist`（不要 devUrl/dev server），减少同时编译的模块数。
3. 调试期可临时关闭宿主崩溃弹窗：`sudo defaults write com.apple.CrashReporter DialogType none`（恢复用 `-string browser`）；仅止弹窗，不消除崩溃。**（2026-11-23 已应用：经管理员授权写入并回读为 `none`；恢复命令 `sudo defaults write com.apple.CrashReporter DialogType browser`）**
4. 最终以真机复验为准：真机不复现即记为「模拟器环境限制」，不计入项目缺陷。
5. 可选降载（非必须）：启动期延后非首屏重资源（shiki 语法包、Draco/WASM），避免与首屏同步编译。
