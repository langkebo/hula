## 2. 布局基线修正（文档 §0 更正）

> 原文档 §0 描述的「240-360 中栏 / 360px 抽屉 / 1200-992-768 四档响应式 / 时间线 800px」在代码中均未落地。本节记录**实际布局基线**，作为后续验收基准。

### 2.1 实际布局基线（代码事实）

| 项 | 文档描述 | 实际值 | 证据 |
|----|---------|--------|------|
| 左导航栏 | 64px(Win)/68px(macOS) | `isMac26() ? 'min-w-64px' : 'min-w-68px'` | `src/layout/left/index.vue:39` |
| 中栏宽度 | 240-360px | **280-400px**（`MIN_CENTER_WIDTH=280, MAX_CENTER_WIDTH=400`）+ `settingStore.panelWidth` 钳制 200-600 | `src/layout/center/index.vue:38-41` |

| 三栏最小总宽 | 310px | `min-w-310px` | `src/layout/index.vue:4` |
| 响应式断点 | sm576/md768/lg992/xl1200/2xl1400 | 配置一致，**但运行时用 1440/1024 两阈值三档**（wide/normal/shrink） | `uno.config.ts:158-164` / `useResponsiveBreakpoint.ts:35-45` |

| 消息头部 | 56px 固定 | **60px min-height**（非固定高度） | `ChatHeaderRoot.vue:469` |
| 时间线居中 | max-width:800px | **无此限制** | Grep `max-width:800px` 聊天样式无命中 |

### 2.2 布局修正建议

- **中栏宽度**：统一到 280-400px（实际值），更新文档 §0 表格；或若需对齐 240-360，需修改 `MIN_CENTER_WIDTH`/`MAX_CENTER_WIDTH`（但建议以实际为准，280-400 更合理）。
- **响应式分档**：`useResponsiveBreakpoint.ts` 实际为 1440/1024 三档，与文档的 1200/992/768 四档不符。建议二选一：
  - 方案 A：更新文档对齐实际（1440/1024 三档）
  - 方案 B：修改代码对齐文档（1200/992/768 四档，需重构 useResponsiveBreakpoint）
- **360px 抽屉**：文档要求大屏 ≥1200 下详情抽屉 360px 覆盖，**实际未实现**。若需实现，需新建 `DetailDrawer` 组件。
- **时间线 800px 居中**：文档要求大屏下消息时间线 max-width:800px 居中，**实际未实现**。若需实现，在 `ChatMain` 时间线容器添加 `max-width: 800px; margin: 0 auto`。
- **群聊右栏 280px**：实际为 240px，若需对齐文档 280px，修改 `ChatSidebar.vue:8` 的 `w-240px` → `w-280px`。

> **决策待定**：以上布局修正涉及数值对齐方向（文档→代码 or 代码→文档），建议与产品确认后再行动。
