## 1. 文档目的

用于为优化计划执行阶段提供标准发布模板，覆盖：

- 发布前检查清单
- 灰度发布记录
- 回滚演练与回滚执行单
- 发布复盘模板

本文件不替代现有自动化发布工作流，而是补足“流程治理文档层”的最后一段，让交付链从 `Issue -> PR -> Release -> Rollback -> Postmortem` 完整闭环。

---

## 2. 与现有发布流程的关系

### 2.1 当前自动化发布事实

基于 [release.yml](file:///Users/ljf/Desktop/hu_ts/hula/.github/workflows/release.yml#L1-L299)，当前可确认的发布链路包括：

- 以 `v*` tag 触发发布
- 先构建前端产物并上传 `frontend-dist`
- 再进入多平台 Tauri 构建
- release 默认先以 draft 形式创建，再由后续 job 发布
- 最后触发 UpgradeLink 上传

### 2.2 当前流程缺口

- 缺少标准化“发布前人工确认清单”
- 缺少灰度记录模板
- 缺少回滚演练记录模板
- 缺少发布后复盘模板

### 2.3 建议使用方式

- 自动化构建与打包：继续使用 [release.yml](file:///Users/ljf/Desktop/hu_ts/hula/.github/workflows/release.yml)
- 发布申请、灰度、回滚、复盘：使用本文件模板
- 重大优化项上线前，要求至少补齐“发布前检查 + 灰度记录 + 回滚说明”

### 4.2 优化专项灰度建议

| 变更类型 | 建议灰度方式 | 建议观察指标 | 典型回滚动作 |
|---|---|---|---|
| 性能优化 | 先内部包，再小流量用户 | 启动耗时、FPS、longtask、用户投诉 | 关闭性能开关或回退相关 PR |
| Bundle / 构建调整 | 先单平台，再全平台 | 安装包可用性、白屏率、资源加载失败 | 回退构建配置或恢复旧 chunk 策略 |
| CSP / capability 收紧 | 先测试环境，再预发，再正式 | 登录失败、OIDC、媒体、更新、外链异常 | 恢复旧配置并重新打包 |
| token 存储迁移 | 先兼容读取，再切换默认写入 | 自动登录成功率、会话恢复率、token 丢失率 | 恢复旧写入路径并保留兼容读取 |

## 7. 首批优化任务发布模板

### 7.1 性能 / bundle 基线类任务发布建议

适用任务：

- `P0-PERF-01`
- `P0-BUNDLE-01`

建议：

- 这类任务通常不直接发布生产功能，可使用“归档型发布清单”
- 若仅更新文档与分析产物，可不走正式灰度，仅保留发布前检查记录
- 若伴随埋点或构建配置改动，则应附上灰度记录

### 7.2 安全配置类任务发布建议

适用任务：

- `P0-SEC-01`
- `P0-SEC-02`
- `P0-SEC-03`

建议：

- 必须补“发布前检查清单”
- 必须补“回滚执行单”
- 如果改动影响登录、更新、媒体、会话恢复，必须先做灰度发布记录
