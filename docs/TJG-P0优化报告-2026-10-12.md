## 二、逐项变更说明

### P0-1 重建本地会话加密（SC-01，提交 `a64647f9`）

**问题**：原 `src/services/secure/sessionCrypto.ts` 使用**硬编码常量派生密钥** + 裸 SHA-256，且加密 / 解密失败时**静默回退明文**。任何能读到静态代码或 `sessionStorage` 的方即可还原 AI API Key 等敏感值，等于明文存储。

**优化动作**：
1. **密钥来源**：改为 **per-install 随机密钥**（`crypto.getRandomValues(32B)`，Base64 存入 `localStorage`，key 名 `tjg-session-crypto-secret-v2`）；仅在 Tauri 平台安全存储不可用的回退链路中生效。
2. **派生算法**：由裸 SHA-256 改为 **PBKDF2-HMAC-SHA-256，210,000 次迭代，随机 16 字节盐**，派生 AES-256-GCM 密钥。
3. **密文格式与版本**：新增版本前缀 `tjg:v2:`，密文体为 `base64(salt(16) | iv(12) | ciphertext)`，为未来密钥轮换留出扩展位。
4. **失败语义改为 fail-closed**：加密失败**抛错**、解密失败**抛错**，彻底移除「使用明文存储 / 作为明文读取」两条降级路径。
5. **向后兼容（关键）**：保留 **v1 只读迁移分支** —— 无 `tjg:v2:` 前缀的旧密文走 `decryptLegacyV1`（复刻旧算法）仍可解；写入侧一律升为 v2，旧密文在首次读写后可自然迁移。

**变更文件**：

| 文件 | 变更 |
| :--- | :--- |
| `src/services/secure/sessionCrypto.ts` | 重写（PBKDF2+AES-GCM + 版本前缀 + fail-closed + v1 只读分支） |
| `src/services/secure/robotAiProviderStorage.ts` | 2 处边界 catch：加密失败放弃写 sessionStorage（不降级明文）；解密失败忽略该回退值 |
| `src/services/secure/__tests__/sessionCrypto.test.ts` | 新增（9 用例，见 §三） |
| `scripts/settings-wiring-manifest.json` | 登记新持久化 key `tjg-session-crypto-secret-v2`（kind=credential，storage=local） |

**前后对比**：

| 维度 | 优化前 | 优化后 |
| :--- | :--- | :--- |
| 密钥来源 | 硬编码常量（源码可见） | per-install 随机 32B（localStorage，运行时生成） |
| 密钥派生 | 裸 SHA-256（0 迭代、无盐） | PBKDF2-HMAC-SHA-256（210,000 迭代 + 16B 随机盐） |
| 加密算法 | AES-GCM（弱密钥） | AES-256-GCM（强派生密钥） |
| 加密失败处理 | 回退明文写入 | **抛错**（不写入） |
| 解密失败处理 | 返回密文原文 | **抛错** |
| 密文可轮换性 | 无版本标识，无法平滑升级 | `tjg:v2:` 版本前缀 + v1 只读迁移 |
| 明文泄漏面 | sessionStorage 回退值可被还原 | 无（无条件加密或放弃写入） |

**行为影响 / 兼容性**：仅影响「Tauri 安全存储不可用时的 sessionStorage 回退值」这条**非主路径**；主路径（`secure_store.rs` / keyring 合规存储）不受影响。旧 v1 密文仍可解密 → **向后兼容**。代价是 PBKDF2 210k 迭代带来一次性派生开销（仅在读写该回退值路径，非热路径）。

### P0-3 收紧移动端网络权限（SC-02）— ⚠️ 取证完成，待决策

**审查建议**：将 `src-tauri/capabilities/mobile.json` 的 `http:default` 由 `https://**` 收敛为显式 host 白名单（homeserver + 后端域名）。

**现状取证**（[mobile.json#L107-L114](file:///Users/ljf/Desktop/hu_ts/Tjg/src-tauri/capabilities/mobile.json#L107-L114)）：

```json
{
  "identifier": "http:default",
  "allow": [
    { "url": "https://**" },
    { "url": "http://localhost:**" },
    { "url": "http://127.0.0.1:**" }
  ]
}
```

**冲突点（为何暂不改）**：TJG 的 homeserver 地址由**用户在运行时配置**（`localStorage` key `tjg-homeserver-url`），支持任意 host、自建实例与联邦。若改为**静态** host 白名单，将直接**破坏自建 / 联邦 homeserver 的连通性**——媒体下载、联邦请求均会因 scope 拒绝而失败，属功能性回归。静态白名单与「用户可配置 homeserver」的产品能力在本项目内**不可同时成立**。

**建议方案（待决策，按推荐度排序）**：
1. **动态 scope 下发**（推荐）：保留运行时能力，但由 Rust 侧在用户配置 homeserver 时，通过 `tauri::scope::http` API 动态 `allow` 该 host（含其联邦媒体域），实现「能力随配置收敛」而非全放开。需在 `src-tauri` 增加配置联动逻辑。
2. **构建期白名单注入**：若发行版将 homeserver 固定，可在打包时用环境变量注入白名单，仅适用于中心化部署形态。
3. **维持现状 + 记录风险**：若必须支持任意联邦，则 `https://**` 为必要能力，转由**传输层鉴权**与**内容安全策略**缓解，风险登记在案。

> 结论：P0-3 按「保守：其余先报告」执行——**本阶段不改 `mobile.json`**，冲突取证与三选一方案如上，等待决策后单独立项。
