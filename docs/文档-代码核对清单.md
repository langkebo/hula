## 1. 机制说明

文档中的路由表、设置 Tab 清单、管理导航分组与契约数字，一律以代码为唯一来源；本清单固定「文档章节 → 代码来源 → 核对方法」的对应关系，避免再次出现「改了代码没改文档」或「文档写了一个不存在的路由」。

**必须更新的时机**

- `src/router/routes/*.ts` 增删路由或改动子路由归属；
- `src/stores/domains/settings/settingsSchema.ts` 增删设置 Tab 或调整分组；
- `src/views/admin/useAdminNav.ts` 的 `rawNavGroups` 增删项或调整分组；
- `synapse-rust` 重新导出路由契约（`backend_routes` 等数字变化）。

## 5. 变更流程

1. 先改代码或先改文档，但两者必须在同一次提交内一致；
2. 同步更新需求文档对应表格（§5.7 / §5.8 / §10.1 / §10.2 / §10.3）；
3. 更新本清单第 2 节结论与开头的「最近核对」日期；
4. 运行 `node scripts/check-integration-map-freshness.mjs --print` 复核契约数字；
5. 随同一次 commit 提交（commit scope 使用 `ui`）。
