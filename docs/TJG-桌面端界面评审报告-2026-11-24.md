# Tjg 桌面端界面评审报告（2026-11-24）

> 评审输入：6 张实机截图（消息列表 / 好友列表 / 房间卡片 / 空间空状态 / 加密会话 / 设置-账号）
> 评审方式：设计、体验、前端三方独立取证 → 交叉质证 → 以源码和实测为准
> 结论口径：**只认源码取值与 `getComputedStyle` 实测值，不认截图取样色和推断**

## 0. 一句话结论

截图里"看不清"的问题基本都不是"颜色选得不好看"，而是**同一个根因的多种表现**：
项目把**填充色**当**文字色**、把**装饰色**当**控件边界色**、把**不可聚焦元素**当**可交互元素**。
三类误用各有一批，本轮修掉了其中最贵的部分，其余列出验收判据待排期。

## 2. 修复明细（before → after，附判据）

### 2.1 左侧导航栏：未选中图标长期不达标

| | 值 | 对比度 |
|---|---|---|
| 改前 | `rgba(255,255,255,.78)` on `primary-500 #13987f` | **2.78:1** ✗ |
| 改后 | `rgba(255,255,255,.88)` on `primary-600 #0f7a66` | **3.9:1** ✓ |

判据 WCAG 1.4.11 非文本 3:1。这 5 个图标是屏幕上"存在时间最长、看得最多"的元素，
原方案却把最弱的一档给了它们。
顺带解决：白 pill 选中态 vs rail **5.26:1** ✓，选中图标 `primary-600` on 白 **5.26:1** ✓
（原方案是"白 18% 蒙层 pill + 白图标"，pill 与图标同色，选中态只靠一层几乎看不见的蒙层区分）。

**未动**：`--left-active-indicator-color` 保持白色——白 pill 下这条白指示条会隐形，
侧栏当前不渲染该指示条，改它属于"改没有消费方的东西"。

### 2.2 语义色：填充档被当文字档用

项目已有完整分档，但调用处普遍取了 `-500`：

| 令牌 | 值 | 白底对比度 | 允许用途 |
|---|---|---|---|
| `success-500` | `#52c41a` | 2.27 | **仅填充**（≥3:1 都不够，只能做面积块） |
| `success-600` | `#389e0d` | 3.46 | 仅图形（圆点、图标） |
| `success-700` | `#237804` | 5.59 | **文字** |
| `danger-500` | `#ff4d4f` | 3.27 | 仅填充 |
| `danger-700` | `#a8071a` | 7.75 | **文字** |

改动：
- `--tjg-status-online`：`#52c41a` → `var(--tjg-color-success-600)`。全仓 15 处引用**全部**是
  `background-color` / 圆点填充 / 光晕，无一处当文字 → 提升到 3.46 安全。
- 三处文字用途改 `-700`：`RobotCard` 在线文字、`FedStatusBadge` 在线标签、`SingleDetails` 删除好友文字。
- 房间卡片加密群聊左边条：`success-500` → `success-700`。这条 3px 竖条是**唯一**信息载体
  （卡片上没有"加密"字样），2.27:1 等于没写。

### 2.3 来电横幅：焦点环写在按钮自己身上

两个圆形按钮原本 `focus-visible:ring-2 ring-[--tjg-color-danger-400]`，
ring 颜色（`danger-400`）和按钮底色（`danger-500`）是同一色相相邻档 → **2.56:1**；
接听键 `ring-primary-300` on `primary-500` → **1.99:1**。
即"键盘用户看不到焦点"。

改法不是换更亮的 ring，而是**删掉这段压制，交回全局规则**
（`base.scss:11–15`：`outline: 2px solid primary-500; outline-offset: 2px`）——
outline 带 2px 偏移，落在横幅底色 `surface-panel` 上，浅色 3.60:1 / 深色更高，两端都成立。

### 2.4 表单控件边界

`--tjg-border-default: #e3e3e3` 白底仅 **1.28:1**，全仓 213–223 处引用。
它只能做**装饰分隔线**，不能承担**控件边界**（WCAG 1.4.11 要求 3:1）。
新增专用令牌而非改 `border-default`（改它会连带 200+ 处装饰线一起变脏）：

```
--tjg-border-control: #8b9491;   /* 浅色 3.11:1 */
--tjg-border-control: #6b7572;   /* 深色 3.68:1 */
```
约定：**只配白底，只用于 input / textarea / select / segmented / checkbox**。

### 2.5 不新增的令牌（重要）

- **`--tjg-focus-ring`**：`base.scss:11–15` 已有全局 `:focus-visible`。再造一个令牌 = 死令牌，
  且会诱导后来者以为"加了令牌就有焦点环"。
- **头像尺寸令牌**：`SingleDetails` 的 hero 头像是 `n-avatar :size="148"`，**prop 硬编码，不走 CSS**。
  把它抽成 CSS 变量属于"为了统一而统一"。

## 3. 未修清单（按优先级，附验收判据）

### P0-① 原生关窗可绕过「未保存」确认（已修，`SettingPage` 壳层）

**先纠正本报告早前的错误描述**：原文写成「改完无保存反馈、直接关窗静默丢失」——不准确。
实测代码后的事实是：

- 设置项本身走 `useSettingStore`（`persist: true`，由 `$subscribe` 驱动写入 localStorage），
  改一个开关就落一个盘，**不存在"未保存的设置值"**，所以"加保存条"是错药方。
- 账号页的资料（昵称/简介/性别/地区/生日）是 **`@blur` 自动保存 + toast 反馈**，本来就没有保存按钮。
- 项目**已有**完整的脏值体系：`useSettingsDirtyRegistry` + `SettingsContent` 的「未保存」状态条 +
  `handleClose()`（应用内 × 按钮）与 `onBeforeRouteLeave` 都会弹确认。

真正断掉的只有一处：

> `window.addEventListener('beforeunload')` 在 Tauri v2 里**拦不住原生关窗**。
> 点窗口红灯 / `Cmd+W` 走的是 Rust 侧 `WindowEvent::CloseRequested`，不会经过 `beforeunload`。
> 于是「未保存」确认在**唯一真正会丢东西的路径**上被完全绕过——而这条路正是用户最常用的。

修复：新增 `src/composables/settings/useSettingsNativeCloseGuard.ts`，在独立设置窗口上挂
`onCloseRequested`，两个时序点必须踩准：

1. **`event.preventDefault()` 必须在任何 `await` 之前同步调用**。handler 是异步的，一旦先 await，
   Tauri 已经放行关闭，再拦也来不及。
2. 确认关闭后走 **`destroy()` 而不是 `close()`**。`close()` 会再次触发 `CloseRequested`，
   把守卫重入一次（表现为"点两次才关掉"）。

单测 `useSettingsNativeCloseGuard.test.ts` 6 例，且已做**变异自证**：
把 `preventDefault()` 挪到 `await` 之后 → 用例失败；删掉 `destroy()` → 用例失败。

#### 遗留 → 已修（`cefddaec4`）
`account` 页的资料表单因是 blur 自动保存、不注册脏值，所以「改完昵称直接 `Cmd+W`」时
输入框还没失焦、写请求根本没发出，守卫读到的 `hasDirty()` 恒为 `false` 就放行了。

修法不是给它补脏状态（自动保存表单本来就没有"未保存"概念），而是引入**在飞写请求**这个维度：

- 新增 `src/composables/settings/settingsPendingWrites.ts`：模块级 `Set<Promise<boolean>>`。
  用模块级而非 pinia，因为关窗发生在窗口销毁路径上，此刻组件可能已卸载、store 可能已 teardown。
- `trackSettingsWrite` 把 rejection **归一成 `false`**——关窗路径上抛错会让窗口关不掉，比丢数据更糟。
- `flushSettingsWrites` 永不 reject，默认 **8s 超时**，且**循环 drain**：flush 期间 `blur()`
  可能链式触发多个字段的写请求，只快照一次会漏掉后登记的。
- 守卫新增 `hasPending` / `flushPending`；`SettingsPage` 抽出 `flushFormWrites()`
  （`activeElement.blur()` → `nextTick()` → `flushSettingsWrites()`），
  **原生关窗 / 切 tab / 点关闭三处复用**——否则「改完昵称直接点另一个 tab」走的是同一条丢数据路径。

**顺序不变量**：`flushPending()` 必须排在 `hasDirty()` 重判**之前**。
自动保存表单的脏状态要靠 blur 写成功才清掉，顺序颠倒会变成「刚保存完又弹确认框」。
这条已被「flush 期间才变脏 → 必须走 confirm」的用例锁死。

#### 已知限制（未修，非回归）
`flushSettingsWrites` 返回的 `failed` 目前被守卫忽略。极端情况：写请求失败 **且** 用户同时关窗——
`useAccountProfileForm` 的 catch 先回滚表单、再弹 toast，紧接着窗口就被 `destroy()`，提示看不到。
结果与修复前一致（都是丢一次编辑），不是回归。

收口方案（约 3 行，符号定位，不用行号免得烂）：
1. `settingsPendingWrites.flushSettingsWrites` 已经 `return { failed }`，只是调用方没接；
2. `useSettingsNativeCloseGuard` 的 `flushPending` 返回类型 `Promise<void>` → `Promise<{ failed?: number } | void>`，
   接住结果，`failed > 0` 时改走 `confirm` 分支而不是直接 `destroy()`；
3. `SettingsPage.flushFormWrites` 末尾 `return await flushSettingsWrites()` 把值透出来。

### P0-④ ~~删除好友的后果文案与实现不一致~~ —— **已作废（判断错误）**

原判断是「文案暗示只是移除关系，实际会退出会话」。读了实现后**不成立**：

- `MatrixFriendOperations.removeFriend()`（`src/services/matrix/friends/MatrixFriendOperations.ts:195`）

- 因此现有文案「确定要删除该好友吗？删除后聊天记录将保留。」（`locales/zh-CN/friend.json`
  → `detail.remove_confirm`）**是准确的**，不需要改文案。

真正值得讨论的是产品问题（不是缺陷）：删好友后 DM 会话仍留在列表里，而对方已不在好友列表，
详情面板也不再可达，用户没有清理入口。**要不要「删除好友时一并退出会话」是产品决策，不是 bug 修复**，
不该混进这次可达性收口。

### P0-③ 图标按钮缺可访问名（已抽查确认，待实施）
- `ActionBar.vue:51/58`：常驻置顶按钮，`<svg aria-hidden="true" class="... cursor-pointer">` 包在
  `n-popover` 的 trigger 里 —— **点击能开弹层，键盘永远到不了**。
- `MsgInputToolbar.vue:95/99`：输入框上/下箭头，同样是 `@click` 挂在 `aria-hidden` 的 `<svg>` 上。

- 验收：Playwright 里逐个 Tab 到，读到 `activeElement.tagName === 'BUTTON'` 且 ARIA 名非空。

## 5. 附录 B：作废方法（每条都真实发生过）

1. **拿截图取样色当源码事实**。屏幕有色彩配置转换；任何颜色结论必须回源码 `grep`。
2. **拿 `head` 截断的输出当全量**。得到"15 处"，实为 26 处。
3. **拿单行 grep 判断多行模板结构**。得到"18/6"，分母是假的。
4. **先造供应方再找消费方**。先设计令牌，再去找谁用——必然造出一批没人用的令牌。
   必须反过来：先列消费点，再决定令牌。
5. **用推断代替实测**。`getComputedStyle` 一遍能定的事，不要靠"应该会级联成…"。
6. **在不可聚焦元素上补焦点环**。CSS 写得再对也不会渲染，且会让"焦点覆盖率"指标虚高。
7. **并列不同分母的统计**。产出量差 10 倍的人放在同一张表比"谁错得多"，结论必然是反的。
8. **自产判据自行验收**。本轮所有错判都符合这条。
9. **把「产品上想改的」写成「代码里做错的」**。P0-④ 就是模板：先有"应该退出房间"的主张，
   再去读实现，读到 `removeFriend` 从不 leave room，说明**文案是对的、主张是新的**。
   判据：断言"文案与实现不一致"之前，必须先打开实现读那 20 行。
10. **把「没打开文件」当成「文件里没有」**。P0-① 第一版说"没有脏值守卫"，
    实际 `useSettingsDirtyRegistry` 已完整存在。数一遍比说一遍便宜。

## 6. 附录 C：三条纪律

1. **纪律一**：颜色/尺寸/对比度结论，必须带 `文件:行号` 或 `getComputedStyle` 输出，二者缺一不进报告。
2. **纪律二**：凡是自产的判据或数值，**不得由产出者单独验收**（"写判据的人不负责验判据"的特例）。
3. **纪律三**：可复现不是纪律，是**唯一能让争论停下来的机制**。争不出结果时，去做那个能一次定论的最小实验

#### 复用时发现的真缺陷：`v-clickable` 在 `<svg>` 上会抛错

`click()` 定义在 **`HTMLElement`** 上，`SVGElement` 继承的是 `Element`，**没有这个方法**。
指令原本直接 `el.click()`，且它挂在 `keydown` 里 —— 表现是
**「按 Enter 没反应 + 控制台 TypeError」**，比完全没有实现还难排查。

已改为能力探测，非 `HTMLElement` 走 `dispatchEvent(new MouseEvent('click', { bubbles: true }))` 兜底。
另外把元素类型从 `HTMLElement` 放宽到 `Element` 后暴露一个类型问题：**`Element` 的
`addEventListener` 没有 `keydown` 重载**（只有 `HTMLElement` 有），处理器必须按 `EventListener`
存、函数体内再窄化成 `KeyboardEvent`。

> 这是一条只靠 `vitest` 抓不到的错：682 个用例全绿时 `vue-tsc` 仍在报 TS2769。
> **绿灯 ≠ 类型安全**，两道门禁都得跑。

### 8.4 三个必须先知道的坑

1. **8 处是 `v-if="isWindows()"`**：`AvatarCropper:19`、`FileUploadModal:17`、`ChatModals:7`、
   `ChatMsgMultiChoose:32/133`、`LocationModal:19`、`definePlugins/index:18`、`RegisterEmailCodeModal:11`。
   **macOS 上根本不渲染** ⇒ 改完在这台机器上无法验证，只能靠单测；要真机验需 Windows。
   （佐证：`ChatModals.vue:5` 的 macOS 分支用的是独立组件 `MacCloseButton`，不是这个 svg。）
2. **`aria-hidden="true"` + `@click` 是全仓最普遍的矛盾写法**：ARIA 规范明确禁止
   `aria-hidden` 元素承载可聚焦内容或交互。所以 A 类不能"补个 tabindex 了事"——
   要么删 `aria-hidden` 改 `role="button"`，要么外面包 `<button>`。后者更好，还能顺手拿到原生键盘行为。
3. **7 处是误报，不要动**。`ActionList.vue:25/37/118/130/180/225/237` 的 `<svg>` 是**导航图标**，
   父 `<div>` 已经有 `role="button" tabindex="0" :aria-label :title @click @keydown.enter @keydown.space.prevent`。
   子元素上的 `@click="tipShow = false"` / `handleTipShow(item)` 只是"顺手把别处的提示条关掉"的副作用，
   **不是它自己的语义**。给它们补 `role="button"` 会让读屏在侧栏念出 7 个重复的「关闭」，
   而且 Tab 序列里凭空多出 7 个停靠点。正确处置是**保持 `aria-hidden` 不动**，或另行去掉那个冗余 `@click`。

> 这 7 处是怎么被误判的：上一版按 `@click` 的**文本形态**（`xxx = false`）反推元素语义，
> 于是把所有 `tipShow = false` 都算成了"关闭按钮"。**handler 文本不等于元素语义**，
> 必须看它挂在哪个节点、谁在管点击。
