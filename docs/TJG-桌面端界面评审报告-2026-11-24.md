# Tjg 桌面端界面评审报告（2026-11-24）

> 评审输入：6 张实机截图（消息列表 / 好友列表 / 房间卡片 / 空间空状态 / 加密会话 / 设置-账号）
> 评审方式：设计、体验、前端三方独立取证 → 交叉质证 → 以源码和实测为准
> 结论口径：**只认源码取值与 `getComputedStyle` 实测值，不认截图取样色和推断**

---

## 0. 一句话结论

截图里"看不清"的问题基本都不是"颜色选得不好看"，而是**同一个根因的多种表现**：
项目把**填充色**当**文字色**、把**装饰色**当**控件边界色**、把**不可聚焦元素**当**可交互元素**。
三类误用各有一批，本轮修掉了其中最贵的部分，其余列出验收判据待排期。

## 2. 修复明细（before → after，附判据）

### 2.1 左侧导航栏：未选中图标长期不达标

| | 值 | 对比度 |
|---|---|---|
| 改前 | `rgba(255,255,255,.78)` on `primary-500 #13987f` | **2.78:1** ✗ |
| 改后 | `rgba(255,255,255,.88)` on `primary-600 #0f7a66` | **3.9:1** ✓ |

判据 WCAG 1.4.11 非文本 3:1。这 5 个图标是屏幕上"存在时间最长、看得最多"的元素，
原方案却把最弱的一档给了它们。
顺带解决：白 pill 选中态 vs rail **5.26:1** ✓，选中图标 `primary-600` on 白 **5.26:1** ✓
（原方案是"白 18% 蒙层 pill + 白图标"，pill 与图标同色，选中态只靠一层几乎看不见的蒙层区分）。

**未动**：`--left-active-indicator-color` 保持白色——白 pill 下这条白指示条会隐形，
侧栏当前不渲染该指示条，改它属于"改没有消费方的东西"。

### 2.2 语义色：填充档被当文字档用

项目已有完整分档，但调用处普遍取了 `-500`：

| 令牌 | 值 | 白底对比度 | 允许用途 |
|---|---|---|---|
| `success-500` | `#52c41a` | 2.27 | **仅填充**（≥3:1 都不够，只能做面积块） |
| `success-600` | `#389e0d` | 3.46 | 仅图形（圆点、图标） |
| `success-700` | `#237804` | 5.59 | **文字** |
| `danger-500` | `#ff4d4f` | 3.27 | 仅填充 |
| `danger-700` | `#a8071a` | 7.75 | **文字** |

改动：
- `--tjg-status-online`：`#52c41a` → `var(--tjg-color-success-600)`。全仓 15 处引用**全部**是
  `background-color` / 圆点填充 / 光晕，无一处当文字 → 提升到 3.46 安全。
- 三处文字用途改 `-700`：`RobotCard` 在线文字、`FedStatusBadge` 在线标签、`SingleDetails` 删除好友文字。
- 房间卡片加密群聊左边条：`success-500` → `success-700`。这条 3px 竖条是**唯一**信息载体
  （卡片上没有"加密"字样），2.27:1 等于没写。

### 2.3 来电横幅：焦点环写在按钮自己身上

两个圆形按钮原本 `focus-visible:ring-2 ring-[--tjg-color-danger-400]`，
ring 颜色（`danger-400`）和按钮底色（`danger-500`）是同一色相相邻档 → **2.56:1**；
接听键 `ring-primary-300` on `primary-500` → **1.99:1**。
即"键盘用户看不到焦点"。

改法不是换更亮的 ring，而是**删掉这段压制，交回全局规则**
（`base.scss:11–15`：`outline: 2px solid primary-500; outline-offset: 2px`）——
outline 带 2px 偏移，落在横幅底色 `surface-panel` 上，浅色 3.60:1 / 深色更高，两端都成立。

### 2.4 表单控件边界

`--tjg-border-default: #e3e3e3` 白底仅 **1.28:1**，全仓 213–223 处引用。
它只能做**装饰分隔线**，不能承担**控件边界**（WCAG 1.4.11 要求 3:1）。
新增专用令牌而非改 `border-default`（改它会连带 200+ 处装饰线一起变脏）：

```
--tjg-border-control: #8b9491;   /* 浅色 3.11:1 */
--tjg-border-control: #6b7572;   /* 深色 3.68:1 */
```
约定：**只配白底，只用于 input / textarea / select / segmented / checkbox**。

### 2.5 不新增的令牌（重要）

- **`--tjg-focus-ring`**：`base.scss:11–15` 已有全局 `:focus-visible`。再造一个令牌 = 死令牌，
  且会诱导后来者以为"加了令牌就有焦点环"。
- **头像尺寸令牌**：`SingleDetails` 的 hero 头像是 `n-avatar :size="148"`，**prop 硬编码，不走 CSS**。
  把它抽成 CSS 变量属于"为了统一而统一"。

## 3. 未修清单（按优先级，附验收判据）

### P0-① 设置页改完无保存反馈，直接关窗会静默丢失
截图"设置-账号"暴露：改完选项没有任何"已保存"信号，也没有未保存提示。
- 验收：改动后出现保存条（[保存]/[重置]）；有未保存改动时关窗弹确认；
  **必须用 Tauri v2 `getCurrentWindow().onCloseRequested`**，`beforeunload` 挡不住原生关窗。
- 涉及：`src/views/settingsWindow/`、`src-tauri` 窗口事件。

### P0-③ 图标按钮缺可访问名
一批"只有图标、无文字"的按钮没有 `aria-label`，读屏念不出来。
- 方案：新建 `<IconButton>`，**`aria-label` 设为必填 prop**（类型层面拦住），
  ESLint 禁裸 `<button>` 带 `<svg>` 子节点。
- 验收：`interactive_aria_hidden_count = 0`。

### P0-④ 删除好友的后果文案与实现不一致
当前文案暗示"只是移除关系"，实际会退出会话、聊天记录不可见。
- 方案（选项 b，退出房间）：动作名改「删除好友并退出聊天」；
  弹窗正文：「删除好友并退出会话后，你将无法查看这个会话的聊天记录。如需保留个别重要消息，请先右键消息导出。」
  按钮 `[取消]` / `[删除并退出]`；默认焦点在取消，**Enter 不得确认**。

### P1 可点击但不可聚焦（9 处）
`@click` 挂在 `<svg aria-hidden="true">` 上。这类元素**不进 Tab 序列**，`role` 也没有，
所以给它补 `:focus-visible` 环是**永远不渲染的死 CSS**。
- 正确修法是结构性的：包一层 `<button type="button" :aria-label>`。
- 验收：Playwright 里逐个 Tab 到，读到 `activeElement.tagName === 'BUTTON'` 且 ARIA 名非空。
- 已知点位（举部分）：`RobotChatInputPanel.vue:175`、`InfoEdit.vue:112`、
  `FooterToolbar.vue:176`、`MsgInputToolbar.vue:95/99`、`ActionBar.vue:51/58`、`MobileSessionList.vue:108/115`。

### P1 单聊详情页 hero 区（6 项批量）
`src/components/rightBox/SingleDetails.vue`
- `<n-avatar :size="148">` → `72`（对齐设计稿，当前 148 为 prop 硬编码）
- 头像描边 `3px` → `2px`；`shadow-lg` → `shadow-sm`
- hero 区 `gap: 14` → `10`
- `AccountStatusBadge` 从 `__name-row` 移出，与 `friendStatusLabel` + `lastSeenText` 合成独立状态行
- `@dblclick` 打开头像 → 单击 + `tabindex="0"` + Enter
- 验收：hero 总高 ≤ 272px；昵称单行不折行；状态行只有一行。

### P1 发送按钮禁用态在浅色渐变上近乎不可见
`MsgInputToolbar.vue:73-85` 按钮**存在**（不是缺失），仅禁用态样式在浅色渐变上糊掉。
- 验收：禁用态与输入区底色 ≥ 3:1，且保留"这是按钮"的边界感。

### P2 `outline-none` 存量（14 文件 26 处）
需分类，不能一刀切：
- **已合规**（自带 `focus-visible:ring-*`）：9 处，不动。
- **`<svg>` 上且元素本身不可聚焦**：抑制是 no-op，真实缺陷归入上面 P1"不可聚焦"，不在此重复计。
- 本轮已修 2 处（来电横幅）。

### P2 侧栏在线点与 rail 配色过近
`LeftAvatar.vue:15` 在线点 `success-600` on rail `primary-600` ≈ **1.52:1**，周边描边同为 rail 色。
纯装饰性状态点，不阻塞；若要修，把描边改成 `--tjg-surface-panel` 让点与 rail 分离。

## 5. 附录 B：作废方法（每条都真实发生过）

1. **拿截图取样色当源码事实**。屏幕有色彩配置转换；任何颜色结论必须回源码 `grep`。
2. **拿 `head` 截断的输出当全量**。得到"15 处"，实为 26 处。
3. **拿单行 grep 判断多行模板结构**。得到"18/6"，分母是假的。
4. **先造供应方再找消费方**。先设计令牌，再去找谁用——必然造出一批没人用的令牌。
   必须反过来：先列消费点，再决定令牌。
5. **用推断代替实测**。`getComputedStyle` 一遍能定的事，不要靠"应该会级联成…"。
6. **在不可聚焦元素上补焦点环**。CSS 写得再对也不会渲染，且会让"焦点覆盖率"指标虚高。
7. **并列不同分母的统计**。产出量差 10 倍的人放在同一张表比"谁错得多"，结论必然是反的。
8. **自产判据自行验收**。本轮所有错判都符合这条。

## 6. 附录 C：三条纪律

1. **纪律一**：颜色/尺寸/对比度结论，必须带 `文件:行号` 或 `getComputedStyle` 输出，二者缺一不进报告。
2. **纪律二**：凡是自产的判据或数值，**不得由产出者单独验收**（"写判据的人不负责验判据"的特例）。
3. **纪律三**：可复现不是纪律，是**唯一能让争论停下来的机制**。争不出结果时，去做那个能一次定论的最小实验
   （本轮 iOS 字体问题就是靠 Safari 三行 A/B/C 一次定案的）。
