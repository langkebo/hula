## 一、Goal（目标）

把主方案登记的两项安全纵深问题，从「报告结论」转化为**分优先级、逐项可验证、可回滚**的落地任务：

1. **SC-05（capabilities 最小化）**：对 `src-tauri/capabilities/{default,desktop,mobile}.json` 的全量权限做「保留 / 收紧 / 删除」三分，逐项以「前端/Rust 调用点证据」判定，按 P0 → P3 分批收敛；每收敛一项即跑一次全平台冒烟，确保运行期能力不回归。
2. **SC-07（`HttpClient` host allowlist）**：为 `src/utils/HttpClient.ts` 增加**配置化的 host 白名单**（dev/prod 分环境、未知 host 默认拒绝并记录日志），杜绝任意 host 出网；以纯函数 + 单测 TDD 驱动，接入点收敛到 `fetchWithTimeout` 单一咽喉。

**收益**：缩小注入后的可调用面（capabilities 命令级授权 + http 出网 host 级授权），补齐 Tauri 三层控制面（capabilities / CSP / assetProtocol）中的**真正闸门**层；同时不破坏「永不白屏」乐观渲染（ADR-003）与既有同步/上传/媒体链路。

## 二、非目标（Out of Scope）

- **不改业务逻辑**：SC-05 只动 capabilities JSON；SC-07 只在 `HttpClient` 咽喉处加门，不改任何调用点语义。
- **不动 `matrix-js-sdk`**：SDK 直连 `@/services/matrix/network/runtimeFetch` 的请求（内部走 `MatrixHttpClient` / SlidingSync）**不在 SC-07 范围**——SC-07 只覆盖 `@/utils/HttpClient` 这一独立出口（见 §6.2）。
- **不改 CSP 与 `assetProtocol.scope`**：属同一纵深但在本次仅登记；CSP 若需同步收紧，列为 §十一 决策项，不默认执行。
- **不改 `withGlobalTauri`**：`tauri.conf.json` `"withGlobalTauri": true` 会暴露 `window.__TAURI__`，放大注入可调用面；属独立风险，列为 §十一 决策项。
- **不做大规模权限重构**：不引入新的权限抽象层，不重写 capabilities 生成流程。

两条线**互不依赖**，可分别推进、分别验收。建议先做 SC-07（纯代码 + 单测，回归可控、可离线验证），再做 SC-05（配置类、依赖运行期冒烟）。


## 六、现状取证（只读，本专项事实基线）

### 6.1 SC-05：三层控制面与权限现状

Tauri v2 的命令级授权有**三层**，SC-05 只针对**第一层**：

| 层 | 载体 | 作用 | 本次是否收敛 |
| :--- | :--- | :--- | :--- |
| ① capabilities | `src-tauri/capabilities/{default,desktop,mobile}.json` | **命令级授权**；`plugin-http`/`fetch` 经 Rust 侧出网，**不受 CSP 约束**，是真正的出网闸门 | **是（SC-05）** |
| ② CSP | `tauri.conf.json` `app.security.csp` | WebView 内 `connect-src`/`img-src`/`media-src`/`frame-src`；对 Rust 侧 http 无效 | 否（仅登记，§十一） |
| ③ assetProtocol | `tauri.conf.json` `app.security.assetProtocol.scope` | `convertFileSrc` 本地资源作用域（`$APPDATA/**`、`$RESOURCE/**`、`$CACHE/**`、`$TEMP/**`） | 否（仅登记） |

**capabilities 文件与窗口绑定**（取证）：

- `default.json`：`identifier="default-capability"`，`platforms=["macOS","windows","linux"]`，`windows=["*"]`，**101 项 permissions**（94 字符串 + 7 scope 对象；SC05-P0-1 删除 `shell:allow-execute` 后实测）。
- `desktop.json`：`identifier="desktop-capability"`，`platforms=["macOS","windows","linux"]`，`windows=["*"]`，13 项（updater / global-shortcut / 少量 window）。
- `mobile.json`：`identifier="mobile-capability"`，`platforms=["iOS","android"]`，`windows=["*"]`，含 `hula:default`（scope）等；`fs` scope 已收窄为 `$APPDATA/tjg/**` 等，**是 `default.json` 的收窄样板**。
- 三者在 `tauri.conf.json` 通过 `app.security.capabilities = ["default-capability","mobile-capability","desktop-capability"]` 激活。

**权限三分（保留 / 收紧 / 删除）**——按风险优先级排列，`文件:行` 为 `default.json`（除标注外）：

| 优先级 | 权限 | 现状 | 结论 | 依据 |

> **`:**` 变体说明**：前端 `hostAllowlist` 匹配时**剥离端口**（`stripPort`），规则与端口无关；capabilities 侧补 `:**` 变体以覆盖同一 host 的任意端口，使两端语义对齐。裸 host 条目与 `:**` 条目在 Tauri `http` scope 语义下分别匹配「默认端口」与「任意端口」。

**homeserver 缺口登记（裁决：静态 + loopback）**：capabilities 侧**不含**生产 homeserver host（`VITE_HOMESERVER_URL` 的 host 随部署环境变化，无法静态枚举）。前端 `httpAllowlistConfig.ts` 通过 `homeserverEntry(VITE_HOMESERVER_URL)` **自动追加**该 host 到 allowlist，故前端侧不遗漏；capabilities 侧生产 homeserver 由**本地/dev 的 loopback 条目**覆盖。影响面：
- **本地/dev**：homeserver = `http://localhost:8008`（默认）→ 命中 loopback 条目，nativeFetch 可用，无缺口。
- **生产**：homeserver 为真实域名 → nativeFetch 因 capabilities 无该 host 而被拒 → `runtimeFetch` 回退浏览器 `fetch`；此时受 CSP `connect-src` 约束（**当前各平台 CSP 均不含生产 homeserver**，见 §6.1/取证）→ 需在生产部署时为 CSP 补该 host（属 SC-05 CSP 面，D7 决策项，独立处理）。
