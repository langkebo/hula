## 2. 测试方法

### 2.1 三维测试框架

每条路由接受三个维度的探针：

| 维度 | 探针方式 | 判定逻辑 |
| :--- | :--- | :--- |
| **注册验证** | 以声明 Method + 占位路径参数请求后端 | 404 + `M_UNRECOGNIZED` → 未注册；401/403/400/404(`M_NOT_FOUND`)/405 → 已注册 |
| **可用性** | 以声明 Method + admin token 请求（写方法附带 `{}` body） | 记录 HTTP 状态码、响应耗时、errcode |
| **安全性** | (a) 无 Authorization 头请求；(b) 非管理员 token 访问 admin 路由 | 受保护路由返回 2xx → AUTH_BYPASS；admin 路由返回 2xx → PRIVILEGE_ESCALATION |

### 2.2 路径参数替换

路径中的 `{param}` 占位符按语义替换为测试值（如 `{roomId}` → `!testroom:matrix.test`、`{userId}` → `@tjgtestuser:matrix.test`、`{eventId}` → `$testevent:matrix.test`），未匹配参数回退为 `"test"`。

### 2.3 限流规避

本轮测试临时调高应用层限流（default 2000/s burst 5000）和 NGINX 限流（12000 r/m burst 500），使 429 从 869 条降至 16 条（仅 login/register 等专用限流端点触发）。剩余 16 条 429 来自 login（5/s）和 register（50/s）端点的专用限流规则。
