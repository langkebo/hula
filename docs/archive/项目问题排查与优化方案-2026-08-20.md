## 1. 问题清单（按严重度）

### 🔴 P0 · 生产功能损坏（`import type` 默认导出致命陷阱复发）

> 陷阱机理（见项目 memory）：SFC 以 `import type X from './Foo.vue'` 导入时，type-only import 在构建时被**擦除**，模板中 `<X>` 标签运行期为 `undefined` → 组件不渲染（降级为未知 HTML 元素，ref 拿不到实例，事件/生命周期全失效）。正确写法：去掉 `type`；确实只要类型时用 `ref<InstanceType<typeof import('./Foo.vue')>>`。

#### P0-1 · 主窗口会话列表不渲染
- **位置**：`src/views/homeWindow/message/index.vue`
  - `:42` `import type RoomSessionList from '@/components/workbench/RoomSessionList.vue'`
  - `:20` 模板 `<RoomSessionList ref="sessionListRef" :session-list="filteredSessionList" ... />`
- **根因**：`RoomSessionList` 以 `import type` 导入，模板却当组件用。无全局注册（`main.ts` 仅 `createApp(App)`，无 `app.component`）。
- **影响**：消息主窗口会话列表区域可能为空/不可用（核心路径）。
- **修复**：`:42` 去掉 `type` → `import RoomSessionList from '@/components/workbench/RoomSessionList.vue'`（零风险，与 `RoomSessionList.test.ts` 现有 `RecycleScroller` mock 兼容）。
- **验证（TDD）**：先写回归用例断言 `findComponent(RoomSessionList)` 存在 / `sessionListRef` 非 `HTMLUnknownElement`；修复后转绿。

#### P0-2 · 截图工具条 / 放大镜不渲染
- **位置**：`src/components/common/Screenshot/ScreenshotRoot.vue`
  - `:57-58` `import type ScreenshotMagnifier` / `import type ScreenshotToolbar`
  - `:7` `<ScreenshotMagnifier ref="magnifierRef">`、`:27` `<ScreenshotToolbar ref="toolbarRef">`
- **根因**：同上，type-only 导入 + 模板用组件。
- **影响**：截图功能的放大镜与工具条不显示，截图交互受损。
- **修复**：两行去掉 `type`，改为正常导入。
- **验证**：补 `ScreenshotRoot` 渲染测试，断言 `findComponent(ScreenshotMagnifier)` 存在。

> ✅ 排除误改：`useCallState.ts:6` `import type ActionBar` 仅用于 `:60` `useTemplateRef<typeof ActionBar>('actionBarRef')` 的**类型注解**（运行时不取 `ActionBar` 值），且 `ActionBar` 组件在 `callWindow` 中独立正常渲染 → **安全**。

## 3. 防复发建议
1. **加 CI 规则**：禁止 `import type X from '*.vue'` 后在同一 SFC 模板使用 `<X>`（或强制统一用 `ref<InstanceType<typeof import('*.vue')>>` 仅类型）。可落为 ESLint 自定义规则或 vue-tsc 插件检查。
2. **孤儿函数检测**：CI 跑 `ts-prune`（或自研脚本）对零引用的 `export const 函数` 报警，防止死代码累积（本次 `build*`/`createMenuActionHandler` 即此类）。
3. **空桩预警**：对 `TODO(P0-*)` 与"永远返回空/空数组"的 `load` 类函数做定期审查，纳入迭代 backlog。
