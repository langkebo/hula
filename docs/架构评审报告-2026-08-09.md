## 二、维度详解

### 1. 技术栈健康度 — 17/20 ⭐⭐⭐⭐

**亮点：**
- 全链路最新稳定版：Vue 3.5.40 / Vite 8.2 / TypeScript 6.0.3 / Pinia 3.0 / Vitest 4.1 / Playwright 1.62 / Biome 2.5。
- `tsconfig` 开启 `strict: true` + `noImplicitAny`，路径别名 `~/* @/* #/*` 规划清晰。
- pnpm only-allow 强制 + `pnpm.overrides` 23 条统一收敛安全漏洞版本（postcss/ws/js-yaml/mermaid 等），`meta/sdk-pin.json` 锁定 SDK commit，依赖治理意识很强。

**扣分项：**
- ⚠️ **23 条 pnpm overrides 是"治理能力强"同时也是"债务信号"**——说明传递依赖健康状况差，需每季度复核哪些可以下线。
- ⚠️ `matrix-js-sdk: link:../matrix-js-sdk` 本地链接协议，CI 靠 sdk-pin 缓解，但本地开发仍存在"SDK 漂移"风险（改 SDK 忘提交即不可复现）。
- 双 UI 库（Naive UI + Vant）+ 双图标方案（SVG Sprite + Iconify）双轨并行，属有意的渐进策略，可接受，但需防止继续扩张。

### 2. 架构设计模式 — 15/20 ⭐⭐⭐

**亮点：**
- 服务层按 Matrix 子域划分清晰：`auth / room / messaging / media / user / friends / notifications / crypto / admin`，组件不直连 SDK（`adminService` facade 模式），`check:sdk-boundary` 脚本用 CI 强制边界。
- **Matrix SDK 运行在 Web Worker**（`matrixSdk.worker.ts` 850 行 + `MatrixWorkerHost` 285 行桥接），主线程 <50ms 约束有架构级保障。
- 路由 67 处全部动态 import 懒加载，`authGuard` 独立成文件。
- Pinia 按域分 5 组 54 个 store，职责边界清楚。

**扣分项（核心问题）：**
- 🔴 **上帝服务**：`MatrixSpaceService` 1138 行、`MatrixCryptoService` 1096 行、`SynapseRustExtensionsService` 1069 行、`AdminFacadeService` 1062 行——单文件超千行，职责过载，测试与变更影响面大。
- 🔴 **类型逃逸 528 处 `as any`**：`noImplicitAny` 开着但 `as any` 泛滥，biome `noExplicitAny` 仅 warn——类型安全的堤坝有 528 个决口，服务边界尤其危险。
- 🟡 **巨型 composable / store**：`useChatMain` 942 行；chat 域 store `group.ts` 732 / `contacts.ts` 716 / `room.ts` 702 行，已接近"上帝 store"。
- 🟡 **大组件**：`ScreenshotRoot.vue` 912 行、`ChatMain.vue` 907 行、`ModelManagement.vue` 894 行，单一职责被稀释。

### 3. 工程化成熟度 — 18/20 ⭐⭐⭐⭐⭐（全场最佳）

- **CI 矩阵豪华**：13 条 workflow——quality-gate（Biome + 类型 + 测试门禁）、codeql、dependency-review、performance、security-performance、sdk-check、style-check、release-validation 等，且 action 全部 SHA 钉版 + step-security/harden-runner 加固。
- **自研质量脚本体系**（罕见亮点）：`check:sdk-boundary`（架构边界）、`check:ratchet`（债务棘轮只减不增）、`check:v-html`、`quality:no-raw-fetch`、`check:doc-coverage`、`check:sdk-types`、`verify:sdk-pin`——把架构规则变成了可执行的 CI 检查。
- 提交链完整：Husky + lint-staged + commitlint + cz-git，scope-enum 约束。
- 测试密度高：610 个单测文件（约 6800 用例），Vitest + @vue/test-utils + msw + happy-dom/jsdom 双环境，Playwright 15 个 E2E（含移动端 project 与 axe-core a11y 基线）。
- 有 knip（死代码检测）、Storybook 10、bundle metrics、lighthouse budget。

**扣分项：**
- 🟡 15 个长期失败测试（4 个套件）挂着未修——测试信用会被侵蚀，团队容易对红 CI 脱敏。
- 🟡 Biome 多条规则仅 warn（`noExplicitAny` 等），门禁力度可再收紧。

### 4. 性能与可维护性 — 15/20 ⭐⭐⭐⭐

**亮点：**
- SDK 入 Worker + `MatrixRequestDeduper` 请求去重 + `MatrixRateLimitInterceptor` 限流拦截 + `MatrixCacheManager` 缓存管理，性能设计体系化。
- `vue-virtual-scroller` 长列表、生产构建 esbuild drop console、`vite-plugin-compression`、bundle 指标上报脚本。
- 技术债指标优秀：全库仅 6 处 TODO、6 处 console.log、7 处 ts-ignore、mitt 事件总线仅 1 处——说明 ratchet 机制真的在工作。

**扣分项：**
- 🔴 **已知 a11y 对比度违规未修**：暗色 `--tjg-text-tertiary` 3.65:1、`--tjg-text-quaternary` 最低 1.8:1、发送气泡 ~2.6:1，均不达 WCAG AA 4.5:1——axe 基线已建但问题未闭环。
- 🟡 千行级文件的可维护性风险（见维度 2）。
- 🟡 i18n 仅 en / zh-CN 双语，若规划出海需提前评估 rtl 与复数规则。

## 四、一句话总结

> 这是一个**工程化水准远超同体量开源项目**的前端：CI 门禁、棘轮脚本、Worker 隔离都是教科书级实践。当前的瓶颈不在"工具"而在"熵"——千行上帝类、528 处 `as any`、挂着不修的失败测试，都是熵增信号。按 P0 → P1 顺序还债三个月，综合评分可上 90（⭐⭐⭐⭐⭐）。
