### 4.2 风险分析

1. **构建目标与最低系统版本错配（核心风险）**：构建目标为 `safari15`，而 iOS 13/14 的 WKWebView 对应 Safari 13/14，**低于构建目标**。esbuild 不会为 `safari13` 降级，可能产出 iOS 13/14 不支持的语法。
2. **运行时 API 无降级**：因无 `core-js`/特性检测，`structuredClone`（Safari 15.4+）、`Array.prototype.at`（Safari 15.4+）等在旧 WKWebView 直接 `undefined is not a function`（对应 CP-03）。
3. **`crypto.subtle` 依赖安全上下文**：非安全上下文下不可用，可能直接抛错致 VoIP/本地加密失效（对应 CP-02，属 P2-2 范畴）。
4. **Android minSdk 26** 对应 WebView（Chrome 版本随系统升级）较新，风险低于 iOS 旧版本。

**结论**：本项目的**实际运行面下限约为 Safari 15**，但声明下限为 iOS 13——即「声明支持 iOS 13，实际只在 iOS 15+ 可靠」。

### 4.3 二选一建议（本轮不改配置）

| 方案 | 动作 | 优点 | 代价 |
| :--- | :--- | :--- | :--- |
| **(a) 抬下限（推荐，短期）** | `minimumSystemVersion` 13.0 → **15.0**，与 `build.target` 对齐 | 零运行时改动，消除错配，最省事 | 缩小设备覆盖（放弃 iOS 13/14） |
| **(b) 降目标（长期）** | `build.target` 增补 `safari13`、`tsconfig` 相应下调，并补运行时 polyfill/特性检测 | 保留 iOS 13 覆盖 | 需引入 `core-js` 或逐点特性检测；引入体积与复杂度 |

**建议路径**：短期取 (a)（与既有 `build.target` 严格一致、零运行时风险）；若产品明确要求覆盖 iOS 13/14，再以 (b) + **P2-2 现代 API 降级**专项联合推进（特性检测 `crypto.subtle`/`structuredClone`/`Array.at`）。
