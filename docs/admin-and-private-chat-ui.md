## 1. 管理员后台界面

### 1.1 入口与权限控制

#### 1.1.1 入口位置

**PC 端**:
- 主界面左侧导航栏底部，设置图标下方
- 使用 🔧 扳手图标（灰色，不显眼）
- 仅当用户角色为 `admin` 时显示
- 点击后跳转至 `/admin` 路由

**移动端**:
- 管理后台在移动端以**只读视图**为主（见 §3.1 的断点规则）：可查看列表与详情，
  写操作（删除、封禁、改角色）收进二级页并需二次确认。
- 入口位置：`我的 → 设置 → 管理后台`，仅管理员可见；非管理员不渲染该项。


#### 1.1.2 权限判断

```typescript
// 权限检查逻辑
const isAdmin = computed(() => {
  const userInfo = currentUserStore.getCurrentUserInfo()
  return userInfo?.role === 'admin' || userInfo?.is_admin === true
})
```

**非管理员用户**:
- 完全不显示管理员入口
- 直接访问 `/admin` 路由时重定向到首页
- 显示 Toast: "您没有权限访问此页面"

### 1.4 状态设计规范

后台每个数据视图都必须显式定义四种状态。**只画「有数据」的界面是这版文档最大的缺口** ——
真实使用中，管理员看到空列表或报错的次数远多于看到满屏数据。

#### 1.4.1 加载中

| 场景 | 呈现 | 约束 |
| --- | --- | --- |
| 首屏 / 切模块 | **骨架屏**，形状与目标表格一致（行高 48px，保留 5 行占位） | 不用全屏 Spinner：会让布局左右跳动 |
| 分页加载 | 表格底部内联 24px 高 loading 条 | 不遮罩已有行，允许继续滚动查看 |
| 详情抽屉 | 抽屉先滑出，内部骨架 | **抽屉不要等数据到了才打开**，否则点击像没反应 |
| 操作提交 | 按钮进入 `loading` 态并禁用 | 按钮宽度不变（避免布局抖动），文字可换成「处理中…」 |

骨架屏用 `--tjg-bg-secondary` 打底，`--tjg-border-default` 描边，不加动画之外的装饰。

#### 1.4.2 空态

空态必须回答两件事：**为什么空**、**我能做什么**。

| 空态类型 | 标题 | 说明 | 操作 |
| --- | --- | --- | --- |
| 无数据（首次） | 还没有用户 | 创建第一个用户或等待注册 | 主按钮「邀请用户」 |
| 筛选无结果 | 没有匹配的结果 | 试试放宽筛选条件 | 次按钮「清除筛选」 |
| 搜索无结果 | 找不到「{关键词}」 | 支持按用户 ID / 昵称 / 邮箱搜索 | 次按钮「清除搜索」 |
| 权限受限 | 无权查看 | 需要管理员权限 | 无操作 |

**禁止**用「暂无数据」四个字打发——它不告诉用户下一步。

空态插图尺寸 **120×120**，垂直居中于内容区，文案宽度限制 **360px**。

#### 1.4.3 错误态

| 类型 | 呈现 | 恢复路径 |
| --- | --- | --- |
| 整页请求失败 | 内容区居中：图标 + 「加载失败」+ 错误摘要 + 「重试」 | 重试按钮必须真的重新请求 |
| 局部失败（抽屉/卡片） | 该区域内联错误条 | 不整页重载 |
| 操作失败 | Toast（3s 自动消失）+ 按钮恢复可点 | 危险操作失败要保留用户已填内容 |
| 网络断开 | 顶部常驻条「网络已断开，正在重连」 | 恢复后自动消失，不弹窗 |

错误摘要**不要直接抛后端原文**（例如 `ApiError: 500`），映射成人话再显示；
原始错误进日志。

#### 1.4.4 危险操作的二次确认

删除用户 / 删除房间 / 封禁 / 批量操作，统一走确认弹窗：

```
┌──────────────────────────────────────┐
│  删除用户 @alice:server.com？          │
│                                      │
│  该操作不可撤销。她的所有消息将标记为   │
│  已删除，但不会从数据库物理清除。       │
│                                      │
│  [取消]              [确认删除]        │
└──────────────────────────────────────┘
```

- 确认按钮用 `--tjg-color-danger-500` 实心，**不用**主品牌色
- 确认文案写清**后果与不可逆性**，不写「确定要执行此操作吗」
- 批量操作要显示**影响数量**（「将删除 12 个用户」）
- 焦点默认落在「取消」上，防误触回车

### 2.3 阅后即焚功能

#### 2.3.1 发送方视角

**发送界面**:
- 开启阅后即焚后，消息气泡右上角显示 🔥 火焰图标
- 消息底部显示倒计时（发送后，时长可选 1/5/30 分钟）:
  ```
  ┌─────────────────────────────┐
  │  这是一条阅后即焚消息        │
  │                             │
  │  🔥 将在对方阅读后销毁       │
  └─────────────────────────────┘
  ```

**已阅读状态**:
- 对方阅读后，消息变灰 + "将在 N 分钟后销毁" 文案（N = 房间设置的时长）
- 倒计时进度条（底部细条，红色）

**销毁后**:
- 本地倒计时结束时，消息替换为 "🔥 消息已销毁" 占位（半透明 + 斜体 + 灰色）
- ⚠️ 后端 sweep 只把行标记为 processed，**不向前端推送事件**；移除动作由本地倒计时完成
- 两条清理路径的差异与影响见 §2.3.5

#### 2.3.2 接收方视角

**未阅读**:
- 消息气泡显示 🔥 图标
- 提示: "阅后即焚消息 — 阅读后将自动销毁"

**阅读时**:
- 首次进入视口时触发阅读确认
- 显示倒计时: "此消息将在 N 分钟后销毁"（N 取自房间设置：1/5/30）

**销毁动画**:
- 渐隐效果（300ms）
- 火焰特效（可选）
- 最终显示: "🔥 消息已销毁"

#### 2.3.4 时长与状态矩阵

**可选时长**（房间级，全局统一三档）：

| 档位 | 值 | 适用场景 |
| --- | --- | --- |
| 短 | 1 分钟 | 一次性凭证、验证码式消息 |
| 中（默认） | 5 分钟 | 常规私密对话 |
| 长 | 30 分钟 | 需要回看但不想留存的资料 |

超过 30 分钟的值会被服务端拒绝（`MAX_BURN_AFTER_MS`），客户端不应提供更长选项。

**状态机**（单条消息）：

```
      发送              对方 m.read 回执            本地倒计时归零
  ─────────► pending ──────────────────► burning ──────────────► removed
               │                            │
               │ 房间关闭焚毁                │ 用户切换会话
               ▼                            ▼
            (不进入倒计时)              (计时继续，与视图无关)
```

**要点**：

- `pending`：气泡显示 🔥 + 「阅读后自动销毁」，**不显示倒计时**（尚未起算）。
- `burning`：显示进度条与剩余时间；数字每秒刷新，进度条按 1s 线性递减即可
  （30 分钟档不必做非线性缓动，反而会让人误判剩余时间）。
- `removed`：从列表移除（不是留占位）。留占位会让「已焚毁」的消息仍占一屏高度，
  长会话里连续多条焚毁会形成大片空洞。
- **切换会话不暂停计时**：到期判断以绝对时间为准，不依赖组件是否挂载。

#### 2.3.5 实现状态与已知限制（2026-11-21 审计）

本节记录**代码实际行为**，与上文的设计意图可能有差异，以实现为准。

**已落地的链路**（非界面伪装）：

| 环节 | 实现位置 | 行为 |
| --- | --- | --- |
| 发送标记 | `messageContentBuilder.ts` | 内容写入 `m.burn_after_read = { expires_in }` |
| 服务端登记 | `synapse-rust` `burn_after_read_service/schedule` | **per-user** 记录 `delete_ts`（每人一行，不是房间级） |
| 自动调度 | SDK `burn-after-read` 收到含 `expires_in` 的消息时调 `scheduleBurn` | 客户端无需手动触发 |
| 阅读上报 | `BurnMessage.vue` 进入视口 → `markMessageRead` | 成功后 `isBurning = true`，启动倒计时 |
| 发送方感知 | 后端 `MessageRead` → `BURN_MESSAGE_READ` → `updateMsg({ isBurning: true })` | 发送方也看到倒计时 |
| 本地到期 | `BurnMessage.completeBurn()` | `isBurned = true`，渲染「已销毁」占位 |
| 服务端到期 | `sweep.process_expired_burns` | **只标记 processed，不推送**（前端收不到事件）|
| 后台清扫 | `start_burn_processor` | 定时扫过期行，标记 processed，失败重试（上限 5 次转 dead letter） |

**时长口径**：仅支持 **1 / 5 / 30 分钟**三档（前端 `BURN_DURATION_VALUES`，
后端 `MAX_BURN_AFTER_MS = 30 分钟`；超出上限会被服务端拒绝）。

**已知限制（必须知道）**：

1. **「焚毁」是本地遮罩，不是物理删除。**
   服务端**不 redact 房间事件**——因为房间事件是所有成员共享的，一个读者到期就 redact 等于
   「一人已读、全员丢消息」。物理删除交给 retention 策略（房间级）。
   代码注释原文见 `MatrixBurnAfterReadService.ts` 的「遮罩语义」说明。

2. ~~两条清理路径行为不一致。~~ **已统一（2026-11-21）。**
   原状：本地倒计时结束只置 `isBurned`（占位留痕），服务端 sweep 才删。
   现实现：`BurnMessage.completeBurn()` 在到期时**直接 `chatStore.deleteMsg`**，
   接收端在本地时间到达即移除消息。

   ⚠️ 这里刻意**不走 SDK 的 `MessageBurned` 事件**：它要 `/redact` 成功才 emit，
   而 `can_redact_event` 只对「作者本人（v11+）」或「power >= 50」放行 ——
   接收方是普通成员必然 403，事件永不触发。**本地倒计时是接收端唯一可靠的到期信号。**

3. ~~重新加载可能恢复。~~ **已修复（2026-11-21）。**
   原状：客户端没有持久化「已焚毁黑名单」，消息列表也不按 pending 过滤，
   重进会话 / 重新 sync 后到期消息会复活。
   现实现：`src/utils/burnedMessages.ts` 把已焚毁的事件 ID 落到
   `localStorage['tjg:burned-messages']`（上限 1000 条，超出淘汰最早），
   三个位置接入——
   - `BurnMessage.completeBurn()`：本地倒计时结束时记入
   - `BURN_MESSAGE_BURNED` 处理器：服务端到期时记入（**保留原有 `deleteMsg` 行为**）
   - `chatMessageList` / `chatMessageListByRoomId`：渲染前过滤掉黑名单条目
   于是两条清理路径（本地占位 / 服务端移除）在**重载后最终状态一致**——都不再出现。
   ⚠️ 残余边界：清空本地存储或换设备后，服务端尚未 sweep 的到期消息仍可能短暂出现。

4. **拒发阅读回执即可绕过倒计时 —— 已决策接受。**
   **现状**：正常客户端读消息会发 `m.read` 回执（不可省的正常行为），
   服务端在回执落库后自动登记销毁时间（`send_receipt` 的
   `maybe_schedule_burn_on_read`），不再依赖客户端额外调
   `PUT /burn/{event_id}`。
   **残余缺口**：改包拒发 `m.read` 回执，服务端就没有任何记录，
   消息永不进入倒计时。
   **为什么接受**：要堵死只能改成「sync 投递即建行」，语义会从
   「阅读即焚」变成「送达即焚」，且要动 sync 热路径、对大房间有放大风险。
   产品口径确认：**该功能防的是普通用户随手翻看，不防有技术能力的接收方。**
   **对外沟通不要承诺「对方一定看不到」**，应表述为「读后自动销毁」。

5. **发送方可截屏/复制。**
   §2.4 的防截屏仅覆盖本端窗口，无法阻止对方拍照或用另一台设备记录。

**结论**：功能**真实可用**（有后端登记 + 后台清扫 + 事件推送 + UI 全链路 +
跨会话焚毁黑名单），
但**不具备密码学意义的「不可恢复销毁」**，也**不防有技术能力的接收方**
（拒发阅读回执即可绕过倒计时，见限制 4）。
对外沟通应表述为「阅后即焚（本地销毁）」，**不要承诺**「服务端不保留」或「对方一定看不到」。

## 4. 安全与隐私规范

### 4.1 管理员权限验证

```typescript
// 路由守卫
const adminGuard = async (to, from, next) => {
  const userInfo = await matrixAccountService.getCurrentUserInfo()
  if (userInfo?.role !== 'admin') {
    showToast('您没有权限访问此页面', 'error')
    next('/')
  } else {
    next()
  }
}
```

### 4.2 私密聊天安全

- **端到端加密**: 使用 `m.room.encrypted` 事件类型
- **密钥管理**: 自动交换设备密钥
- **消息仍加密存储**: 服务端保存密文（Matrix 房间事件由全员共享，不能因一人
  到期就 redact，否则会「一人已读、全员丢消息」）；客户端侧按 §2.3 移除
- **不要对用户承诺「服务端不保留」**：端到端加密保证服务端看不懂内容，
  但保证不了「服务端不存」
- **截屏警告**: 截屏行为通知所有群成员

### 4.3 隐私合规

- 私密模式切换需用户明确确认
- 阅后即焚功能需明确告知用户
- 截屏检测需符合当地法律法规

### 4.4 可访问性（WCAG 2.1 AA）

私密聊天与后台都是高频界面，键盘与读屏用户是真实存在的群体。

#### 4.4.1 对比度

| 元素 | 最低要求 | 说明 |
| --- | --- | --- |
| 正文文字 | 4.5:1 | `--tjg-text-primary` 在 `--tjg-bg-primary` 上已达标 |
| 大字号（≥18px 或 ≥14px 粗体） | 3:1 | 统计卡片的大数字 |
| 图标 / 边框 / 焦点环 | 3:1 | 表格分隔线不在此列（纯装饰） |
| 危险色文字 | 4.5:1 | `--tjg-color-danger-500` 做**背景**时文字必须转白色，不可反向 |

⚠️ 私密模式的红色系最容易出问题：`--tjg-color-danger-500` 上放白字约 4.6:1，
刚好过线；**不要**再压深或加透明度，否则掉到 4.5 以下。

#### 4.4.2 键盘可达

- 所有可点击元素必须能 `Tab` 到达，且 `focus-visible` 有可见环（用 `--tjg-border-contrast`，2px）
- 弹窗 / 抽屉打开后**焦点移入**，`Esc` 关闭，关闭后**焦点回到触发元素**
- 表格行内的操作按钮不做 `tabindex="-1"`：键盘用户必须能操作删除
- 私密模式确认对话框是**模态**的，背后内容不可 Tab 进入（`aria-modal="true"`）

#### 4.4.3 语义与播报

| 元素 | 要求 |
| --- | --- |
| 图标按钮 | 必须有 `aria-label`（🔧 / 🔥 / 🔒 这类 emoji 图标读屏念不出来） |
| 状态点 | 不能只用颜色区分在线/离线，要配文字或 `aria-label` |
| 倒计时 | `aria-live="polite"`，但**不要每秒播报**——改为每 30 秒或最后 10 秒播报 |
| Toast | `role="status"`；错误用 `role="alert"` |
| 表格 | 用真 `<table>` + `<th scope="col">`，不要纯 div 布局 |

#### 4.4.4 动态效果

- 尊重 `prefers-reduced-motion`：关闭火焰特效、渐隐改直接切换
- 骨架屏的呼吸动画在减弱动效时改为静态占位

## 5. 视觉与交互一致性规范

### 5.1 设计 token

**一律使用 `--tjg-*` 变量，禁止写死色值**。改主题时写死的值不会跟着变，这是历史遗留问题的主要来源。

| 类别 | token | 用途 |
| --- | --- | --- |
| 后台底色 | `--tjg-admin-bg` | 内容区背景（`#f0f2f5` 系） |
| 后台卡片 | `--tjg-admin-card-bg` / `--tjg-admin-card-shadow` | 统计卡片 |
| 侧栏 | `--tjg-admin-sidebar-bg` / `--tjg-admin-sidebar-text` / `--tjg-admin-sidebar-hover` | 导航 |
| 文字层级 | `--tjg-text-primary` / `--tjg-text-tertiary` / `--tjg-text-quaternary` | 三级层次 |
| 语义色 | `--tjg-color-danger-500` | 危险 / 私密模式 |
| 表面 | `--tjg-surface-panel-muted` | 私密模式头部微弱区分 |
| 阴影 | `--tjg-shadow-sm` | 顶栏、卡片 |
| 圆角 | `--tjg-radius-md` | 卡片、按钮 |
| 间距 | `--tjg-space-2/3/4` | 8 / 12 / 16px |
| 动效 | `--tjg-motion-ease-standard` | 统一缓动 |

### 5.2 间距与栅格

- 基础单位 **4px**，常用档位 **8 / 12 / 16 / 24 / 32**
- 卡片内边距 **16px**，卡片间距 **24px**（与 §1.3.1 的统计卡片网格一致）
- 表格行高 **48px**，单元格左右内边距 **12px**
- 内容区最大宽度 **1440px**，超出后居中留白（不要在超宽屏上把表格拉满）

### 5.3 交互反馈

| 状态 | 表现 |
| --- | --- |
| hover | 背景提亮一档（`--tjg-admin-sidebar-hover` 等），**不做位移** |
| active / 按压 | 缩放 0.98 或加深一档，时长 120ms |
| focus | 2px 焦点环，**始终可见**（不要 `outline: none`） |
| disabled | 透明度 0.5 + `cursor: not-allowed`，**不改变尺寸** |
| 提交中 | 按钮 loading + 禁用，**宽度锁定** |

### 5.4 文案规范

- 按钮用**动词**（「删除用户」而非「确定」）
- 错误提示说**用户能做什么**，不说系统发生了什么
- 私密相关文案**不承诺绝对安全**（见 §2.3.5 限制 4）
- 中英文之间加空格，数字与单位之间不加（「30 分钟」而非「30分钟」）

### 5.5 图标

- 统一用图标的**线性风格**，不混用实心与线性
- 尺寸档位 **16 / 20 / 24**，不出现 18、22 这类非档位值
- 纯图标按钮必须有 `aria-label`（见 §4.4.3）
