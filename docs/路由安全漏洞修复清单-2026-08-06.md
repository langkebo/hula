## P0 — media r1 下载未授权访问

### VULN-01：`/_matrix/media/r1/download/{server_name}/{media_id}` 无认证

| 字段 | 内容 |
| :--- | :--- |
| **漏洞 ID** | VULN-01 |
| **严重性** | MEDIUM |
| **类型** | AUTH_BYPASS（认证缺失） |
| **影响端点** | `GET /_matrix/media/r1/download/{server_name}/{media_id}` |
| **无 auth 响应** | `200` + `{}`（不存在媒体返回空对象而非 404） |
| **风险** | 攻击者无需 token 即可下载媒体；枚举 `media_id` 可获取用户上传的图片/文件。不存在的 media_id 返回 200+`{}` 而非 404，便于枚举探测 |
| **根因** | [media/mod.rs](file:///Users/ljf/Desktop/hu_ts/synapse-rust/src/web/routes/media/mod.rs) `create_media_legacy_download_router()`（L36-39）将 `/download/{server_name}/{media_id}` 注册为公开路由，未挂载认证中间件。r1 legacy 路径为联邦媒体兼容保留，但未对本地媒体强制认证 |
| **修复方案** | 方案 A（推荐）：在 `download::download_media_v1` handler 内部增加 `OptionalAuthenticatedUser` 提取，对非联邦来源的本地媒体强制要求 token；联邦请求通过 X-Matrix 签名验证放行。<br>方案 B：将 r1 download 路由从 `public_routes` 移至 `create_media_authenticated_router()`，仅在 `/_matrix/client/v1/media/download` 下提供认证下载；r1 legacy 路径返回 410 Gone 引导客户端迁移至 v3/client/v1 |
| **涉及文件** | [src/web/routes/media/mod.rs](file:///Users/ljf/Desktop/hu_ts/synapse-rust/src/web/routes/media/mod.rs)（L36-39）、[src/web/routes/media/download.rs](file:///Users/ljf/Desktop/hu_ts/synapse-rust/src/web/routes/media/download.rs)（`download_media_v1` 函数） |
| **验证方法** | `curl -sk -o /dev/null -w "%{http_code}" https://matrix.test/_matrix/media/r1/download/matrix.test/testmedia` → 修复后应返回 401（无 token）或 404（资源不存在），不再返回 200 |
| **实际修复** | 在 [media/mod.rs](file:///Users/ljf/Desktop/hu_ts/synapse-rust/src/web/routes/media/mod.rs) 新增 `create_media_r1_router(state)` 工厂函数，对 `create_media_legacy_download_router()` 产生的 r1 路由叠加 `auth_middleware`（`from_fn_with_state`），仅 r1 legacy 路径强制认证；v1/v3 下载保持公开以兼容 Matrix 联邦规范 |
| **状态** | [x] 已修复（回归测试 `vuln_01_media_r1_download_without_auth_returns_401` / `vuln_01_media_r1_download_with_auth_still_works` 通过） |

## P1 — webhook 端点认证顺序错误

### VULN-03：`/_synapse/external/openclaw/{service_id}/webhook` 认证晚于请求体校验

| 字段 | 内容 |
| :--- | :--- |
| **漏洞 ID** | VULN-03 |
| **严重性** | MEDIUM |
| **类型** | WEAK_AUTH_ENFORCEMENT（认证顺序） |
| **影响端点** | `POST /_synapse/external/openclaw/{service_id}/webhook` |
| **无 auth 响应** | `422`（`missing field 'action'`）— 请求体反序列化失败先于认证检查 |
| **风险** | 未认证调用者通过 422 错误消息获知端点期望的 JSON 字段结构（`action` 等），泄露 API 契约。正确行为应是无 token 时直接返回 401 |
| **根因** | [external_service.rs](file:///Users/ljf/Desktop/hu_ts/synapse-rust/src/web/routes/external_service.rs) L406-411 将 webhook 路由放在 `public_routes`（无 auth 中间件）。handler `handle_openclaw_webhook`（L256）通过 `extract_webhook_auth` 在函数内部校验 token，但 Axum 的 `Json<Payload>` 提取器在 handler 执行前先反序列化请求体，导致 422 先于 401 返回 |
| **修复方案** | 在 webhook handler 前增加轻量认证中间件层：从 headers 提取 `Authorization` / `x-webhook-token` / `x-webhook-signature`，无凭证时直接返回 401，不进入 body 反序列化。具体实现：为 `public_routes` 中的 webhook 路由添加 `.route_layer(webhook_auth_middleware)`，中间件内调用 `extract_webhook_auth` 并在 token/signature 均缺失时返回 401 |
| **涉及文件** | [src/web/routes/external_service.rs](file:///Users/ljf/Desktop/hu_ts/synapse-rust/src/web/routes/external_service.rs)（L91 `extract_webhook_auth`、L256 `handle_openclaw_webhook`、L406-411 `public_routes`） |
| **验证方法** | `curl -sk -X POST -H "Content-Type: application/json" -d '{}' -w "\n%{http_code}" https://matrix.test/_synapse/external/openclaw/testsvc/webhook` → 修复后应返回 401（无 token），不再返回 422 |
| **实际修复** | 在 [external_service.rs](file:///Users/ljf/Desktop/hu_ts/synapse-rust/src/web/routes/external_service.rs) 新增 `webhook_auth_guard` 中间件（L120-132），检查 `authorization` / `x-webhook-token` / `x-api-key` / `x-webhook-signature` 任一存在即放行，否则直接返回 401（不进入 `Json<Payload>` 反序列化）；通过 `public_routes.route_layer(from_fn(webhook_auth_guard))` 挂载到全部 webhook 公开路由 |
| **状态** | [x] 已修复（回归测试 `vuln_03_openclaw_webhook_without_auth_returns_401` 通过） |
