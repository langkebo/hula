### 5.1 Android 打包：三条入口怎么选（2026-11-14 实测）

先记结论：**环境不需要升级**（JDK 21.0.13 / Gradle 8.14.7 / NDK 30 / compileSdk 36 / Android Studio 2026.2 都在支持矩阵内），
卡点是**入口方式**——这个 gradle 工程被 Tauri 设计成「`rustBuild*` 回调 CLI 并从 WebSocket 取选项」，
现在已加 cargo 回退（§5.2），IDE 里可以直接 Run / Build。

| 用途 | 入口 | 前端来源 | 状态 |
| --- | --- | --- | --- |
| 日常联调（CDP 探针） | `pnpm adev`（`tauri android dev`） | devUrl，5210 热更 | 一直在用 |
| **在 Android Studio 里 Run / Debug** | 直接在 IDE 里点 Run / Build | devUrl | ✅ 已修（2026-11-14）：`rustBuild*` 拿不到 CLI 的 ws 时**自动回退 cargo**，见 §5.2。⚠️ CLI 2.11.4 **没有** `tauri android open` 子命令（曾写进本文档，已纠正） |
| dev 壳出包（可装、可探针） | `pnpm build:android`（= `scripts/build-android-apk.mjs`） | devUrl | ✅ 实测通过（497 MB，16 KB 对齐校验 OK） |
| 生产包（离线可用） | `pnpm build:android:prod`（走 `tauri android build`） | **打进 APK**（dist） | ✅ `npx tauri android build --debug --apk --target aarch64` 实测 32m51s 成功，产物 `apk/universal/debug/app-universal-debug.apk`（519 MB，包内含 `assets/*.js/css/html`） |

> ⚠️ 两种包**不通用**：dev 壳的 Rust 用 `--no-default-features` 编译（不嵌 assets，靠 devUrl）；
> 生产包带 `custom-protocol` 把 dist 打进去。装错包会出现「明明打了包，打开却连 dev server」或
> 「CDP 探针 `import('/src/...')` 全失败」。

#### 一键脚本

`scripts/build-android-apk.mjs`（`pnpm build:android` / `pnpm build:android:prod`）把下面三个坑内建，
并在结尾自动跑 **16 KB 对齐** 与 `check:apk-freshness`：

```bash
pnpm build:android                    # dev 壳（arm64/debug），联调用
pnpm build:android:prod               # 生产包（嵌 dist）
node scripts/build-android-apk.mjs --release          # release profile
node scripts/build-android-apk.mjs --target armv7 x86_64
node scripts/build-android-apk.mjs --skip-rust        # 只重打包（仅 dev 模式有效）
```

#### 独立 gradle 的三个坑（脚本内建的原因）

1. **`rustBuildArm64Debug` 会 panic**：`buildSrc/.../BuildTask.kt` 里它不是自己调 cargo，而是回调
   `pnpm tauri android android-studio-script`，该子命令要从父进程的 WebSocket 读 CLI 选项；
   独立跑 gradle 没有父进程 ⇒ `failed to read CLI options: … failed to build WebSocket client: Connection refused`（exit 134）。
   ⇒ 脚本用 `-x rustBuildArm64Debug` 自己编 Rust。**（2026-11-14 起 `BuildTask` 已加 cargo 回退，
   不加 `-x` 也能过；见 §5.2。脚本保留 `-x` 只是为了避免同一份 cargo 编两遍。）**
2. **手动 cargo 必须用 API 26 的 NDK 包装**（`minSdk = 26`）：用 `aarch64-linux-android24-clang` 会在链接期
   `ld.lld: error: unable to find library -laaudio`（`aaudio` 自 API 26 才有，来自 `oboe`/`cpal`）。
3. **必须同时给 `CC_*` 与 `CXX_*`**：只给 CC 时 cc-rs 报
   `failed to find tool "aarch64-linux-android-clang++"`；且 `cargo … | tail` 会吞掉退出码（失败也显示 0），
   判据要看 `Finished \`dev\` profile` 与产物 mtime。

> 另：`app/build.gradle.kts` 已显式钉 `ndkVersion = "30.0.15729638"`——本机同时装了 27.2 与 30.0，
> 不钉版本时 AGP 可能选到 27.2（< r28）⇒ 会打出 4 KB 对齐的 .so，装到 16 KB 设备直接报
> `ELF alignment check failed`。升级 NDK 时同步改这里与 `src-tauri/.cargo/config.toml` 的注释。

> 沙箱/CI 特有：`tauri android build` 会跑 `pnpm build`，在 AI 沙箱里可能 `write EPIPE`（broker IPC），
> 需 `NODE_OPTIONS='' CODEBUDDY_BROKERED_FS_HOOK_ENABLED=0`；脚本已自动注入这两个变量。


手工排障时的等价命令（日常请直接用 `pnpm build:android`，脚本会做同样的三步并额外校验）：

```bash
# ① 编原生库（minSdk=26 的工具链）
cd src-tauri && NDK=$HOME/Library/Android/sdk/ndk/30.0.15729638 && T=$NDK/toolchains/llvm/prebuilt/darwin-x86_64
CC_aarch64_linux_android=$T/bin/aarch64-linux-android26-clang \
CXX_aarch64_linux_android=$T/bin/aarch64-linux-android26-clang++ \
AR_aarch64_linux_android=$T/bin/llvm-ar \
CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER=$T/bin/aarch64-linux-android26-clang \
cargo build --target aarch64-linux-android --no-default-features

# ② 打包（复用刚编的 .so；jniLibs 里是指向 target/ 的软链）
cd gen/android && JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home \
  ./gradlew :app:assembleArm64Debug -x rustBuildArm64Debug

# ③ 校验：16KB 对齐（16KB 设备必需）+ 安装
llvm-readelf -l src-tauri/target/aarch64-linux-android/debug/libtjg_app_lib.so | grep LOAD   # Align 应为 0x4000
adb install -r -t src-tauri/gen/android/app/build/outputs/apk/arm64/debug/app-arm64-debug.apk
```

> ⚠️ debug 包的 `devUrl = http://localhost:5210` ⇒ **前端改动不需要重打 APK**（dev server 热更即可），
> 只有 `src-tauri/**` 的原生改动才需要。反过来，**APK 构建时间早于原生改动时间**时，设备上跑的是旧 Rust
> （本轮就踩到：`lib.rs` 11-13 22:19 / `im_user_repository.rs` 11-14 12:08 都晚于旧包 20:16）。
>
> ✅ **已加门禁**：`pnpm check:apk-freshness`（`scripts/check-apk-freshness.mjs`）比对 APK 与全部原生输入
> （`src-tauri/src`、`src-tauri/capabilities`、`tauri-plugin-hula`、Cargo/tauri/Android 壳配置）的 mtime，
> 陈旧则 **exit 1** 并列出超期文件；未打包时 SKIP。四个设备探针启动时也会自动跑它：
> 默认只打 ⚠️ 横幅，`PROBE_REQUIRE_FRESH_APK=1` 时直接中止（原生层判据如 D2-R 必须开）。
>
> ✅ **探针自带清数据**：`scripts/lib/probe-runtime.mjs` 的 `resetAppState()` 在探针开头 `pm clear com.tjg.app`
> （`PROBE_KEEP_STATE=1` 可跳过）—— 此前连续跑不同探针会因「上一支还登录着 ⇒ 登录表单填不进去」互相污染
> （本轮焚毁探针 2 红、E2EE 首跑 3 红都只是这个原因，与产品无关）。

### 5.2 Android Studio 里点 Run 就 `BUILD FAILED in 2s`（2026-11-14 修复）

**现象**：IDE 里点 Run/Build，热 daemon 下 **2 s 就红**（冷启 7~24 s），报

```
Execution failed for task ':app:rustBuildArmDebug'.
> Process 'command 'pnpm'' finished with non-zero exit value 134
failed to read CLI options: failed to build WebSocket client: ConnectionRefused
```

**两层根因**（都不是环境问题，也不需要升级 Android Studio）：

1. **ws 依赖**：`buildSrc/.../BuildTask.kt` 的 `rustBuild*` 不编 Rust，而是回调
   `pnpm tauri android android-studio-script`；该子命令要从**父 CLI 进程的 WebSocket** 读选项
   （CLI 里对应 `failed to write server address file` / `127.0.0.1:0` 的 ws server）。
   IDE 直接构建没有那个父进程 ⇒ exit 134。CLI 2.11.4 **没有** `android open` 之类能留下该 ws 的子命令。
2. **变体选错**：RustPlugin 生成 4 个 ABI flavor（`universal/arm64/arm/x86/x86_64`），IDE 同步后默认选
   **`armDebug`（armeabi-v7a，32 位）**；而本仓只编 aarch64、`jniLibs/` 里也只有 `arm64-v8a`
   ⇒ 即便编过，装上去也是没有 `libtjg_app_lib.so` 的空壳包。
   ⚠️ 上游 bug：`archList` 属性只影响**任务命名**，创建 flavor 时仍遍历硬编码的 `defaultArchList`。

**修法（三处，均已实跑验证）**：

| 落点 | 改动 |
| --- | --- |
| `buildSrc/.../BuildTask.kt` | CLI 失败时回退到 `node scripts/android-rust-build.mjs --target <triple> [--release]`（打 `[rust] tauri CLI 不可用…回退` 日志）；`node` 走绝对路径候选 + `NODE_BINARY` 覆盖 |
| `buildSrc/.../RustPlugin.kt` | flavor 创建改遍历 `archList`（上游只认硬编码表），让 `abiList/archList/targetList` 真正生效 |
| `src-tauri/gen/android/gradle.properties` | `abiList=arm64-v8a` / `archList=arm64` / `targetList=aarch64` ⇒ 只剩 `universal`+`arm64` 两个变体，IDE 无论选哪个都是 arm64 |
| **新增** `scripts/android-rust-build.mjs` | 纯 cargo 入口：api=minSdk(26) 的工具链、`CC_*`+`CXX_*`+`AR_*`+linker、debug 用 `--no-default-features`、**并自建 `jniLibs/<abi>/` 软链**（原本由 CLI 建；缺链会打出无 `.so` 的空壳包） |

> ⚠️ `buildSrc/` 与 `gradle.properties` 都是 `tauri android init` 的生成物，重跑该命令会覆盖，
> 届时需把上面三处补回（文件里已标 `PATCH（本仓改过…）`）。
> `app/build.gradle.kts` 的 `packaging { jniLibs.keepDebugSymbols… }` 也被压成一行，属同批改动。

**验证（都是 IDE 等效命令，不加 `-x rustBuild*`）**：

| 场景 | 结果 |
| --- | --- |
| `./gradlew :app:assembleArm64Debug` | `[rust] tauri CLI 不可用…回退` → `BUILD SUCCESSFUL in 1m47s`；APK 521 MB，包内 `lib/arm64-v8a/libtjg_app_lib.so` |
| `./gradlew :app:assembleUniversalDebug`（IDE 另一种可能的默认变体） | `BUILD SUCCESSFUL in 29s` |
| **软链自愈**（先 `rm jniLibs/arm64-v8a/libtjg_app_lib.so`） | 回退脚本重建软链并成功打包 ⇒ 不会静默打出空壳包 |
| `:app:tasks --all` | `assembleArm`/`assembleX86` 等已消失，只剩 `assembleArm64*` 与 `assembleUniversal*` |
| `pnpm build:android --target armv7`（已被裁剪） | 前置报错并给出「把 armeabi-v7a / arm 补回三处属性」的可执行提示，不再落到 gradle 的 `Task not found` |

**日常仍推荐**：`pnpm build:android`（dev 壳）/ `pnpm build:android:prod`（出包）——脚本额外做 16 KB 对齐与
`check:apk-freshness` 校验；IDE 的 Run 只适合「改原生代码后快速装到设备看效果」。
