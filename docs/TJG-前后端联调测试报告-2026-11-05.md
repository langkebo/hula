### 1.1 复跑方式（两条环境前提，踩过坑）

```bash
# ① 批量单测：宿主的文件系统钩子已由 scripts/run-vitest.js 统一关闭
#    （固定 CODEBUDDY_BROKERED_FS_HOOK_ENABLED=0），直接跑即可。
#    手工加前缀只在绕过该脚本直接调 vitest 时需要。
#    （node-brokered-fs-shim：每个 readFileSync 变成 broker IPC，
#     并行度高时 connect refused ⇒ 报成用例失败，看起来像超时）
node scripts/run-vitest.js run <paths>

# ② 真后端 live 用例需显式开启（会注册临时账号）
TJG_MOBILE_LIVE=1 npx playwright test e2e/mobile-session-list.spec.ts --project=mobile-chromium
```

> 其它约定：登录后用 `#app.__vue_app__.config.globalProperties.$router.push` 做 SPA 跳转
> （浏览器态 token 只在内存，`page.goto` 必掉登录）；每次整页重载后要放过「设置本地解锁密码」门禁。

## 四、现存问题清单（前端 / 后端 / SDK）

> 每条给「现象 → 证据 → 影响 → 下一步」。优先级口径：**P0** 阻断交付 / **P1** 影响主流程或结论可信度 /
> **P2** 体验或工程债 / **P3** 观察项。

### 4.1 后端（3 项）

> **BE-12 / BE-9 已于 2026-11-06 关闭**（commit `c8180e544`，镜像 `6.3.0-9bdd56801-dirty` 含该提交）。
> 下面是复核证据与**残留的部署风险**（不是功能缺陷）。

#### ① 部署可重复性：索引迁移没有版本记录 + 镜像 tag `-dirty` —— **P1**

- **现象**：`migrations/` 下只有一个基线文件，索引重建写在 DO 块里「重放时执行」；
  库里**没有** `_sqlx_migrations` 之类的版本表，无法从数据侧判断某个库是否已应用。
  实测证据：同一库在 16:04 查询 `pg_indexes` 仍是旧定义（`INCLUDE (…, content, …)`），
  16:10 复核已是新定义 —— 说明这次是**期间被手工/脚本执行**才生效的，不是自动保证。
- **影响**：新环境/存量环境可能一个已修一个没修，而接口表现只差「500 → 413」不易察觉；
  镜像 tag 带 `-dirty` 也无法从 tag 反查代码状态。
- **下一步**：① 把索引重建拆成**带版本号的独立 migration**（或在启动时校验 `pg_get_indexdef` 不含
  `INCLUDE%content` 并告警）；② 重建干净镜像并更新 `meta/sdk-pin.json` 的 `synapse_rust_commit`。
- **验收**：`select pg_get_indexdef(...)` 不含 `content`；`docker inspect` 的 tag 无 `-dirty`；
  `pnpm verify:sdk-pin`（带 `TJG_SDK_DIR`）通过。

#### ② BE-7 `M_UNKNOWN` 同码多义 —— **P2，观察**

- **现象**：同一 errcode 覆盖 400/409/500/501/503。已有 `M_UNKNOWN_MEANINGS` 穷尽表 + 守卫，前端按 HTTP 状态消歧。
- **影响**：客户端无法只凭 errcode 决策（BE-12 修好前，写入超限正是被这层掩盖成「未知错误」，
  现在有了 `413 M_TOO_LARGE` 这条明确的出口）。
- **下一步**：保持现状；若后续再出现「同一码多种处置」，优先按 HTTP 状态拆分而不是新增 errcode。

#### ③ `m.friends.list` 存量仍走 legacy 单事件 —— **P3，已知设计**

- **现象**：V5 已实现按好友 localpart 首字母分片（28 个 shard，新写入走分片），
  但**存量不主动迁移**；实测库里 419 条 `m.friends.list` 的 `state_key` 仍全为空（legacy 通道）。
- **影响**：单个事件体量仍随好友数线性增长（每好友 ≈264B）。BE-12 之后这不再导致写入失败，
  但同步载荷与联邦重写成本仍压在单事件上。
- **下一步**：维持「no-migration」语义即可；若要压载荷，另开一次性 backfill（需停写窗口）。

### 4.2 前端（6 项）

#### ① 本轮已修的三项（好友列表 / 附件发送 / 会话恢复）—— 已闭环

| 项 | 根因（一句话） | 修法 | 守卫 |
