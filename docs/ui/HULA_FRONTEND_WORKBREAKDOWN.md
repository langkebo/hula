# HULA 前端任务拆分表（以后端合同为准）

## 1. 文档目标

本文档将房间列表、空间列表、消息区与好友关系页的改造拆解为前端任务，并把每个阶段与真实后端能力绑定，保证开发顺序、联调路径和降级策略都可执行。

## 2. 范围说明

本任务拆分覆盖：

- 房间列表与 sliding sync 接入层
- 房间摘要与详情侧栏
- 空间列表、空间树、空间摘要
- 好友列表、好友请求、直聊跳转
- 消息区的扩展状态对齐
- `matrix-js-sdk` 事件与管理器接口接线
- Storybook / 样式指南示例补齐
- 冗余业务弹窗迁移与清零
- 可访问性、性能和回归验证

## 3. 角色建议

- 列表架构负责人：负责房间列表、空间树与同步容器
- 聊天区负责人：负责消息区和房间摘要侧栏
- 关系链路负责人：负责好友、请求、DM 跳转
- 设计系统负责人：负责 token、状态矩阵、Figma 变量
- QA/联调负责人：负责接口对照、截图回归、降级路径验证

## 4. 优先级

- `P0`: 后端对齐和主链路必须完成
- `P1`: 体验增强与跨端一致性
- `P2`: 第二轮打磨和高级导航

## 5. 阶段拆分

### 阶段 A：能力对齐与调用边界治理

#### 目标

先建立后端能力边界，避免页面开发时继续写入错误假设。

#### 任务

##### A1. 建立列表能力 contract 文档和调用封装

- 优先级：P0
- 输入：本目录四份规范文档
- 输出：统一的 API contract 层，覆盖 sliding sync、room summary、spaces、friends、tags、DM、SDK manager
- 验收：前端代码中不再分散硬编码接口路径和字段名

##### A1.1 建立 SDK 事件接线表

- 优先级：P0
- 输入：`matrix-js-sdk/src/client.ts`、`models/room.ts`、`models/room-member.ts`、`friend/index.ts`、`dm/index.ts`、`space/index.ts`
- 输出：`ClientEvent`、`RoomEvent`、`RoomMemberEvent`、`FriendEvent`、`SpaceEvent` 到组件状态的映射表
- 验收：房间列表、好友页、空间树不再依赖分散的临时事件总线重复刷新

##### A2. 建立 feature gate 与降级态判断

- 优先级：P0
- 输出：好友能力不可用、空间无权限、房间摘要无权限三类统一降级组件
- 验收：页面不再把“接口不存在”和“返回空数组”混为一谈

##### A2.1 建立“禁止独立业务窗口”规则

- 优先级：P0
- 输出：房间详情、成员列表、设置面板、好友添加/验证的统一承载规则
- 验收：业务组件不再新增 `createWebviewWindow` 入口；遗留入口全部建立迁移编号

##### A3. 收敛组件语义 token

- 优先级：P0
- 目标文件：`src/styles/css/design-tokens.css`
- 输出：房间高亮未读、邀请态、空间可见性、好友状态、同步恢复横幅 token
- 验收：后续组件不再新增裸色值表达这些状态

### 阶段 B：房间列表主链路改造

#### 目标

把房间列表切换到以后端增量同步和真实字段为中心的架构。

#### 任务

##### B1. 封装 sliding sync 列表数据层

- 优先级：P0
- 后端依赖：`POST /_matrix/client/v3/sync`
- 输出：房间列表 store / composable，支持初始同步、增量同步、恢复同步
- 验收：列表刷新可以只更新变更项

##### B2. 重构房间列表项字段映射

- 优先级：P0
- 当前文件：`src/components/workbench/RoomSessionList.vue`
- 输出：`room_id/name/avatar/is_dm/is_encrypted/is_tombstoned/invited/highlight_count/notification_count/timestamp` 的统一映射
- 验收：高亮未读与普通未读视觉语义明确

##### B3. 加入标签与置顶能力

- 优先级：P1
- 后端依赖：`/user/{user_id}/rooms/{room_id}/tags`
- 输出：房间列表分区或置顶逻辑
- 验收：标签排序只做上层增强，不破坏默认时间排序

##### B4. 接入房间邀请态操作

- 优先级：P1
- 后端依赖：房间加入/离开流程、邀请态字段
- 输出：邀请房间行内 CTA
- 验收：接受/拒绝操作路径短且可解释

##### B5. 清除房间详情二次弹窗

- 优先级：P0
- 输入：`RoomList.vue`、`RoomDetailPane.vue`、`WorkbenchDetailPane.vue`、`views/modalWindow/index.vue`
- 输出：房间列表点击后只更新主内容区和右侧详情区
- 验收：点击房间列表后无二次弹窗；房间详情、邀请、设置都在当前壳层内完成

### 阶段 C：空间列表与空间树改造

#### 目标

把空间从房间列表附属功能提升为独立导航域。

#### 任务

##### C1. 搭建空间侧栏与空间来源分区

- 优先级：P0
- 后端依赖：`/spaces/user`、`/spaces/public`、`/spaces/search`
- 输出：用户空间、公开空间、搜索结果三个数据域
- 验收：公开/私有/邀请制状态可一眼识别

##### C2. 实现分页空间树

- 优先级：P0
- 后端依赖：`/spaces/{space_id}/hierarchy/v1`
- 输出：支持 `next_batch` 的树形加载器
- 验收：深层空间不阻塞首屏，不假设全量返回

##### C3. 接入 tree path 与 parent spaces

- 优先级：P1
- 后端依赖：`/spaces/{space_id}/tree_path`、`/spaces/room/{room_id}/parents`
- 输出：面包屑和“所在空间”定位能力
- 验收：用户可以从任意房间回到上层空间

##### C4. 接入空间摘要与加入流转

- 优先级：P0
- 后端依赖：`/spaces/{space_id}/summary`、`/summary/with_children`、`/join`、`/leave`
- 输出：空间详情页、加入按钮、权限态提示
- 验收：invite-only 空间不能误导为可直接加入

##### C5. 清除空间公告/成员独立窗口

- 优先级：P1
- 输入：`ChatSidebar.vue`、`WorkbenchDetailPane.vue`、`Details.vue`
- 输出：空间/群公告、成员目录、成员资料统一收敛到详情区
- 验收：`announList/:roomId/:type` 不再作为业务主路径存在

### 阶段 D：消息区与房间摘要对齐

#### 目标

让聊天区与详情信息复用真实后端扩展和摘要能力。

#### 任务

##### D1. 接入房间摘要侧栏

- 优先级：P0
- 后端依赖：`/rooms/{room_id}/summary*`
- 输出：topic、别名、加密、人数、统计、成员摘要
- 验收：无权限与无数据状态明确区分

##### D2. 收敛消息区扩展状态

- 优先级：P1
- 后端依赖：sliding sync `extensions.receipts/typing/presence/account_data`
- 输出：消息区回执、输入中、在线状态联动
- 验收：动态状态不影响主消息排版稳定性

##### D3. 处理只读房间和 tombstoned 房间

- 优先级：P1
- 后端依赖：房间状态 + room summary
- 输出：输入区禁用态与迁移说明
- 验收：不可发消息时不出现误导性输入框

### 阶段 E：好友与直聊链路改造

#### 目标

让好友页、好友请求和 DM 跳转以真实关系模型为中心。

#### 任务

##### E1. 封装好友能力探测与降级态

- 优先级：P0
- 后端依赖：friends feature gate、`/friends`
- 输出：能力关闭时的统一空态和说明
- 验收：用户不会看到空白好友页

##### E2. 接入好友列表真实字段

- 优先级：P0
- 后端依赖：`m.friends.list`
- 输出：备注名、昵称、状态、添加时间、隐藏状态等字段渲染
- 验收：`favorite / normal / blocked / hidden` 映射准确

##### E3. 接入好友请求与接受后跳转

- 优先级：P0
- 后端依赖：`/friends/request/*` 系列接口
- 输出：请求面板、接受后跳转 DM 的过渡态
- 验收：接受成功后可立即打开返回的 `room_id`

##### E4. 接入直聊身份识别

- 优先级：P1
- 后端依赖：`/direct`、`/rooms/{room_id}/dm`、`/rooms/{room_id}/dm/partner`
- 输出：单聊头像、对方名称、DM 标识兜底
- 验收：`m.direct` 缺失时仍可从成员结构正确识别

##### E5. 清除好友域独立窗口

- 优先级：P0
- 输入：`FriendsList.vue`、`SearchFriend.vue`、`InfoPopover.vue`、`useChatMain.ts`
- 输出：好友添加、好友验证、好友详情统一迁入好友页/抽屉
- 验收：`searchFriend`、`addFriendVerify` 不再是主业务路径

### 阶段 F：Storybook、截图与验收资产补齐

#### 目标

让文档里的组件、视觉稿、截图和交互示例都可直接验证。

#### 任务

##### F1. 为新增和重构组件补 Storybook

- 优先级：P0
- 输出：`RoomSessionList`、`RoomDetailPane`、`WorkbenchDetailPane`、`FriendListView`、`FriendDetailDrawer` story
- 验收：`pnpm storybook` 下可交互预览，覆盖 loading/empty/error/default 关键状态

##### F2. 补视觉稿链接与迁移编号

- 优先级：P0
- 输出：每个组件具备 `VisualSpec / StorybookTarget / MigrationId`
- 验收：文档内任一组件都能追溯到视觉稿和迁移记录

##### F3. 提供改造前后截图与录屏

- 优先级：P0
- 输出：PR 附件中包含房间点击、详情切换、好友添加、公告查看前后对比
- 验收：能证明冗余弹窗已清零且功能一致

### 阶段 G：响应式、无障碍与性能收尾

#### 目标

为大列表、多状态、多层级导航补齐质量闭环。

#### 任务

##### G1. 响应式布局验证

- 优先级：P1
- 输出：桌面三栏、平板双栏、移动分层导航三套断点策略
- 验收：空间树与房间列表在窄屏不互相挤压

##### G2. 键盘与读屏支持

- 优先级：P1
- 输出：房间列表、空间树、好友卡片、面包屑的 focus 与 aria 规则
- 验收：树节点展开和分页加载可被读屏正确播报

##### G3. 大列表性能验证

- 优先级：P0
- 输出：房间列表和空间树的虚拟渲染、增量刷新基线
- 验收：不因单个房间计数变更触发整表重渲染

##### G4. 回归验证

- 优先级：P0
- 输出：截图回归 + 关键链路测试
- 验收：至少覆盖房间列表、空间树、好友接受跳转、能力关闭降级四条路径

## 6. 依赖关系

### 弱依赖

- token 收敛可与每阶段组件落地并行推进
- 可访问性优化可以在组件拆分后同步接入

- 房间列表点击后无二次弹窗，信息直接展示在右侧主内容区。
- 所有补充的 UI 组件在 Storybook / 样式指南中有可交互示例。
- 文档中的代码片段可直接复制运行，无缺失依赖。
