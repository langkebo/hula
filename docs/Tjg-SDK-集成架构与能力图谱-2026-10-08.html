图 7值得注意的耦合与风险点

① 设置/撤销群管理员调用了不存在的 SDK 方法（P0，活跃路径）。 room/RoomOperations.ts:495-498 里是 await client.setUserPowerLevel(userId, roomId, powerLevel)。实测（在已安装的 Tjg/node_modules/matrix-js-sdk 内检索）：setUserPowerLevel 在整个包的 src/ + lib/ 中只有 1 处命中，即 src/matrix-client-extensions.ts:362 的类型声明——没有任何 MatrixClient.prototype 或 Manager 实现；且 SDK 声明的签名是 (roomId, userId, powerLevel)，与 Tjg 传入的顺序相反。
调用链是真实用户路径：右键菜单 contextMenuLists.ts:560 / :589 → groupStore.addAdmin / revokeAdmin（roles.ts:94 / :108）→ setMemberPowerLevel → TypeError: client.setUserPowerLevel is not a function。 SDK 真正可用的等价 API 是 StateSendManager.setPowerLevel(roomId, userId, powerLevel) （src/state-send/index.ts:59）。
② Worker 名不副实。MatrixWorkerHost 只暴露 15 个方法（搜索索引、探测、store 统计），未暴露 initialize/login/startClient/syncOnce/getClient；主线程从不发送这些消息。因此 Worker 内 state.client 永远是 null，handleGetStats 恒返回 null、handleClearStores 恒为 no-op。CLAUDE.md 中「Matrix SDK 运行在 Web Worker」目前是设计意图而非既成事实。
③ 四条接入路径并存，且同一后端路由常有多套实现。service 层同时存在 client.xxx()（40 个服务）、getXxxManager()、client.http.authedRequest()（10 个服务）与 SynapseExtensionHttpBase 里的裸 fetch（4 个子类）。后两者绕过 SDK 的 Manager 层。
实测的并行实现：房间能力 —— MetadataService.ts:32（走 RoomManager）vs RoomCapabilitiesService.ts:52（走 matrixHttpClient + 自建 5min 缓存 + 去重）；房间摘要 —— SummaryService.ts:110 vs MatrixRoomSummaryService.ts:221-366 vs extensions/SynapseRoomSummaryService.ts；sticky events —— RoomOperations.ts:448/462 vs SynapseStickyEventService.ts:24。
③b 其他静态可见风险。 RoomOperations.ts:318-336 的 incrementUnread/clearUnread 是空实现存根（只 getRoom() 后吞异常）； pin/unpin（:427-442）、setDirectRoom（:223-234）、pushRule 先删后建（:570-595）均为非原子读改写且无并发保护； MatrixMessageService.ts:169/189 的 sendHtmlMessage/sendEmote 实参顺序存疑（m<timestamp> 型 txnId 不满足 SDK 的 $/null 前缀消解规则）； client.login() 与 client.oidcUserInfo() 同样只有类型声明无实现，SSO 登录对 HTTP 回退形成隐性依赖（MatrixClientAuth.ts:199、MatrixOidcService.ts:178）； MatrixDelayedEventsService.ts:205 调用的 client._unstable_getDelayedEvents 在 vendored 包中无实现。
④ 前缀剥离补丁。MatrixHttpClient.stripMatrixPrefix() 存在的原因是「调用方传了完整前缀，SDK 又拼一次默认前缀」导致 URL 翻倍 404。这是路径常量与 SDK 默认前缀约定不一致的症状性修复。
⑤ 构建依赖 sibling 源码。paths/sdk-paths.ts 深度导入 ../../../../../matrix-js-sdk/src/…/__generated__/route-table，绕过 SDK package exports；纯净的 tarball 消费模式下该路径并不存在。
⑥ Sliding Sync 好友列表过滤常量与后端不匹配。MatrixSyncManager.ts:119 用 room_types: ['im.hula.friend_list']，但后端 friend_room_service/mod.rs:161 创建好友列表房间时用的是 m.friends；全仓检索 im.hula 在 synapse-rust 中 0 命中。该 list 恒为空，好友房间实际随 default 列表同步。
