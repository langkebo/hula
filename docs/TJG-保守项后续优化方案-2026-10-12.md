## 一、Goal（目标）

把 P2 报告中「因涉及删依赖 / 跨大版本 / 配置类 / 大改造 / 需二次取证」而顺延的保守项，逐项转化为**可执行、可验证、可回滚**的落地任务，使：

1. 依赖治理闭环：DP-01（6 疑似冗余依赖）、DP-02（overrides 跨版本）、DP-07（Tauri 插件 pin 策略）、DP-08（前沿版本）、EG-07（双更新机器人）从「报告结论」变成「有守卫的现状」；
2. 门禁纵深补全：TS-05（组件交互测试进 CI）、SC-09（本地只读审计）、CP-04（编译目标对齐）不再留「绿灯假象」；
3. 结构债务可见可收敛：CQ-03/05/06、MT-08/09、AR-06/07、SC-05/07 先量化/收敛，再分批重构，且**严守 AGENTS.md 红线（`.vue` ≤ 800 行、禁硬编码颜色、禁 module-level ref）**。

**非目标（Out of Scope）**：不批量重写、不一次性全开 a11y、不删任何未经运行期冒烟确认的依赖。**CP-04 已按用户裁决（A：抬 iOS 下限至 15.0）落地**；**SC-05（capabilities 权限面）/ SC-07（`HttpClient` host allowlist）不并入本期主批次，登记为独立专项**（见「十二」）。

## 二、Architecture（方案架构）

按「风险 × 可验证性」把保守项分成两期，每期内部再按**文件粒度**拆任务；每任务遵循「取证 → 变更 → 验证 → 提交」闭环。

```
保守项后续优化
├── P2.5 低风险快赢（配置/文档/清单类，零或极低回归面）
│   ├── P2.5-1  EG-07   更新机器人二选一 + 修无效 reviewers
│   ├── P2.5-2  DP-01   6 依赖「文档化 + 守卫」（不删）
│   ├── P2.5-3  DP-02   overrides 覆盖项回归清单
│   ├── P2.5-4  DP-07   Tauri 插件统一精确 pin
│   ├── P2.5-5  SC-09   pre-commit 挂只读审计
│   ├── P2.5-6  TS-05   CI 显式纳入 STORYBOOK_TEST=1
│   └── P2.5-7  CP-04   iOS 下限对齐（决策 A：抬至 15.0，已落地）
└── P3 结构治理（按模块分批，TDD/棘轮驱动）
    ├── P3-1  CQ-06  WebVitalsObserver 模块级状态实例化
    ├── P3-2  CQ-03  a11y 规则分批开启
    ├── P3-3  CQ-05  样式夹层硬编码色 token 化
    ├── P3-4  MT-08  格式化函数重复收口
    ├── P3-5  MT-09  桌面/移动双端重复面量化
    ├── P3-6  AR-06  AdminFacadeService 拆分
    ├── P3-7  AR-07  服务层粒度「调用链合并」专项
    └── P3-8  DP-08  前沿版本升级观察机制
```

**分期原则**：
- P2.5 全部为**配置/文档/清单**改动，不触碰业务逻辑，可独立提交、独立回滚；其中 P2.5-7 为**决策项**，用户已裁决为 **A（抬 iOS 下限至 15.0）并已落地**。
- P3 每任务**先量化、再分批**；每批次可独立合并；任何批次结束都要收紧对应棘轮（`node scripts/check-ratchet.mjs --update`）保证**只减不增**。

## 四、Global Constraints（全局约束）

1. **不越红线**：任何 `.vue` 文件 ≤ 800 行；新增样式不得出现 `#xxx`/`rgb()`/`rgba()`，一律 `--tjg-*`；图标必须 SVG（线宽 1.5px）；禁止新增 `isMobile()` 内联分支（优先补 `src/mobile/`）。
2. **配置类改动默认只报告**：CP-04 的 iOS 下限经用户裁决（决策 A）**已落地**；`capabilities/*.json`（SC-05）仍**只报告**，并升级为独立专项（见「十二」）。
3. **删依赖前提**：任何依赖删除必须通过 `pnpm why <pkg>` + 运行期冒烟（登录 + 收发消息 + 媒体）双重确认；**DP-01 结论为「保留」**（详见 P2.5-2）。
4. **提交纪律**：`git commit --no-verify`；只 `git add` 本任务文件；不提交 `src/typings/auto-imports.d.ts`；提交信息不含 emoji。
5. **每任务验收必跑**：`pnpm check:release` 全绿 + `pnpm test:run` 通过（除既有 `MatrixCryptoStateTracker` 循环依赖失败外，不得新增失败）。
6. **保守口径**：任一任务若取证发现回归面大于预期，立即**降级为报告交付**并在本文档追加结论，不强行落地。

### P2.5-1 EG-07：更新机器人二选一 + 修无效 reviewers

**现状（已取证）**：
- `.github/dependabot.yml` 与 `renovate.json` **双配置并存**；两者都覆盖 npm + cargo，会产生**重复 PR**。
- `.github/dependabot.yml` L33-36 的 `reviewers: ["@龙卷风/core"]` / `assignees: ["@龙卷风/core"]` **语法无效**（非法 GitHub 团队句柄，且含中文），解析结果不可预期。

**决策**：**保留 renovate，删除 dependabot**（renovate 能力更强：分组、`rangeStrategy: bump`、`vulnerabilityAlerts.automerge`、schedule 已在册）。

**变更文件**：删除 `.github/dependabot.yml`；`renovate.json` 补 `github-actions` 生态（`enabledManagers` + 分组 `packageRules`），以覆盖 dependabot 原有 actions 生态。

**落地结果（2026-10-12）**：
- 已删除 `.github/dependabot.yml`（消除双配置重复 PR 与无效 `reviewers/assignees: ["@龙卷风/core"]`）。
- `renovate.json`：`enabledManagers` 由 `["npm", "cargo"]` 扩为 `["npm", "cargo", "github-actions"]`，并新增 `github-actions` 分组规则；`pip` 因仓库无 Python 文件不再保留。
- 已通过 JSON 解析校验：`renovate.json JSON OK`；`.github/dependabot.yml removed`。

**提交**：

### P2.5-2 DP-01：6 个「零直接引用」依赖的「文档化 + 守卫」（结论修正：保留）

**现状（已取证，修正报告口径）**：
- 6 包 `content-type`/`events`/`loglevel`/`matrix-events-sdk`/`matrix-widget-api`/`sdp-transform` **全部**是 vendored SDK（`@langkebo/matrix-js-sdk`）自身的 `dependencies`（非 peer/optional）。
- `build/config/vite.config.base.ts` 的 `optimizeDeps.include` **显式包含这 6 包**，注释明确 `events` 必须 include，否则触发 **2026-08-09 登录页白屏**（`does not provide an export named 'EventEmitter'`）。
- `knip.config.ts` 的 `ignoreDependencies` 已含这 6 包并注明原因。
- 全仓**仅 1 处**直接 import：`src/services/matrix/__tests__/MatrixEventRouter.maxlisteners.test.ts:1`。

**结论**：**不可删除**（`optimizeDeps.include` 依赖其可从根解析）。本任务**不删依赖**，改为「文档化 + 守卫」，防止后人误删再次触发白屏。

**变更文件**：
- 新增 `docs/baseline/dependency-vendor-runtime.md`（记录 6 包与 `optimizeDeps.include` 的绑定关系 + 2026-08-09 事故链接）；
- `knip.config.ts`：把 `ignoreDependencies` 中这 6 项的注释补充为**指向新文档**的引用；
- 新增守卫 `scripts/check-vendor-runtime-deps.mjs`：导出纯函数（如 `evaluateVendorRuntimeDeps({ pkg, optimizeDepsInclude })`），断言 6 包同时出现在 `package.json.dependencies` 与 `vite.config.base.ts` 的 `optimizeDeps.include` 中，任一缺失即 exit 1；
- **新增单测 `tests/lint/check-vendor-runtime-deps.test.ts`**（`vitest.config.ts` 的 `include` 覆盖 `tests/lint/**/*.test.ts`，而**不含 `scripts/**`**；遵循既有 `tests/lint/check-dependency-audit.test.ts` 约定：`import { ... } from '../../scripts/check-vendor-runtime-deps.mjs'`）；
- `package.json`：新增脚本 `check:vendor-runtime-deps`，并**并入 `check:release`**。

**步骤（TDD）**：
1. 写守卫脚本，导出纯函数（先使其对当前仓库 exit 0）。
2. 新增单测 `tests/lint/check-vendor-runtime-deps.test.ts`：构造「缺一包」的假配置入参，断言判定为违规 / exit 1。
3. 跑测试（先红后绿）：`pnpm vitest run tests/lint/check-vendor-runtime-deps.test.ts`。
4. 补文档与 `knip.config.ts` 注释引用。
5. 跑聚合门禁。

**验收判据**：

- 人为删除 `package.json` 中任一包 → 守卫 exit 1（取证）；
- 单测位于 `tests/lint/` 且被 vitest 发现执行；
- 新文档落盘且被 `knip.config.ts` 引用。

**提交**：
