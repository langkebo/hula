## 二、问题分析

### 2.1 问题特征

**间歇性失败**：
- 单独运行：100% 通过
- 全量运行：偶尔超时
- 失败不固定：有时 1 个，有时 3 个

**超时位置**：
- 测试：路由重定向测试
- 超时时间：10000ms
- 实际耗时：通常 3-4 秒

### 2.2 根本原因

**测试环境资源竞争**：

1. **并发测试竞争**：
   - 全量运行时，217 个测试文件并发执行
   - 路由测试需要创建 Vue Router 实例
   - 多个测试同时创建路由实例可能导致资源竞争

2. **内存压力**：
   - 全量测试加载大量组件和模块
   - 内存压力可能导致路由初始化变慢

3. **事件循环阻塞**：
   - 大量异步操作可能阻塞事件循环
   - 导致 `router.isReady()` 延迟

### 2.3 不是代码问题

**证据**：
1. ✅ 单独运行 100% 通过
2. ✅ 代码逻辑正确
3. ✅ 路由配置正确
4. ✅ TypeScript 0 errors
5. ✅ 其他 2356+ 测试通过

**结论**：这是测试环境问题，不是代码缺陷

- 影响：极小（1-3/2359 个测试）

2. 不影响功能

### 4.2 中期方案（可选）

**CI 配置优化**：

1. **增加测试超时**：
   ```json

   {
     testTimeout: 15000 // 从 10000 增加到 15000
   }
   ```

2. **减少并发数**：
   ```json
   // vitest.config.ts
   {
     maxConcurrency: 5 // 限制并发测试数
   }
   ```

3. **添加 retry**：
   ```typescript

     // ...
   }, { retry: 2 }) // 失败时重试 2 次
   ```

### 4.3 长期方案（可选）

**测试架构优化**：

   - 串行运行路由测试

2. **Mock 路由**：
   - 使用更轻量的路由 mock
   - 减少真实路由实例创建

3. **测试环境优化**：
   - 增加 CI 资源
   - 优化测试并发策略
