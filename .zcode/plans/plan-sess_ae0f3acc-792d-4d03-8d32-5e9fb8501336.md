# TJG 前端整改计划（基于 2026-08-18 全面排查）

按优先级分三阶段推进；每项独立立方案（writing-plans）、独立验收，遵守项目守门命令全绿不恶化（vue-tsc / test:run / check:ratchet / check:sdk-boundary / quality:no-raw-fetch / check）。

## Phase 1 — P0 止血（1-2 天）

1. **NaiveProvider token 化**：15 处硬编码主题色改读 `--tjg-*` token，消除双 token 源。验收：该文件 grep 零 hex/rgb 命中，check:ratchet 通过。
2. **server_notifications 孤儿域处置**：二选一（默认方案 A）——
   - A. 删除整域死代码：`paths/admin.ts:39-45` 的 7 条路由常量、`MatrixServerNotificationService.ts`、`useServerNotifications.ts`、`ServerNotificationsPanel.vue` 及自动生成 typings（重新生成）。
   - B. 若产品需要该功能：先与 synapse-rust 后端对齐 `/notifications/*` 真实端点再挂载。
3. **裸 fetch 4 处定性收口**：`video.ts` blobUrl 与 `OpenClawView` AI 网关进 no-raw-fetch 白名单（或改走 utils 封装）；`App.vue:278` 连通性探测收敛到 utils；`useAvatarUpload.ts:123` 改走 MatrixMediaService 下载通道。
4. **capabilities.json 治理**：评估改为 CI 生成校验或 gitignore，消除反复脏工作区。

## Phase 2 — P1 SDK 收口 + 测试盲区（3-5 天）

5. **Manager 裸调迁移**（每域一个 PR + 单测，顺序按风险从低到高）：
   - presence（5 处 → `getPresenceManager`）
   - AI connection（6 处 → `getAIConnectionManager`）
   - spaceQueries `/spaces/search`（2 处 → `getSpaceManager`）
   - profile（4 处）、device（4 处）、SAML（4 处，注意 getter 名 `getSamlAuthManager`）
   - friend 2 处、messageQueryHelpers 2 处
   - `MatrixMessageService.sendTextMessage` 迁 SendingManager（或书面豁免理由入文档）
   - `MatrixAccountService` 的 getCapabilities//my_rooms//events 逐条定性：迁移或 JSDoc 豁免
6. **workers 最小测试**：优先给纯逻辑层 `workerClientHandlers.ts`、`workerSearchHandlers.ts`、`matrixWorkerTypes.ts` 补单测；worker 线程本体用 message-roundtrip 冒烟测试。
7. **admin 域收口评估表**：产出 6 个 admin 服务"方法 → AdminManager/sub-managers"映射表，判定可迁/需 SDK 补/保留 HTTP 层，作为后续批次输入。

## Phase 3 — P2 打磨（持续）

8. augmentations 弱类型重复声明清理（`getDirectMessageManager?: unknown` 等 4+ 个，统一走 SDK 官方强类型 getter），跑 `pnpm check:sdk-types`。
9. 公共组件批量替换：66 处裸 `n-empty`/`van-empty` → `EmptyState`；33 处裸 `n-avatar` → `TjgAvatar`（移动端补镜像组件）。
10. 硬编码色清零（FedStatusBadge/AdminFederationMonitor/LockScreen/MsgInput 等约 25 处）并纳入 ratchet 基线。
11. composables 4 处 `import type` SDK 收敛到服务层导出类型。
12. 空 catch 12 处逐一定性（补日志或显式忽略注释）；复查未读徽章 WCAG 对比度。
13. 逼近红线的 5 个 .vue（763/763/760/756/749）按职责预防性拆分，优先 registerWindow 与 AdminUsers。

## 执行方式

Phase 1 批准后即逐项以 writing-plans 出独立方案文档（`docs/superpowers/plans/2026-08-18-*.md`），再按 subagent-driven-development 执行；每项完成后跑全部守门命令取证。
