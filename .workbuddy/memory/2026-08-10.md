- `synapse-services/src/event_notifier.rs` — 提取 `notify_room_local`/`notify_user_local`（仅本地唤醒不回 Redis）；新增 `handle_redis_message`（跳过自回声 + 路由到 local notify）；新增 `start_redis_subscriber` + `subscribe_and_listen` 后台 Redis pub/sub 订阅任务；新增 4 个测试
- `synapse-services/src/container.rs` — `build_domains` 中当 `config.redis.enabled` 时自动创建 Redis pool 并调 `with_redis` + `start_redis_subscriber`，失败降级为本地通知

### 测试基线
- event_notifier 模块: 23 passed, 0 failed (原 19 + 新增 4)
- 全 synapse-services: 1422 passed, 1 flaky (media test，与 S8 无关)

### 关键设计决策
- 自回声抑制：`handle_redis_message` 检查 `sender_instance == self.instance_id` 跳过，避免本地 notify → Redis publish → 订阅回执 → 再 notify 的循环
- `notify_room`/`notify_user` 重构为 local + publish 两步，local 步骤被 Redis 订阅器复用（不触发二次 publish）
- 不改 `ServiceContainer::new` 签名：直接在 `build_domains` 中从 `config.redis_url()` 创建 pool，避免影响 60+ 个调用方
- Redis 不可用时降级为 `EventNotifier::new()`（纯本地通知），与 S6 的单实例模式完全兼容
