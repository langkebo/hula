### 09:50-10:05 徽章配色静默失效 + SyncStatusBar 声明未实现（本轮）

**修复的真实缺陷：**
1. **MessageLockBadge 三态配色完全失效**（最严重）。配色写成 `.msg-lock-badge__icon { &.msg-lock-badge--verified { color } }` → 编译为复合选择器 `.msg-lock-badge__icon.msg-lock-badge--verified`，要求两个类**同元素共存**；但模板把 `--verified` 放根 span、`__icon` 放 svg → DOM 中永不匹配 → 绿/灰/红三态**渲染成同一种颜色**（svg 的 `currentColor` 继承气泡文字色）。已改为根元素修饰类 `&--verified/&--unverified/&--risk` + svg `currentColor` 继承，`__icon` 显式不声明 color。
   - 用 `npx sass` 编译实证过选择器产物；`.msg-lock-badge__icon.msg-lock-badge--verified` 是最直接的铁证。
2. **外环定位逃逸**：`.msg-lock-badge--ring::after` 用 `position: absolute`，但根元素无定位上下文 → 外环会挂到最近的定位祖先（消息气泡/视口）。根元素补 `position: relative`。
3. **stories 类型逃逸**：`PlainMessage` 传 `trustLevel: 'plain' as never`，三态 `v-else-if` 全不匹配 → 渲染无图标的空徽章。改用真实支持的 `unverified`。
4. **SyncStatusBar 自动收起是「声明了没实现」**：`autoHideTimer` 声明后从未赋值、`onUnmounted` 清理它，注释承诺「CONNECTED 延迟 2 秒自动隐藏」但 `shouldShow` 只读 `props.isVisible` → 连上后「已连接」横幅**永久驻留**。已实现自动收起（卸载清理 + 状态变化重置 + 与外部 `isVisible` 分离的 `autoHidden` 标志）。
5. **SyncStatusBar 重试无防重复**：`isRetrying` 恒 `false`，`@click` 直接 `emit('retry')`。改为 `handleRetry` 加锁 + 状态离开 ERROR 解锁 + 8s 保护超时兜底。另移除死事件 `update:isVisible`（声明后从未 emit，全仓无消费方）。

**新增测试能力（可复用）：`MessageLockBadge.styles.test.ts`**
用 `sass.compileString`（sass 1.102.0 是 devDep，与构建同源）编译 SFC 的 `<style lang="scss">` 块，拍平成 `{selector, body}`，再挂载真实 DOM 收集每元素的 class 集合，**校验每条含 color 声明的选择器其 class token 是否可达**。
- 这套方法能捕获「class 断言全过、配色却静默失效」的纸面测试盲区，比正则断言强得多。
- 两个解析坑：sass 会保留注释；样式块含中文时会在顶部插 `@charset "UTF-8";` → 两者都必须先剥离，否则首条规则的 selector 带前缀导致查找失败。
- 断言范围要排除「其它等级」的规则：某等级挂载时其它等级的修饰类天然不在 DOM，属合法未激活而非缺陷。

**变异验证的一次重要教训（测试假绿）**
重试加锁用例最初写 `await trigger('click')` 连点三次断言只 emit 一次 —— 删掉组件内的加锁守卫后**用例仍然全绿**。根因：第一次点击后 `:disabled` 已渲染，后续点击是被 **DOM 的 disabled** 拦掉的，与守卫无关。
改为同一 tick 内直接 `dispatchEvent(new Event('click'))`（此时 disabled 尚未渲染）后，删守卫即 3 次触发 → 用例转红。
**结论：涉及「防重复点击/加锁」的用例，必须让重复动作发生在 DOM 状态更新之前，否则测的是 DOM 而不是守卫。**
