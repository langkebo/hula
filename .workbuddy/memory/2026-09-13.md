### ⚠️⚠️ 本轮最严重踩坑：共享索引被并发进程"卷走" staged 文件
- 我把 4 个 UI 文件 `git add` 进**共享暂存区**后，并发进程（langkebo，每 2-3 分钟一笔 `chore(config)` SDK pin 提交）执行 commit 时把这 4 个文件**一起打包进了它的 chore 提交**（`ce348635`）。我的 `git commit` 随后报 "no changes added"。
- **应对**：① 内容已在 HEAD、测试绿 → 不重写（活跃并发分支下 rebase 风险 >> 收益），接受"内容入、消息不专属"；② **之后每组 add 完立即 commit**，把共享索引暴露窗口压到秒级；③ commit 前先 `[ -f .git/index.lock ]` 探锁。
- **index.lock 处理纪律**：锁文件 mtime 是几十秒内 = 并发进程正在写，**绝不 `rm .git/index.lock`**（会破坏对方提交），轮询等待（3s×10）释放后再 add+commit。本次实测等 ~1 分钟即释放，且 `e0ed82f5` 未卷我文件。
