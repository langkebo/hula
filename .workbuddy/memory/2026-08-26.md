## 新沉淀易错点
- **vue-i18n 裸 `@` 会崩**：message 值里字面 `@` 必须转义为 `{'@'}`（或 `\@`），否则 `@` 后跟非 `.`/`:` 触发 `INVALID_LINKED_FORMAT`。排查口诀：渲染报 `Invalid linked format` → `grep -rn "@" locales/ | grep -v "{'@'}"` 找裸 @。
- **后端返回的 roomId 不可信**：DM 房间打开前必须校验本地 `getMyMembership()==='join'`，后端 friends/dm 可能返回当前用户非成员的 stale room。
- **`i18n.d.ts` 是 `scripts/generate-i18n-types.mjs` 自动生成**（`pnpm gen:i18n`），改 locales/*.json 后必须重跑同步。

## 修复：429 限流风暴 — 熔断器全局化 + key 粗化

**现象**：11:25 起持续近 3 分钟 nginx 429 限流风暴（`x-ratelimit-remaining: n/a` = nginx limit_req，非应用层）。涉及 tags/friends/presence/whoami/createRoom，连锁导致 createRoom 半成功（房间建了但 getRoom null）、whoami 429 误判 isAdmin=false、健康检查失败。

**根因**（三层）：①客户端房间列表刷新/建房间时 tags 遍历 + friends 三连 + presence + whoami 集中爆发，超 nginx burst；②拦截器对每个 429 独立重试 3 次形成 N×3 风暴；③**熔断器失效**——`endpointKey` = `${method} ${pathname}` 含房间 ID，每个房间的 tags 独立计数，单个房间达不到「连续 3 次 429」阈值，日志全程无「熔断」日志。

**修复**（`MatrixRateLimitInterceptor.ts`）：
1. **key 粗化**：`normalizePathname` 把 `%40xxx`（用户 ID）→`{userId}`、`!xxx`（房间 ID）→`{roomId}`、`%24xxx`（事件 ID）→`{eventId}`，让同类端点共享端点级熔断 key。
2. **全局熔断器**：滑动窗口 10s 内「每次调用最终 429」≥6 次即开路（感知跨端点全局限流，端点级熔断器对此失明），冷却 10s 起指数增长（最大 120s），成功响应复位。记录粒度是「调用结果」而非「内部重试」，与端点级熔断器正交，不干扰现有 callCount 断言。
3. 全局熔断检查在 `createRateLimitedFetch` 入口优先于端点级。

**验证**：msw.test.ts 17 项（+2 回归：key 归一化、全局熔断）+ interceptor 单测 7 项 + runtimeFetch 11 项全过；biome clean；vue-tsc 0 错误。

**易错点沉淀**：nginx 429（`x-ratelimit-remaining: n/a`）是**跨端点全局限流**，per-endpoint 熔断器对此失明——必须配「全局 429 滑动窗口熔断器」才能打断风暴。URL 编码规则：`@`→`%40`、`:`→`%3A`、`$`→`%24`，`!` 原样；`URL.pathname` 返回编码后的值。
