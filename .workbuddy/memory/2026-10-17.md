2. **to-device 是 `get_and_delete_messages`（读后即删）**（`synapse-e2ee/src/to_device/storage.rs:461`）——
   这是 Matrix 里**唯一天然接近 SimpleX 单向队列语义**的通道，且走 Olm 双棘轮（Megolm 没有 break-in recovery）。
   ⇒ 「服务端不留存」只能靠 to-device 兑现，不在房间事件上。
3. **`retention` 只开在 `/_synapse/admin/v1`**（`admin/retention.rs:15-22`），普通用户/房管**无法设房间 TTL**
   ⇒ 私密房间想承诺「N 天后消失」必须先加 vendor 端点（B-5）。

### 密码门的真实状态：部件齐全，三处断裂（关键，别再误判）
密码门**不是没做**，是**没接上**：

   → 用户设过密码，重启后点 S 图标必提示"请先设置密码"
2. `/secretChat` 路由**无 beforeEnter / 无全局守卫**（`router/routes/desktop.ts:186-190`），

### 房间模型现状

房间本身与好友房间完全同类，只是 UI 过滤。点击私密会话还会 `updateSession(roomId, { hide: false })`
把它还原成普通会话 → 语义混乱。

### P0-0 设计要点（已写入方案 §3）
- **房间分离**：`privateRoomRegistry`（account data `com.hula.private_rooms` + **本地加密缓存**同步判定）
  替代 `hide`；三处过滤必须同时改（普通列表 / 好友列表 / 搜索+通知），漏一处等于没分离。
  用 account data 而非房间 state，是因为 state 会让"该房间是私密的"对房间内所有人可见。
- **密钥先行**：Argon2id（或 PBKDF2 ≥600k）派生 32B，切两半：`verifier` 落盘（校验）、
  `dbKey` 仅内存（加密本地私密索引）。**dbKey 绝不落盘**，锁定时 `fill(0)` 清零。
  开启开关前置校验 `isSecretChatConfigured()`，未设密码直接抛 `SECRET_CHAT_PASSWORD_REQUIRED`。
- **硬门禁**：内存态 `secretChatSession{unlockedAt, dbKey, lastActivityAt}`（不持久化，重启即锁）+
  `/secretChat` 的 `beforeEnter` + `/chat/:roomId` 兜底（防直接打开私密房）+ 接线孤儿事件。
- **自动锁**：空闲 `lockTimeout` / 失焦（可选）/ 切后台（必须）/ 登出 → 清 dbKey + 停私密索引写入
  （否则锁着还在往盘里写明文索引）。
- **创建约束**：私密房强制加密、通知静音、不进搜索索引。

- **忘记密码可找回** —— dbKey 由密码派生，找回能力 = 后门

## P0-0 收尾：房间级兜底守卫 + 私密标记入口

### 关键认知：只在 `/secretChat` 加守卫等于没加
所有「进房间」的路径——好友详情发消息、搜索结果、通知点击、独立聊天窗口、
手输 URL——最终都汇到 **`/message/:roomId`**（桌面）与 **`/window/chat/:roomId`**（独立窗口）。
因此门禁必须挂在**具体房间路由**上，这才是「好友列表侧不展示私密房入口」的真正修法
（不需要逐个入口改）。

⚠️ 容易踩的两个坑：
1. **`/chat/:roomId` 在本仓不存在**（`/chat` 是机器人插件路由且无参数）。
   `SecretChatPage` 原来跳这个路径 → 落 notFound。正确写法是 `{ name: 'message', params: { roomId } }`。
2. **`/room/:roomId`（name `room-details`）是房间目录详情页**，不是聊天房间。
   守卫按 **route name 白名单**（`message` / `windowChat`）取 roomId，不能见 `params.roomId` 就拦。

### 冷启动深链的判据
`isPrivateRoom()` 读 localStorage 同步缓存，冷启动时 `getUserId()` 还是 null → 读的是
`anonymous` 缓存 → **私密房会被当普通房放行**（房间已渲染就遮不住了）。
修法：`ensurePrivateRoomRegistryReady()`（等 `waitForClientReady` → `loadPrivateRoomRegistry`），
**失败时把 readyPromise 置 null 以便重试**（一次性失败不该永久失去门禁）。
