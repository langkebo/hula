### 新缺陷
- **D13（P1 隐私）撤回不生效**：服务端 content 已清空 `{}`、timeline 有 `m.room.redaction`，
  但客户端 `event.isRedacted()=false` 且 `body` 仍是原文。
  根因方向：`MatrixMessageAdapter.getMsgTypeFromEventLike` 只把 redaction 映射成 `MsgEnum.RECALL`
  （额外一行「撤回」），**没有把被撤回的那条置为已撤回态**。
- **D14（P2）讨论串未启用**：`client.supportsThreads()===false`；服务端 `/relations…/m.thread` 有数据，
  客户端 `room.getThread(root)` 为 null ⇒ 无线程视图。
- **D15（P2 后端）房间版本能力声明与实际不符**：capabilities 列 v1–v12，但
  `createRoom(room_version=11)` 与 `upgrade`（→11/10/9/8）全 `400 M_UNSUPPORTED_ROOM_VERSION`；
  只接受 v12 ⇒ **房间升级在当前环境无法验证**（也无法建旧版本房）。
- **D16（P2 后端）不产生通知记录**：`/notifications` 恒空，即使消息含当前 displayname（提及）⇒ ack 无对象。
- **D12（P1 间歇）运行中整页 reload → client 置空 + 重弹本地解锁门禁**：页面停在 `/mobile/message`、
  `localStorage.matrix` 账号仍在，但 `getClient()=null`、`debug.initialized=false`，同时出现
  「输入本地解锁密码」。`runLocalUnlockPreflight` 只在 `onMounted` 调用一次 ⇒ 说明发生了整页重载
  （WebView 内存压力下重载），但 UI 无任何「已断开」提示。三轮复现 1 次。
  ⇒ 脚本加 `ensureClient()` 自愈（过弹窗 → 必要时重登），并把它记成断言 X1（次数 0 才算过）。

### 踩坑

  `noRoom` 分支里带上 `clientRooms/syncState/supportsThreads/href` 才能分清

## 第二十四轮：补测搜索与阅后即焚（#16 / #10）

### 结果：`scripts/search-burn-probe.mjs` → 18 passed / 0 failed / 0 skip
- 搜索三层都通：服务端 `POST /search`、客户端 `searchMessages`、`searchRoomMessages`
- 阅后即焚全链路通（enable → sendMessage 带 `m.burn_after_read.expires_in` → 接收方标记 →
  `burn_after_read_pending` 落行 delete-created=5000ms → 9s 后 `is_processed=t` → **不 redact**）

### 新缺陷 D17（P2 假安全信号）：burn 语义三端不一致
- 服务端 `burn_after_read_settings` 主键是 **(user_id, room_id)** ⇒ 每用户设置；
  `PUT /_matrix/vendor/v1/rooms/{id}/burn` 只改调用者自己的
- 实测：A 开启后 B 直接标记 → `400 M_BAD_JSON Burn not enabled for this room`；B 自己开启才 200
- 前端 `burnPolicy.ts` 注释与 `useSessionListState` 都按**房间级 state `m.burn_after_read`** 判定
  ⇒ 房主开启后成员看到「已开启」，实际不会焚毁
- 附：`markBurnRead` 对**自己**的消息必然 403（被服务层吞成 false），UI 侧应过滤自己的消息

### 两条"看起来是缺陷、其实是语义"的坑（写进脚本注释）
- `markBurnRead` 用发送方账号调用必然 false → 必须用**接收方**账号
- `searchRoomMessages` 返回 `{results,count,highlights}` 对象，不是数组（按数组取 length 会误报 0）
