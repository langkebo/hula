## 第二十七轮：D13 撤回落地（已修）

### 根因
room v11+ 服务端把 `redacts` 放在 **event.content**，vendored SDK `Room.tryApplyRedaction`
只读事件顶层 `event.event.redacts` ⇒ 目标事件不进入撤回态（`isRedacted()=false`）、原文残留。

### 修复
- `RealtimeService.applyRedaction`：`resolveRedactionTargetId` 同时读顶层与 `getContent().redacts`，
  命中后调用 SDK 公开 API `MatrixEvent.makeRedacted(event, room)`（清 content + 写
  `unsigned.redacted_because`，复刻服务端行为），再 `emit('recall')` → `updateRecallMsg` 立即改 UI。
- `stores/domains/chat/room/sync.ts`：`eventDecrypted` 分支对 `event.isRedacted()` 直接走撤回文案，
  不再用空正文覆盖（加密房「撤回先于解密」）。
- 历史/分页路径：`MatrixEventService.convertEventToMessage` 的 `isRedacted()` 分支产出 `RECALL` + 空 body（既有）。
- R1 合规：用 SDK 公开 API，未自研协议/未裸 fetch；SDK 侧缺陷（`tryApplyRedaction` 不读 content）建议同步上游。

### 验证
- 定向单测 3 文件 / 90 例全绿（`RealtimeService` + `MatrixEventService` + `chat/room`）；
  `pnpm vue-tsc --noEmit`、`pnpm check`、各守门命令通过（ratchet 仅并行 WIP 既有违规）。
- 实机探针（清 app 数据 + 重启）：`✅ [R3] 客户端标记为已撤回 — redacted=true`，汇总
  **20 passed / 3 failed / 1 skip**；R1/R2/R4/R5/X1 全绿。
