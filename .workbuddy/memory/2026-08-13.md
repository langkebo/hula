### 测试模式要点（复用价值高）
- **vi.hoisted 中不能用 ref**：hoisted 块执行早于 import。模式：hoisted 存普通 state 对象 + mock 工厂内用静态导入的 ref 包装
- **mock composable 层优先于 service 层**：组件只依赖 composable 契约，测试更稳定（如 useAdminNotices/useAdminRetention）
- **stub URL 需保留构造器**：`vi.stubGlobal('URL', class extends OriginalURL { static createObjectURL = ... })`，否则 happy-dom 锚点 click 导航报 "URL is not a constructor"
- **IntersectionObserver 需 stub**：happy-dom 无此 API，`vi.stubGlobal('IntersectionObserver', StubClass)`
- **NDescriptionsItem 的 label prop 需在 passthrough mock 中显式渲染**
- ModerationRouteAlignment.test.ts 是 2.6s 慢测试（动态导入整个 desktop 路由模块），批跑时可能超时——既有 flake，与本次无关
