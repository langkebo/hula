## BUG 修复：头像点击完全不弹（回归）
- **现象**：重启后用新代码，点击主界面消息头像无弹出。
- **根因**：P2-9 新增的 `ref="rootEl"` 挂在 `<n-flex>` **组件**上（非原生元素），`onMounted` 里 `nextTick(() => rootEl.value?.focus())` 拿到的是组件实例、无 `focus()` 方法 → 抛 `TypeError: ...focus is not a function`。该错误发生在 popover 内容挂载的 nextTick 中，打断 n-popover 进入过渡，弹层停在隐藏态 → 表现为"点了没反应"。
- **修复**：取组件实例的 `$el` 真实 DOM 根再 focus：`const el = (rootEl.value as {$el?:HTMLElement}|null)?.$el ?? (rootEl.value as HTMLElement|null)`。
- **验证**：新增 `src/components/common/__tests__/InfoPopover.render.test.ts`（happy-dom 挂载冒烟），确认挂载自身/他人 uid 不再有未捕获错误；`biome check` clean。
- **教训**：`<script setup>` 中 `ref` 绑在组件上得到的是组件实例（public instance），不是 DOM 元素；要操作真实 DOM 必须走 `.$el`（或给原生元素绑 ref）。

### #6 P2 原生 fetch `resource id invalid` ★ 本轮最有价值发现
- **根因（查 node_modules 源码确认）**：Tauri plugin-http 用 Rust **资源表(rid)** 管理在途请求：
  `invoke('plugin:http|fetch')→rid` → signal abort 触发 `fetch_cancel(rid)` **丢弃资源** → 后续 `fetch_send(rid)`/`fetch_read_body(rid)` 抛 `"resource id invalid"`；插件另有分支直接抛普通 `Error("Request cancelled")`。
  **二者本质是"请求被主动取消"，不是网络故障，且 name 都不是 AbortError。**
- **暴露的真实缺陷**：`runtimeFetch.ts` 的 catch 对**任何** nativeFetch 异常都无条件回退浏览器 fetch → 被 SDK 主动取消的 `/sync` 长轮询会被**重新发出去（幽灵重复请求）且返回 ok:true**；`fetchWithRetry` 也不检查 `signal.aborted`，会继续 200/400ms 退避重试；错误未归一化导致 matrix-js-sdk sync 循环误判网络异常进入错误退避。
- **修复**：新增 `isSignalAborted(init)` + `createAbortError(url)`（优先 `DOMException(...,'AbortError')`）。三处拦截：nativeFetch 调用前预检、catch 内先于日志/回退判断、`fetchWithRetry` 循环首尾。取消时不打噪声日志、不回退、不重试。
- **测试**：`runtimeFetch.test.ts` 加 4 例（含 1 例回归守护：无 signal 的真实网络故障仍需回退+重试），10/10 通过。
