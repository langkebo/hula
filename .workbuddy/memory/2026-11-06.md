## 第十五轮：§7 六项未覆盖项实测收口 + 发现 BE-12（阻断级）

### 关键发现 1：BE-12 —— 事件 `content` 撞 btree INCLUDE 上限（后端未修）
- 索引：`CREATE INDEX idx_events_sync_covering ON events USING btree (room_id, stream_ordering DESC)
  INCLUDE (event_id, sender, event_type, content, origin_server_ts)`
- Postgres btree v4 **单索引元组上限 2704B（压缩后）**，`content` 进 INCLUDE ⇒ 超了直接 INSERT 失败
- 复现（决定性）：账号 33 个好友时 `pg_column_size(content)=2510`（贴红线），**第 34 个 accept 必 500**
  日志：`index row size 2728 exceeds btree version 4 maximum 2704 for index "idx_events_sync_covering"`
- **不止好友**：2600B 不可压缩随机文本消息也 500 ⇒ **消息正文约 2.5KB 即硬上限**，且报 500 M_UNKNOWN 而非 413
- 之前「20KB 重复字符能发」是假象：判定用**压缩后**大小，重复字符压缩比极高
- 推断（未实测）：`m.room.encrypted` 密文 base64 近不可压缩 ⇒ 约 1.9KB 明文即越界 ⇒ **E2EE 补测前必须先修**
- `m.friends.list` 是好友列表**全量快照**（每人 +264B），每变一次写一条事件 = 体量绑好友数
- 修复建议：把 `content` 从 INCLUDE 去掉（回表）；插入路径把该 sqlx 错误映射成 413 M_TOO_LARGE

### 关键发现 2：「重型用例假红」不是 timeout，是沙箱 fs shim
- 现象：`src/mobile/views/chat-room/__tests__/**` 整目录并行时 4 例红，**失败在 90s（远未到 240s）**
- 异常：`Error: connect failed: Connection refused` @ `node-brokered-fs-shim.cjs:368`
- 根因：`NODE_OPTIONS=--require …/node-language-shim.cjs` + `CODEBUDDY_BROKERED_FS_HOOK_ENABLED=1`
  把每个 `readFileSync` 变成 broker IPC；并行度高时 broker 拒连 ⇒ **导入模块就抛错**（不是断言失败）
- 关钩子对比（同一命令，只加环境变量）：
  - 带钩子：8m10s，81 文件 / 750 例，4 例红
  - `CODEBUDDY_BROKERED_FS_HOOK_ENABLED=0 NODE_OPTIONS= `：**34.13s，81 文件 / 766 例全绿**
  - 单文件：90s → 6s（14×）
- 结论：**调 timeout 治不了**；已在 §19.6 加更正、改 `vitest.config.ts` 注释（含命令）
- 日常批量跑单测建议直接带这两个变量
