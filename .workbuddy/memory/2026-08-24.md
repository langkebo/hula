## synapse-rust 编译拦截修复（方案选单构建失败）

- **根因**：`src/web/routes/e2ee/backup.rs` 中 `verify_secure_backup_passphrase` 被工作区改动从 `async fn` 改为同步 `fn`。axum 0.8 要求路由 handler 返回 `Future`（满足 `Handler` trait），同步 `fn` 不满足 → `all-extensions` feature 下编译失败（E0277: `Handler<_, _>` is not satisfied），拦截「方案选单」构建，服务自动回滚到旧镜像。
- **修复**：恢复 `async fn`（还原工作区改动至已提交版本）。`cargo check --features all-extensions` exit=0。
- **验证**：反向验证——临时改回 sync `fn` 复现 E0277 错误（keys.rs:48 `.route(... post(verify_secure_backup_passphrase))`），确认根因。
- **无需提交**：文件恢复后与已提交版本一致，`git diff` 为空。其余 synapse-rust 未提交文件（leak_detection/friend_room_service/extensions 等）属其他任务。

## SSSS bootstrap 超时修复（客户端）

- **现象**：运行时日志显示 `bootstrapSecretStorage(SSSS) 后台失败 (15001ms)`——15s 超时后失败。
- **根因**：matrix-js-sdk 的 `bootstrapSecretStorage` 内部 `setDefaultKeyId` 上传 `m.secret_storage.default_key` account_data 后，等待 `/sync` 回送 AccountData 事件才 resolve。客户端使用 sliding sync（pollTimeout 15-30s），传统 `/sync` 的 long-poll 周期可能需要 30s+，15s 超时必定不够。
- **服务端确认**：synapse-rust `/sync` 响应**确实包含** account_data 事件（`get_account_data_events` → `list_account_data` 无过滤），根因不在服务端。
- **修复**（`CryptoKeyBackupAdapter.ts`，commit `e440b089`）：
  1. SSSS bootstrap 超时 15s→45s（覆盖至少一个 sync long-poll 周期）
  2. 超时后用 `getAccountDataFromServer('m.secret_storage.default_key')` 直接 REST GET 验证密钥是否已上传——PUT 请求在超时前已成功，只是 sync echo 未及时到达
  3. `resetKeyBackup` 超时同样 15s→45s
