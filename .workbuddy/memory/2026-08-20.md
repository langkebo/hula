## #3 好友/加密聊天按钮不跳转（已修复，commit c0045616）

### 根因
好友聊天（send_message）/加密聊天（encrypted_chat）/SingleDetails 加密按钮都走 `openMsgSessionByRoomId(roomId)` → `focusSessionRoom`，该路径**只靠 `getSessionList` 轮询（1500ms）拉 session，不预加载**。

而消息视图切换会话依赖 `chatStore.currentSessionInfo`（message.ts:123）= `sessionStore.getSession(globalStore.currentSessionRoomId)` —— **必须 chatStore 里存在该 room 的 session**。降级/慢同步/DM 管理器未就绪时，新 DM room 没进 session 列表 → `getSession(roomId)` undefined → `currentSessionInfo` 空 → `watch(currentSessionInfo)` 不触发 → 会话视图不切换，用户感知「按钮点了没跳」。

对比：搜索栏 `openMsgSession(uid)` 先 `getSessionDetailWithFriends` + `addSession` 预加载，所以稳。两者差异即根因。

### 修复
`focusSessionRoom` 在轮询超时仍无 session 时，兜底 `matrixSessionService.getSessionDetailWithFriends(roomId)`（string 默认按单聊查）+ `chatStore.addSession`，确保 `currentSessionInfo` 派生。

## #5 设备列表过多（已修复，commit 57b3b717）

### 根因
密码登录 `MatrixClientAuth.login` 与 SSO 登录 `completeSSOLogin` 调 `loginRequest`/`login` 时**不传 device_id**，Matrix 服务器每次生成新设备；登录后 deviceId 只存 Pinia store 内存，**不持久化**。只有 token 登录 `loginWithToken`（Issue 5）通过 whoami 预解析收敛。→ 每次密码/SSO 登录在服务器端累积一个新设备。

### 修复（TDD 红→绿）
- 新增 `src/services/matrix/deviceIdPersistence.ts`：localStorage 持久化 deviceId（key=`tjg.persistedDeviceId:<登录标识>`，密码登录用 username、SSO 用完整 userId）。
- `login`：登录前复用 `config.deviceId ?? getPersistedDeviceId(username)` 传 `device_id`；登录后 `persistDeviceId(username, device_id)`。
- `completeSSOLogin`：登录后 `persistDeviceId(user_id, device_id)`。

### 守门
- biome clean · vitest 70/70（MatrixClientAuth 27 + slidingsync + spec）· vue-tsc 0 error · husky 正常通过。

### 备忘
- password/SSO 登录前无 access token，无法走 whoami 预解析（whoami 仅 token 登录有效），只能靠本地持久化 deviceId。
- **全部 5 个待办（#1~#5）已闭环**。
