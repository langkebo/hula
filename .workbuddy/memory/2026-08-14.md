# 2026-08-14 工作日志

## 导航栏问题修复（commit e11b8809）

### 用户报告的问题
1. 导航栏没发现 🔧 管理员按钮
2. 点击导航栏更多-设置没反应（Tauri 端）；WEB 端能展示但出现重复导航栏

### 根因分析
1. **🔧 按钮不显示**：`canAccessAdmin = isAdmin && isLoggedIn`，但 `isAdmin` 初始 false，`checkAdminStatus()` 只在路由守卫（访问 /admin）时触发，登录后从未主动检测 → 按钮永远不显示
2. **重复导航栏 + Tauri 没反应**：上一轮把 `/settings` 从顶级路由误移到 `homeWindow` 的 children（center 栏）。而 `SettingsPage` 的 `standalone=false` 时会自己渲染 `LeftNav = @/layout/left/index.vue`（主布局左导航），导致 layout 已渲染左导航 + SettingsPage 又渲染一个 = 重复；Tauri 端 center 栏嵌套 LeftNav 导致渲染问题

### 修复
1. **回滚 /settings 到顶级路由**（desktop.ts）：删除 children 里的 /settings，恢复顶级 `{ path: '/settings', component: SettingsWindow }`。原始架构本就正确——SettingsPage 顶级路由时 standalone=false 自渲染 LeftNav+Sidebar+Content 三栏，不重复
2. **ActionList.vue onMounted 主动调用 `adminStore.checkAdminStatus()`**：初始化 isAdmin 状态，登录后即检测（5min 缓存，见 ADMIN_CHECK_INTERVAL）
3. **ActionList.test.ts** mock 补 `checkAdminStatus: vi.fn()`

### 关键教训
- **SettingsPage 不是 center 栏子组件**：它设计为「顶级路由 + 自己渲染 LeftNav」，`standalone` prop 区分独立窗口(label='settings') vs 主窗口内嵌。绝不能放进 layout 的 center 栏
- **设置页"三栏展示"是原始架构自带的**（LeftNav+Sidebar+Content），无需改路由，之前是误判
- `checkAdminStatus` 有 5min 缓存（ADMIN_CHECK_INTERVAL），不会频繁检测；`canAccessAdmin` 依赖它，需在导航挂载时主动触发
- 管理员检测走双通道：checkAdminViaFrontend（adminService.getUser）+ checkAdminViaBackend（TauriCommand.CHECK_ADMIN_STATUS），浏览器 dev 模式（无 Tauri runtime）只走前端校验

## 🔧 按钮仍不显示（commit b9bf8712）

### 诊断过程（admin/Admin@123 账号）
1. 后端验证：curl 登录 admin → JWT 里 `"admin": true`；`GET /_synapse/admin/v1/users/@admin:matrix.test` 返回 `{"admin": true}` → **后端 admin 账号确实是管理员**
2. 根因是**前端时序**：matrixStore 的 `userId` 初始 null 且**不持久化**（无 pinia persist），通过 login 流程异步设置。ActionList 挂载时若 userId 未就绪，`checkAdminStatus` 里 `if (!matrixStore.isLoggedIn) { isAdmin=false; return }` 提前 return 且**不重试**（lastCheckedAt 不更新）
3. 之前 onMounted 只调用一次 checkAdminStatus，时序不巧就永远 false

### 修复
- ActionList.vue 加 `watch(() => matrixStore.isLoggedIn, ...)`，登录态从 false→true 时重试 `checkAdminStatus()`
- 测试 mock 补 useMatrixStore（isLoggedIn: false）

### 关键数据（后端）
- 默认 admin seed：`migrations/00000000_unified_schema_v10.sql:4471` 创建 `@admin:localhost`（is_admin=TRUE）；但实际 `VITE_HOMESERVER_URL=https://matrix.test`，userId 是 `@admin:matrix.test`（数据库中该域名下 admin 也是 TRUE，JWT 已证实）
- synapse-rust 标准注册端点故意忽略 admin 字段（auth_compat.rs:86-88），普通注册用户 is_admin=false，管理员需 `/_synapse/admin/v1/register` 或数据库改字段
