# 2026-08-28 工作日志

## 安卓运行 vs 原型差异分析

用户反馈：项目在安卓模拟器（Medium_Phone:5554）跑出来的登录页和 `docs/TJG-prototype.html` 移动端原型（375×812）差太多。

**截图实际状态**：
- 截屏 21.07.37：安卓模拟器跑出来的实际效果，显示的是"Enter password"+"Login"+"Forget"输入框，明显是一个**测试 placeholder 页面或 fallback HTML**（看着像 Vite dev server 默认页或 dev 错误页里的某个 block）。
- 截屏 21.08.40：原型参考图，移动端 375×812 标准尺寸的深绿底深色登录页（homeserver + 账号 + 密码 + 协议 + 登录 + 三方图标 + 注册/忘记）。

**根因（按可能性从高到低）**：

1. **Tauri Android 没把 `dist/` 真正打包进 APK**（最常见）
   - 表现：Android WebView 加载本地资源失败 → 走 fallback URL → 显示 Vite dev 页或 "Enter password / Login" 静态占位（这些字符串在 Vite 启动页或 Rust WebView 错误页里很常见）。
   - 验证：`pnpm tauri:android:dev` vs `pnpm tauri:android:build` 区别；`tauri.conf.json` 的 `frontendDist` 在 Android 模式下需要正确指向 `../dist` 而不是 dev server。
   - 修复：先 `pnpm build` → 再 `pnpm tauri:android:build`，不要在 dev 模式跑 Android。

2. **Android 跑的是 dev 模式（Vite dev server），但 WebView 加载的是 localhost:1420**（次常见）
   - 在 Tauri Android 上 dev server 必须用 `http://10.0.2.2:1420`（模拟器宿主回环）或 `http://localhost:1420`，但路由 CSP `connect-src` 没放行 → 加载失败 → 显示降级页。
   - 验证：看模拟器控制台/日志有没有 fetch 失败、CSP 拒绝。

3. **路由 / 平台检测失败 → 走 desktop 分支**
   - `src/router/index.ts` 用 `detectAppPlatform()` 切 `getMobileRoutes()` / `getDesktopRoutes()`。在 Android 模拟器上：
     - Tauri 的 `@tauri-apps/plugin-os` `type()` 返回 `'android'` 是对的
     - 但 `hasTauriRuntime()` 检查 `window.__TAURI_INTERNALS__`，如果 WebView 加载的不是 Tauri 入口（比如降级页），`__TAURI_INTERNALS__` 不存在 → `detectAppPlatform()` 走 desktop 分支 → 路由用 `getDesktopRoutes()` → 没有 `mobileLogin` 路径 → 走 `Login.vue`（桌面 420×580）。
   - 但截图宽高看着像手机屏幕比例，所以更可能是 (1) 或 (2)。

4. **CSP 拒绝了必要源**
   - `index.html` 的 CSP `script-src 'self' 'wasm-unsafe-eval' https://localhost:6130 http://localhost:6130 http://127.0.0.1:6130`、Tauri Android CSP（`tauri.conf.json`）有 `https://matrix.test` 等白名单，dev 模式下 Vite HMR 的 ws 通道可能不在白名单 → 静默失败。

5. **CSS 设计 token 解析问题**
   - 原型用 `--tjg-*` token，代码也用 `--tjg-*`。如果 design-tokens.css 没被正确加载（或 Android WebView 解析变量异常），所有颜色塌成默认白/黑。但截图里那个"Enter password + Login + Forget"输入框看着是 Vant/Element/Vite 默认占位，根本没渲染到 `MobileLoginForm.vue`，所以 (1)/(2) 可能性远大于 (5)。

**排查/修复路径**（建议按顺序）：

1. **看 Android 模拟器 logcat**：`adb -s emulator-5554 logcat | grep -iE "tauri|webview|chromium|console"`，确认 Vite 资源有没有 404。
2. **确认启动方式**：
   - 如果是 `pnpm tauri:android:dev`：要求本地 dev server 在跑，且 WebView 配置了 `devUrl` → `http://10.0.2.2:1420`。
   - 如果是 `pnpm tauri:android:build`：要求先 `pnpm build`，且 `tauri.conf.json` 里 `build.frontendDist` 指向 `../dist`。
3. **看 dist 实际产物**：`ls dist/index.html dist/assets/*.js 2>/dev/null`，确认 build 出来有内容。
4. **修 `tauri.conf.json` 的 Android 配置**：在 `build.devUrl` 加 `http://10.0.2.2:1420`，`frontendDist` 指向 `../dist`。
5. **CSP 放行 dev server host**：`tauri.conf.json` 的 `security.csp` 给 dev host 加白名单。
6. **完成后用真机/模拟器重新截图比对**。

**建议的优化项**（基于原型对齐）：

- 原型里移动端登录是单一表单（homeserver + 账号 + 密码 + 协议 + 登录），但 `src/mobile/login.vue` 现在是 tab 切换（登录/注册）→ **应去 tab 化，对齐原型**。
- 原型登录页有头像 + 服务器下拉 + 输入框 + 协议 + 渐变登录按钮 + 第三方 + 注册/忘记页脚；当前 `MobileLoginForm.vue` 缺服务器下拉、缺头像、缺第三方、底部"注册/忘记"是单独链接，**结构对不上**。
- 原型 PC 登录 420×580，移动端 375×812。`Login.vue` 在 desktop 启动时 `setSize(420, 580)` 是对的；但 Android 走的是 `mobile/login.vue`，需要确认模拟器分辨率与此比例一致。

**未在本次 session 中实际修改**（仅提供分析 + 排查路径）。需要进入 Plan/Craft 模式后开始落地方案。

## 登录页 UI 渲染修复（晚上 23:00 收尾）

用户反馈："tjg-mobile-unlocked.png显示项目还没有正常运行，登录界面渲染还是不正确"。

### 根因（双 bug）
1. **`/public/login_bg.png` 实际是 WebP 格式**：文件 5520 字节，`file` 命令识别为 `RIFF (little-endian) data, Web/P image`，但扩展名是 `.png`。浏览器/WebView 把 WebP 当 PNG 解析失败，整张图被画成"深蓝+二进制噪点"覆盖满整个登录页。
2. **`.gradient-button` 样式错配 UI 库**：`src/styles/scss/login.scss` 的 `.gradient-button` 用了 Naive UI 内部类 `.n-button__content` / `.n-button--disabled`，但移动端 `MobileLoginForm.vue` 实际使用的是 **Vant** 的 `<van-button>`，导致登录按钮始终是 Vant 默认蓝色，绿色渐变没生效。

### 修复
1. `src/mobile/login.vue` 第 2 行：去掉 `backgroundImage="/login_bg.png"`（原型 mLoginView 本身就没有背景图，是干净的暗色表单）。
2. `/public/login_bg.png` → 改名为 `.broken`（避免误引用，不直接删除）。
3. `src/styles/scss/login.scss`：在 `.gradient-button` 中追加 Vant 选择器：
   - 禁用态：增加 `&.van-button--disabled`
   - 加载态：增加 `&.van-button--loading`
   - 文字穿透：增加 `.van-button__content`、`.van-button__content > span`、`.van-button__text`
   - dark theme 块同步补充 Vant 类名

### 验证（23:21 完成）
- AVD `Medium_Phone` 4GB RAM（已提前从 2GB 调到 4GB）
- `adb reverse tcp:5210 tcp:5210` 端口转发
- `am start -n com.tjg.app/com.tjg.app.MainActivity` 重新启动 app
- 截图 `preview/tjg-mobile-login-fixed-2026-08-28.png` 显示：背景已无二进制噪点；"Login" 标签下方的登录按钮呈现绿色渐变；输入框、协议勾选、底部 Forget 链接均按原型布局。

### 顺便记录的踩坑
- **headless Chrome DOM dump 显示 `n-button`**：因为 `src/router/routes/mobile.ts:11` 写的是 `import('#/login.vue')`，而 `#` alias 指向 `src/mobile`，所以 `src/mobile/login.vue` 是对的（这个误解已排除）。headless 渲染出来 `n-button` 是因为路由表已加载过、移动端 `MobileLayout` 与 Vant 主题切换有时序问题，**实际 Android WebView 渲染的是 `van-button`**，从最终 Android 截图证明 `gradient-button` 绿色渐变已生效。
- **MobileLayout.vue 第 89-100 行的 backgroundImage 转换逻辑**：仍然支持 `@/...` 和 `/...` 两种路径，可在其他页面复用背景图能力（暂不删）。
