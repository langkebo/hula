### P0-4/5 私密模式文案：只描述已实现行为
`usePrivateMode.privateModeFeatures` 从 4 条压到 3 条：

| 原 | 现 |
|---|---|
| 端到端加密 / 仅收件人可解密 | 消息由端到端加密保护（**仅房间成员**；群聊不是「仅收件人」） |
| 阅后即焚 / 阅读后即删除 | 可为消息设倒计时，**到期仅在本机移除显示** |
| 防截屏 / 启用截屏水印与防截屏保护 | 桌面端检测到截屏时提示并发送房间提醒（**不能阻止截屏**） |
| 不留存 / 服务器不存储消息内容，仅传输 | **整条删除**（零实现） |

**结构性缺陷一并修**：这批文案原来是**硬编码中文**（英文界面漏中文），且与 `ChatHeaderRoot` 的
i18n 版本各写一份、内容不同。现统一成 i18n key（`textKey`），`ChatModals` / `PrivateModeConfirmDialog`
都走 `t(feature.textKey)`；删掉 `private_mode_feature_no_retention` 键；
`private_mode_confirm_desc` 补「服务端仍按保留策略保存消息」。

`PrivacyOverlay.vue` 里的「此聊天受保护，禁止截图」是**死代码**（`LayoutRegression.test.ts` 已断言不渲染），未改。

### P0-6 焚毁文案
- `chat.burn.message_destroyed`：此消息已销毁 → **此消息已在本机移除**
- `chat.burn.destroyed`：已销毁 → **本机已移除**

依据：后端只登记 per-user 时间、永不 redact。发送端闭环（`BURN_MESSAGE_READ` 无监听）归 P1。

### P0-7 全局 burn 开关接线
新增 `composables/chat/burnPolicy.ts` 的纯函数 `resolveBurnAfterRead(roomEnabled, globalDefault)`，
`useMsgInput.isBurnAfterRead` 改为调它。
**为什么抽函数**：这段逻辑埋在 400+ 行 composable 里，正是「只读房间级、设置开关只写不读」
能长期没被发现的原因；纯函数 + 单测能锁住「两个来源都要看」。
变异自证：`return roomEnabled` → 「房间未开启时全局默认生效」用例失败。
