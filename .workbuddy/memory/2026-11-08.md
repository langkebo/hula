### 结论 2：上一轮归因要纠正
- `attempted=true / initialized=false / error=null` = **挂起**（initRustCrypto 未 resolve），不是失败
- 抢资源（16G 只剩 70MB）只是加剧；真正卡点是 D9

### 新缺陷 D9（P1 沉默失效）：登出→登录（同页）后 client 与 crypto 脱钩
- 现象：登出后立刻登录新账号 → `getClient().getUserId()` 仍是旧账号、`getCrypto()`=null，
  但 `getRustCryptoDebugState()` 报 `initialized=true`；服务端 180s **无任何 `/keys/*`**
- 根因方向：debug state **无账号维度** + `ensureCrypto` 的「已就绪即跳过」只看本 client
- 规避（已写进脚本）：登出后**必须 reload** 再登录（`logoutAndReload`），加上即 36/0
- 另外：清 `localStorage.matrix` **不足以**切账号 —— token 在 Rust/SQLite 侧，reload 仍会恢复旧会话

### 新缺陷 D10（P1 功能不可用）：SAS 缺 startVerification + verify
- `startSasVerification` + 对端 `acceptVerification` 后，两端 `getSasView()` 永远抛
  `has not started a SAS method yet` → 再抛 `has no SAS available`
- 根因：`getSasView()` 只读 `verifier.getShowSasCallbacks()`，SDK 要 `request.startVerification('m.sas.v1')`
  再 `verifier.verify()` 才产出 SAS；**全仓 grep 仅单测命中，生产代码没有这两步**
- 实测（脚本直接调 SDK）：服务端立刻出现 `request→ready→start→accept→key`，协议层通；
  但两端 `verify()` 80s 未 resolve，一次 B 端 `m.timeout` ⇒ 还需继续定位

### 新缺陷 D11（P2）：验证事务不清理
- 残留 transaction 仍在 `getPendingVerifications()`；按「取第一条」会**接受旧事务**（踩过两次）
- 脚本已改：开始前 `reset()+initialize()`，且严格匹配 txId（不做 `seen[0]` 兜底）

### D2 精确化（Android 凭证不持久）
- 两处 fallback 都只认 `$HOME`，Android 进程无 `HOME`：
  - `src-tauri/src/utils/secure_store.rs:37-40` → `Cannot determine fallback path`
  - `src-tauri/src/utils/crypto.rs:36-40`（master-key 同一写法）
- logcat 直证：`set_password returned Ok but get_password returned NoEntry (macOS dev mode ACL issue)`
  + `Both keychain and fallback failed`
- token 本身存 SQLite（`user_service.rs` 的 save_tokens/get_tokens，密文用主密钥）⇒ 主密钥取不到
  ⇒ 解密失败 ⇒ 会话恢复失败。`session-persist-probe.mjs` 实测冷启动回 `/mobile/login`
- 修法：fallback 根目录改用 Tauri app data dir（`secure_store::get_service_name()` 已在读
  `TJG_PROFILE_DIR`，但 fallback 路径没读）
