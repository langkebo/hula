## 追加：refreshToken 移出应用状态（commit `a926e8c2`，AR-07b B1 收尾）

**结论**：`matrixStore.refreshToken` 是 accessToken 之外第二份凭证副本，且
`MatrixTokenManager.refresh()` 成功后**不回写**它 ⇒ 续期一次即陈旧（潜伏缺陷）。
现改为「随登录结果传递」，删除 ref 与 `port.getRefreshToken()`。

**关键设计**：
- `port.matrix.{login,registerGuest,completeSSOLogin}` 返回 `LoginResult`（原为 boolean），
  这三个只在 `SessionLoginService` 被调用；`loginWithToken` 保持 boolean（恢复路径调用方已有 token）
- `SessionBootstrapService` 的运行时 token 分支**本就不可达**：它在 `getClient()===null` 时执行，
  而 B1 起 accessToken 直读 SDK client ⇒ 该分支永远拿不到值。直接读 `getStoredTokens()`

**又一个自洽桩**（累计第 5 例）：`SessionBootstrapService.test.ts` 的
「uses runtime access token when available」在 `getClient()===null` 下断言运行时 token 可用，
是测试替身自造的假场景。已改为「即便 port 谎报 token 也必须读存储」。
⇒ 教训：**mock 出来的状态要先问「生产能不能产生」**，否则测的是替身不是系统。

**TypeScript 细节**：`LoginResult` 从 `@/services/matrix/MatrixClientService` 再导出（第 27 行），
store 与 port 都从这里取；`sessionRuntimeInternal.ts` 已 import `MatrixClientConfig` 同源，加一个类型即可。

**变异自证（双向）**：store 不回传 refreshToken → store 用例红；SessionLoginService 忽略返回值
→ `update_token` 断言红。注意 `MatrixRuntimeSessionService.test.ts` 用的是**替身 port**，
改真实 store 不会让它变红 —— 这类跨层契约必须两头各有断言。
