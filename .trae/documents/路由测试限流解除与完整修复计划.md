#### D1：提交 P0/P1 修复（已完成，仅提交）

#### D2：修复 v3 download 401（MEDIA-401）
- **文件**：`src/web/routes/media/download.rs`
- **根因**：`download_media`（L264）和 `download_media_with_filename`（L275）使用 `AuthenticatedUser` 提取器，Axum 在提取失败时返回 401
- **修复**：
  - 将 `download_media` 的 `auth_user: AuthenticatedUser` 改为 `auth_user: OptionalAuthenticatedUser`
  - 将 `download_media_with_filename` 同样改为 `OptionalAuthenticatedUser`（此 handler 当前无 auth 参数，需确认是否已公开）
  - 保持 `download_media_authenticated`（L328，`/_matrix/client/v1/media/download`）使用 `AuthenticatedUser`（此路由应强制认证）
  - 保持 `download_media_signed`（L285，签名下载）不变
- **验证**：运行 `api_media_routes_tests` 套件，8 个失败应转为通过

#### D3：修复 P2 VULN-06（account/profile 公开访问）
- **文件**：`src/web/routes/account_compat.rs`
- **修复**：将 profile 查询 handler 的认证提取器改为 `OptionalAuthenticatedUser`（若已是则不变），在无 token 时返回精简 profile（仅 displayname/avatar_url，不返回敏感字段）
- **文档**：在漏洞修复清单中标注为"设计行为 + 已加固"

#### D4：修复 P2 VULN-07（spaces/public 公开访问）
- **文件**：`src/web/routes/space.rs`
- **修复**：确认为设计行为（端点名含 "public"），在漏洞修复清单中标注为"设计行为"
- 若需加固：添加 optional auth，无 token 时限制返回数量

#### D5：修复 P2 VULN-08（msc4108 rendezvous 限流）
- **文件**：`docker/config/rate_limit.yaml` + 可能的 `src/web/routes/msc4108_rendezvous.rs`
- **修复**：在 rate_limit.yaml 中为 `/_synapse/external/` 和 `/_matrix/client/unstable/org.matrix.msc4108/` 添加专用限流规则（如 10/s burst 20）
- **验证**：无 token 高频请求应返回 429

#### D6：修复 R3（register admin 支持）
- **文件**：`src/web/routes/auth_compat.rs`（register handler）+ 文档
- **分析**：标准 `/_matrix/client/v3/register` 的 `admin: true` 字段被忽略（L86-91 仅调用 `register_user` 不传 admin）。Matrix spec 不要求标准 register 支持 admin 标志（安全考虑）。
- **修复方案**：
  1. 确认 `/_synapse/admin/v1/register`（shared secret + nonce + MAC）正常工作（admin/register.rs 已实现）
  2. 在 register handler 中显式忽略 `admin` 字段并记录日志（防止客户端误设）
  3. 更新文档说明 admin 账号必须通过 shared secret 端点创建
  4. 在测试报告中更新 R3 状态为"已文档化 + shared secret 端点可用"

#### D7：修复 R6（capabilities 可选认证）
- **文件**：`src/web/routes/handlers/versions.rs`（`get_capabilities` 函数）
- **现状**：已使用 `OptionalAuthenticatedUser`，但无 token 时返回全部能力
- **修复**：在 `get_capabilities` 中检查 `auth` 是否有值：
  - 有 token：返回完整 capabilities（含 unstable_features、内部版本）
  - 无 token：返回精简 capabilities（仅 stable room versions、无 unstable_features）
- **验证**：无 token 请求不应返回 `io.hula.friends` 等内部特性标志

#### D8：实现 login 失败锁定
- **文件**：`src/web/routes/auth_compat.rs`（login handler）+ 新增存储/计数模块
- **修复**：
  1. 在 login handler 中，密码验证失败时记录失败次数（key = IP + username）
  2. 使用 Redis 计数器（已有 `synapse-redis` 容器）：`login_fail:{ip}:{username}` → INCR + EXPIRE 900s
  3. 5 次失败后返回 429 + `M_LIMIT_EXCEEDED` + `retry_after_ms: 900000`（15 分钟）
  4. 成功登录时清除计数器
- **新增配置**：在 `docker/config/rate_limit.yaml` 或 security config 中添加：
  ```yaml
  login_lockout:
    max_attempts: 5
    lockout_duration_seconds: 900
  ```
- **验证**：5 次错误密码后第 6 次返回 429 + retry_after_ms

## 三、假设与决策

| # | 假设/决策 | 理由 |
|:---|:---|:---|
| 1 | 限流调高而非禁用 | 保留基本限流防护，避免测试期间服务过载 |
| 2 | login 端点限流不调高 | 避免测试期间暴力破解风险 |
| 3 | v3 download 改为 OptionalAuthenticatedUser 而非移除 auth 参数 | 保留可选认证能力（authenticated download 可记录访问者），符合 Matrix MSC3916 趋势 |
| 4 | R3 通过文档 + shared secret 端点解决而非让标准 register 支持 admin | 安全考虑：标准 register 支持 admin 会允许任意人自助提升权限 |
| 5 | login 锁定使用 Redis 而非内存计数 | 多实例部署一致性 + 已有 Redis 基础设施 |
| 6 | 测试脚本不修改 | 现有脚本的节流参数已足够，调高服务端限流即可 |
| 7 | 完整回归测试使用 `--all-features` | 确保所有 feature-gated 路由的测试都被执行 |

## 五、风险与回退

| 风险 | 缓解措施 |
|:---|:---|
| 限流调高期间服务过载 | 调高至 2000/s 而非无限，测试脚本仍有 166/s 节流 |
| v3 download 改 OptionalAuthenticatedUser 导致已认证下载失效 | OptionalAuthenticatedUser 允许有 token 时提取用户，不影响认证下载 |
| login 锁定误锁真实用户 | 锁定仅 15 分钟，且 key 包含 IP+username 不会误锁其他 IP |
| Redis 不可用导致锁定失效 | 失败时 fail-open（允许登录），记录 warn 日志 |
| 全量测试发现新问题超出修复范围 | 新问题记录到报告，标注为"后续迭代" |
